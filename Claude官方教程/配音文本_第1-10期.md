# 《Claude官方教程》系列① 十期配音文本

每期按成片里的顺序编号。正文是字幕写法（给人读的写法）；配音实际念的写法和它不一样的地方，列在每期后面“念法不同”里（英文名、命令、符号按读音拼出来，方便 TTS 念对）。声线：Fish Audio「温柔男生」，第三人称讲解。

## 第1期｜Claude Code 是什么、怎么工作

（14 句，381 字）

1. Claude Code 干活，就三步：找线索，动手，验结果。
2. 官方入门课第一课，五月发布，出镜的是 Lewis Menelaws。
3. 它和聊天窗口最大的差别，是能直接动你的文件和终端。
4. 聊天框给你一段代码，你得自己复制粘贴。它自己进去改。
5. 怎么改？先收集上下文，再动手改文件、跑命令，最后验证结果。
6. 没达标，就回到第一步重来，一直循环到能验证为止。
7. 比如让它修失败的测试：先跑，读报错，找文件，改，再跑一遍。
8. 整个过程里，你随时能插话、打断、纠偏。
9. 改错了？按两下 Esc，文件能回到改之前；远端的改动撤不回。
10. 撑起这个循环的有四样：循环本身、上下文窗口、工具、权限。
11. 窗口满了会自动压缩，什么时候调用工具由它判断，权限由你来定。
12. 终端、编辑器插件、桌面应用、网页版，都能用。
13. 官方课自己也提醒：它可能理解错、写出 bug、把事情做过头。
14. 聊天框交答案，代理交结果。结果对不对，还得你来验。

## 第2期｜装好 Claude Code，跑第一个提示

（15 句，456 字）

1. 装 Claude Code，三大系统都只要一条命令。
2. Mac 和 Linux 用 curl，Windows 用 PowerShell。
3. 提示符带 PS 的是 PowerShell，不带的是 CMD，别敲错。
4. Homebrew 和 winget 也能装，不过默认不会自动更新。
5. 装完开个新终端，运行 claude --version，能出版本号就成功。
6. 装完在项目目录里敲 claude，第一次运行要先登录。
7. 登录能用 Pro、Max、Team 或企业账号，也能用 API key。
8. 它能访问你启动的那个目录和所有子目录，目录之外的要经你许可。
9. 不想用终端也行：编辑器插件、桌面应用、网页版都能用。
10. 不过终端的功能最全，有些功能只有终端里才有。
11. 第一个提示别急着动手：按 Shift+Tab，轮换到计划模式。
12. 计划模式只研究、只提方案，不改你的源码，最后交一份计划。
13. 计划出来后，按 Ctrl+G 能先改，再批准。
14. 官方示例：整个应用要暗色模式，顶栏加个切换开关，再挑个对比度合适的颜色。
15. 装它一条命令，用好它，从 Shift+Tab 开始。

念法不同：
- 第 4 句：Homebrew 和 Windows 的包管理器也能装，不过默认不会自动更新。
- 第 5 句：装完开个新终端，运行 claude 杠杠 version，能出版本号就成功。
- 第 11 句：第一个提示别急着动手：按 Shift 加 Tab，轮换到计划模式。
- 第 13 句：计划出来后，按 Ctrl 加 G 能先改，再批准。
- 第 15 句：装它一条命令，用好它，从 Shift 加 Tab 开始。

## 第3期｜探索→计划→编码→提交，标准工作流

（14 句，376 字）

1. Claude 动手写代码之前，最该做的，是不让它动手。
2. 官方入门课教的标准工作流，就四步：探索、计划、编码、提交。
3. 前两步放在计划模式里：它先把相关文件读一遍，研究、出方案，但不改你的源码。
4. 计划出来先看一遍，不满意就告诉它具体改哪一块。
5. 这时候纠偏最划算，因为一行代码还没写。
6. 按 Ctrl+G，能直接在编辑器里改计划。
7. 编码阶段给它三样东西：成功标准、趁手的工具、能反复跑的测试。
8. 装上 Claude in Chrome，它能自己测界面，需直连官方账号。
9. 官方课还提醒：测试要靠得住，别让它削弱测试来蒙混过关。
10. 提交之前，先让子代理审一遍：它没参与写代码，眼光是新的。
11. 官方课还列了提交前看的三样：没要求的改动、变弱的测试、硬编码的值。
12. 提交信息想要固定格式？把约定写进 CLAUDE.md，它就照做。
13. 官方也说：一句话说得清的小改动，别计划，直接做。
14. 先看后改，先审后交。

念法不同：
- 第 6 句：按 Ctrl 加 G，能直接在编辑器里改计划。
- 第 12 句：提交信息想要固定格式？把约定写进 Claude 点 md，它就照做。

## 第4期｜上下文管理：/compact、/clear、/context

（14 句，379 字）

1. 目标明确的活，提示写得越含糊，Claude 越费上下文。
2. Anthropic 官方入门课专门有一课，讲怎么管这块“记忆”。
3. 上下文窗口，是 Claude 这次会话的工作记忆。
4. 你的提示、读过的文件、命令的输出，全都占位。
5. 装满了会自动压缩：先清掉旧的工具输出，不够再总结对话。
6. 代价是，早期的详细指令可能丢。
7. 三个命令：/compact 压成摘要，/clear 清空对话，/context 看占用。
8. 同一个功能做到快满，用 /compact。开新功能，用 /clear。
9. 同一个问题纠正两次还不对，就清空重来。
10. 小问题想问一句，用 /btw，答案不占上下文。
11. 要跨会话记住的事，写进 CLAUDE.md：压缩之后，它会从磁盘重新读一遍。
12. 还有个反直觉的：目标明确的活，提示写得越具体，越省上下文。
13. 含糊的提示看着短，它却得自己到处翻代码、自己推理，反而更费。
14. 上下文是预算，不是仓库。

念法不同：
- 第 7 句：三个命令管它：斜杠 compact 压成摘要，斜杠 clear 清空对话，斜杠 context 看占用。
- 第 8 句：同一个功能做到快满，用 compact。开新功能，用 clear。
- 第 10 句：小问题想问一句，用斜杠 B T W，答案不占上下文。
- 第 11 句：要跨会话记住的事，写进 Claude 点 md：压缩之后，它会从磁盘重新读一遍。

## 第5期｜CLAUDE.md：给 Claude 写一份入职手册

（12 句，378 字）

1. Claude Code 每开一个新会话，上下文都是全新的，像第一天上班。
2. 官方课说：没有 CLAUDE.md，结构、依赖、功能都得重新摸。
3. 解法是项目根目录的一个 Markdown 文件，每次开会话，它都会自动读。
4. 官方的比喻：给代码库写的入职手册。
5. 写什么？常用命令、代码风格，这些读代码也猜不到的规矩，每份别超过两百行。
6. 项目级的进版本库，全队共享；用户级的放你的配置文件夹，只给你自己。
7. 几份是叠加着一起读，不是谁覆盖谁。
8. 同一个错纠正第二遍，就写下来，比如“别用 API 路由”。
9. 想进文件，要明说“加到 CLAUDE.md”；只说“记住”，进的是自动记忆。
10. 项目文档用 @ 加路径引用，不过引用的内容照样一启动就全载入，不省上下文。
11. 官方课还建议：一开始先别写，看它总在哪被纠偏，再用 /init 生成。
12. 但它是上下文，不是强制配置。必须照做的硬规矩，交给 hook。

念法不同：
- 第 2 句：官方课说：没有 Claude 点 md，结构、依赖、功能都得重新摸。
- 第 9 句：想进文件，要明说“加到 Claude 点 md”；只说“记住”，进的是自动记忆。
- 第 10 句：项目文档用艾特加路径引用，不过引用的内容照样一启动就全载入，不省上下文。
- 第 11 句：官方课还建议：一开始先别写，看它总在哪被纠偏，再用斜杠 init 生成。

## 第6期｜Hooks：把“通常照做”变成“绝对照做”

（13 句，394 字）

1. 提示里写“改完代码要格式化”，Claude 通常会照做。
2. 通常，不等于每次。Hooks 的卖点就一句：它想跳也跳不过去。
3. 官方列了三十多个钩子事件，常用的就几个。
4. PreToolUse，在工具调用之前触发，能在事情发生前把它拦下来。
5. PostToolUse，在调用成功之后触发，自动格式化、自动检查放这里。
6. Stop，在它想收工时触发。一句“你还没做完”，就能让它接着干。
7. PreToolUse 能返回三种决定：放行、拒绝、交给你来定。
8. 不返回 JSON 的钩子看退出码：2 是拦截，0 是没意见，别的都不拦。
9. 最容易踩的坑：退出码 1 看着像报错，其实不拦，命令照样跑。
10. 就算跳过权限，钩子的拒绝照样拦得住。
11. 还有一招：不拦，改写。把命令里的密钥换成占位符，再放行。
12. 压缩后补上下文，别用 PostCompact，用 SessionStart。
13. 提示词是请求，Hooks 才是规矩。不过路径写错，它会悄悄失效。

## 第7期｜子代理：脏活交出去，主对话只收答案

（13 句，415 字）

1. 查一个问题，Claude 翻了一大堆文件，主对话的上下文就这么被占满了。
2. 子代理就是解法：它在自己的上下文窗口里干活，只把摘要交回来。
3. 比如问一句：这个应用在哪处理退款？Claude 会派探索型子代理去翻代码。
4. 翻的过程留在子代理那边，主对话里只剩结论。
5. 官方示意里，子代理读了六千多 token，只回你四百多。
6. 自带几个子代理：Explore 只读搜代码，Plan 做计划调研。
7. 想自己做一个？最省事的办法，是直接让 Claude 来建。
8. 官方课演示的 /agents 创建向导，新版本已经删了，别照着找。
9. 描述写得好，Claude 才知道什么时候该叫它；用 @ 点名，则一定会派它。
10. 子代理就是带 YAML 头的 Markdown 文件，必填只有两个：名字和描述。
11. 加一行 memory，它就能跨对话记住东西，越用越熟。
12. 还能预载技能：写进 skills 字段，整份技能都会塞进它的上下文。
13. 不过子代理自己也花用量，别当成免费的。脏活外包，只收结论。

念法不同：
- 第 8 句：官方课演示的斜杠 agents 创建向导，新版本已经删了，别照着找。
- 第 9 句：描述写得好，Claude 才知道什么时候该叫它；用艾特点名，则一定会派它。
- 第 10 句：子代理就是带亚马尔头的 Markdown 文件，必填只有两个：名字和描述。

## 第8期｜Skills：把重复的流程做成按需取用的手册

（13 句，380 字）

1. 每次让 Claude 审 PR，都得把同一大段审查标准重新粘贴？
2. Skills 治这个：把流程写成文件，Claude 需要时自己取用。
3. 技能是个文件夹，里面放 SKILL.md：名称、描述，加上步骤。
4. 放在个人目录，所有项目都能用；放在项目里，整个团队共享。
5. 关键区别：它不会一开始就全塞进上下文。
6. Claude 先只读每个技能的名称和描述，对上号了，才把全文读进来。
7. CLAUDE.md 是每次会话都载入的规矩，技能是需要时才翻开的手册。
8. 输入 / 加技能名能直接调用，也能让它自己判断；改完不用重启。
9. 官方课的经验法则：同一套多步指令打了两遍，就该做成技能。
10. 比如视频里演示的：提交信息、PR 描述、调试、写文档。
11. 有副作用的流程，比如部署，设成只能手动叫它。
12. 别高兴太早：技能装多了，描述每一轮都占上下文，用不到的别装。
13. 常驻的规矩进 CLAUDE.md，偶尔用的手册做成技能。

念法不同：
- 第 3 句：技能是个文件夹，里面放 skill 点 md：名称、描述，加上步骤。
- 第 7 句：Claude 点 md 是每次会话都载入的规矩，技能是需要时才翻开的手册。
- 第 8 句：输入斜杠加技能名能直接调用，也能让它自己判断；改完不用重启，当场生效。
- 第 13 句：常驻的规矩进 Claude 点 md，偶尔用的手册做成技能。

## 第9期｜MCP：把代码库之外的工具接进 Claude Code

（12 句，395 字）

1. 很多上下文，其实不在代码库里：在数据库、协作软件、公开仓库里。
2. MCP，模型上下文协议，就是把外部工具接进 Claude Code 的桥。
3. 团队用 Linear 管项目？加个 MCP 服务器，就能直接读工单。
4. 要查依赖的最新文档，有 Context7 这类文档服务器。
5. 用 claude mcp add 添加，常用 HTTP 和 stdio 两种。
6. 会话里敲 /mcp，能看连接状态，不用的直接关掉，配置不会丢。
7. 范围有三档：本地，只有你、只在这个项目；用户，你的所有项目。
8. 第三档是项目：写进 .mcp.json 提交进版本库，全队拿到同一套服务器。
9. 要记住代价：每个服务器的工具名和说明，每个会话都要载入，会占一点上下文。
10. 有现成命令行的，比如 gh、aws，更省；技能管怎么用，和 MCP 互补。
11. 默认只先放工具名，用到才加载。用第三方中转的，默认可能是关着的。
12. 多接一个，就多占一点上下文，不用的，关掉。

念法不同：
- 第 6 句：会话里敲斜杠 mcp，能看连接状态，不用的直接关掉，配置不会丢。
- 第 8 句：第三档是项目：写进 mcp 点 json 提交进版本库，全队拿到同一套服务器。

## 第10期｜权限模式：什么时候可以放手，交给自动模式

（14 句，401 字）

1. Claude Code 有六种权限模式，从事事问你，到完全放手。
2. 手动：只读不用问，其余先问你。接受编辑：改文件和常见文件命令，也不问。
3. 计划：只研究、只提方案，不改你的源码。
4. 自动：多数直接放行，命令、联网这类，交给另一个分类器模型先审。
5. 不再询问：只放行预先批准的，其余直接拒绝，适合 CI 无人值守。
6. 绕过权限：跳过所有检查，只能放在隔离的容器或虚拟机里。
7. 日常按 Shift+Tab，在前四种间轮着切，状态栏随时显示当前模式。
8. 自动模式拦强制推送、生产部署、把下载的代码直接丢进 shell。
9. 想看最新的拦截名单，命令行跑 claude auto-mode defaults。
10. 连续被拦三次，自动模式就会暂停，回到弹窗询问。
11. 新版本里，终端新会话默认就是自动模式，先看状态栏。
12. 分类器管意图，不管对错：认证写坏了，它照样放行。
13. 所以要搭一个跑测试的 Stop 钩子：一个管动手前，一个管收工后。
14. 放手可以，但要有人验收。

念法不同：
- 第 7 句：日常按 Shift 加 Tab，在前四种间轮着切，状态栏随时显示当前模式。
