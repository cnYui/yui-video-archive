## 逐条核对

### 1. 没有 CLAUDE.md，Claude Code 每次都从零开始：重新探索代码库、搞清依赖、有哪些功能

**结论：△**

官方原话
- "Each Claude Code session begins with a fresh context window." — [memory](https://code.claude.com/docs/en/memory)
- "Auto memory is on by default in local sessions." — [memory](https://code.claude.com/docs/en/memory)
- "persistent context it can't infer from code alone" — [best-practices](https://code.claude.com/docs/en/best-practices)（讲 CLAUDE.md 的作用）
- "Anything Claude can figure out by reading code" — [best-practices](https://code.claude.com/docs/en/best-practices)（在“不该写进 CLAUDE.md”一栏）
- 课程原文（`claude-code-101__08`）："it starts fresh every time. It has to re-explore your codebase"

出入与准确写法
- 文档只讲到：每个会话从全新的上下文窗口开始，靠两样东西带过会话——你写的 CLAUDE.md、Claude 自己记的 auto memory。“重新探索代码库、搞清依赖、有哪些功能”这三件事是课程的描述，文档没有逐条列。
- auto memory 在本地会话默认开，每个会话会载入 MEMORY.md 的前 200 行或 25KB。所以“没有 CLAUDE.md 就完全从零”说过头了，说“新会话上下文是全新的”才准。
- 文档反过来提醒：CLAUDE.md 要写 Claude 读代码也猜不到的东西（构建命令、非默认的风格规则），别写目录结构、依赖清单这类能推出来的。

建议中文念法
- 每个新会话，都从一个全新的上下文开始。
- CLAUDE.md 把项目规矩带进每个会话。

### 2. CLAUDE.md 是放在项目根目录的 Markdown 文件，每次开始会话时自动读取，内容附加到提示里（入职手册比喻）

**结论：✓**

官方原话
- "Claude reads them at the start of every session." — [memory](https://code.claude.com/docs/en/memory)
- "./CLAUDE.md or ./.claude/CLAUDE.md" — [memory](https://code.claude.com/docs/en/memory)（项目级的两个合法位置）
- "delivered as a user message after the system prompt" — [memory](https://code.claude.com/docs/en/memory)（Troubleshoot 一节）
- "Think of it as an onboarding script for your codebase." — `claude-code-101__08`
- "The contents of the CLAUDE.md file are appended to your prompt." — `claude-code-101__08`

小出入（不影响整体 ✓）
- 课程说“附加到你的提示里”；文档的精确说法是“以用户消息的形式放在系统提示后面，不是系统提示的一部分”。台本别写成“写进系统提示”。
- 比喻原文是 onboarding script，译成“入职手册 / 入职说明”都行。
- 根目录之外，`.claude/CLAUDE.md` 也算项目级。
- 补充：根目录的 CLAUDE.md 在 /compact 之后会从磁盘重新注入——“Re-injected from disk”（[context-window](https://code.claude.com/docs/en/context-window)“What survives compaction”表）。

建议中文念法
- CLAUDE.md 放项目根目录，每次开会话自动读。

### 3. 层级：项目级 + 用户级；实战课说四个位置（托管 / 用户 / 项目 / 本地），启动时全部叠加

**结论：△**（四个范围对；“优先级”“gitignored”“启动时全部载入”三处要小心措辞）

官方原话
- "lists them in load order, from broadest scope to most specific" — [memory](https://code.claude.com/docs/en/memory)
- "All discovered files are concatenated into context rather than overriding each other." — [memory](https://code.claude.com/docs/en/memory)
- "Claude may pick one arbitrarily" — [memory](https://code.claude.com/docs/en/memory)（两条指令互相矛盾时）
- "Managed policy CLAUDE.md files cannot be excluded." — [memory](https://code.claude.com/docs/en/memory)
- "Files in subdirectories load on demand when Claude reads files in those directories." — [memory](https://code.claude.com/docs/en/memory)
- "Personal project-specific preferences; add to .gitignore" — [memory](https://code.claude.com/docs/en/memory)（本地文件那一行）
- 课程原文（`claude-code-in-action__02`）："Claude loads all of them together at launch."

memory 页当前的完整层级（按载入顺序，从最宽到最具体）

| 范围 | 文件路径 | 谁能看到 | 进版本库吗 |
| :- | :- | :- | :- |
| 托管策略（Managed policy） | macOS：`/Library/Application Support/ClaudeCode/CLAUDE.md`；Linux 和 WSL：`/etc/claude-code/CLAUDE.md`；Windows：`C:\Program Files\ClaudeCode\CLAUDE.md` | 组织里所有用户 | 不在项目里，由 IT 下发；个人设置排除不掉 |
| 用户 | `~/.claude/CLAUDE.md`（Windows 是 `%USERPROFILE%\.claude\CLAUDE.md`；设了 `CLAUDE_CONFIG_DIR` 就在那个目录下，见 [claude-directory](https://code.claude.com/docs/en/claude-directory)） | 只有你，所有项目通用 | 否 |
| 项目 | `./CLAUDE.md` 或 `./.claude/CLAUDE.md` | 团队 | 是（“Team members via source control”） |
| 本地 | `./CLAUDE.local.md` | 只有你，只对当前项目 | 文档要求你自己把它加进 `.gitignore` |

另外两条加载规则
- 工作目录和它所有上级目录里的 `CLAUDE.md`、`CLAUDE.local.md`：启动时载入；越靠近工作目录的越晚读。每个目录里，`CLAUDE.local.md` 追加在 `CLAUDE.md` 后面。
- 子目录里的 `CLAUDE.md`：不在启动时载入，Claude 读到那个子目录里的文件时才载入。
- 此外还有 `.claude/rules/*.md`（带 `paths:` 的按匹配文件载入）、`~/.claude/rules/`，以及没有 CLAUDE.md 时会被读的 `AGENTS.md`——视频不用展开。

和说法对照
- “四个位置”：对应文档表格里的四个范围，对得上。但文档同时还有上级目录、子目录、rules、AGENTS.md，别说“只有四个位置”。
- “优先级”：文档没有“覆盖”这回事——是叠加。顺序只决定谁排在后面（后读的是离你更近的）；冲突时 Claude 可能随便挑一条。唯一特殊的是托管那份“排除不掉”。
- “gitignored”：不是自动的。文档要求你手动加进 `.gitignore`（用 `CLAUDE_CODE_NEW_INIT=1` 跑 /init 并选个人选项，才会替你加）。
- “启动时全部叠加载入”：对四个范围加上级目录成立；子目录的不是。

建议中文念法
- 托管、用户、项目、本地，四份叠加一起读。
- 项目那份进版本库全队共用，用户那份只给你。
- 几份是叠加，不是谁覆盖谁。
- 本地那份得自己加进 .gitignore。

### 4a. 反复被纠正的事，让 Claude 把规则存进记忆

**结论：△**

官方原话
- "Claude saves it to auto memory" — [memory](https://code.claude.com/docs/en/memory)（你说“记住 X”之后）
- "add this to CLAUDE.md" — [memory](https://code.claude.com/docs/en/memory)（要进 CLAUDE.md 得这样说）
- "Claude makes the same mistake a second time" — [memory](https://code.claude.com/docs/en/memory)（“When to add to CLAUDE.md”的第一条触发条件）
- 课程原文（`claude-code-101__08`）："explicitly ask Claude to save that rule to memory"

出入与准确写法
- 课程把“存进记忆”和“存进 CLAUDE.md”混着说（配图说明写的是 save a rule to the CLAUDE.md file）。文档分得很清楚：你说“记住 X”，Claude 存进 auto memory——Claude 自己的笔记，位置 `~/.claude/projects/<项目>/memory/`，只在你这台机器上，队友看不到。想进 CLAUDE.md（可进版本库、可共享），要明说“加到 CLAUDE.md”，或者用 /memory 自己改文件。
- 两种每个会话都会载入：CLAUDE.md 载入全文；auto memory 载入 MEMORY.md 的前 200 行或 25KB。
- 文档给的触发时机很具体：同一个错 Claude 犯第二次，就该写下来（[features-overview](https://code.claude.com/docs/en/features-overview) 也是同样的说法：“Claude gets a convention or command wrong twice”→ 加进 CLAUDE.md）。

建议中文念法
- 同一个错纠正第二次，就让 Claude 记下来。
- 想写进文件，就说“加到 CLAUDE.md”。
- 记住进的是记忆，不是 CLAUDE.md。

### 4b. 用 @ 加文件路径引用项目文档（import 语法；展开后仍全部在启动时载入，不省上下文）

**结论：✓**

官方原话
- "Imported files are expanded and loaded into context at launch" — [memory](https://code.claude.com/docs/en/memory)
- "maximum depth of four hops" — [memory](https://code.claude.com/docs/en/memory)
- "don't reduce its context cost" — [memory](https://code.claude.com/docs/en/memory)（原句：imports 帮你整理长文件，但不降低它的上下文成本）
- 课程原文（`claude-code-in-action__02`）："They do not reduce the amount of context Claude has to read."

准确写法
- 语法：`@路径`，写在 CLAUDE.md 任意位置，例如 `See @README for project overview`（文档示例）。
- 现行文档写的是最多四层嵌套；要报数字就报“四层”，别照搬别处的旧数字。
- 相对路径按“含 import 的那个文件”算，不是按工作目录。
- 想真正省上下文，用 `.claude/rules/` 里带 `paths:` 的规则，或 skill——它们按需载入。

建议中文念法
- 用 @ 加路径引用文档，但照样启动就全载入。

### 5. 官方建议：新项目先不写 CLAUDE.md，观察总在哪纠偏，再 /init 生成，保持精简

**结论：△**（课程原话；文档的说法不同）

官方原话
- 课程原文（`claude-code-101__08`）："We recommend starting a project without a CLAUDE.md file" ——后面接着说：这样能看出你总在哪里要纠正模型，CLAUDE.md 才会精简
- "generate a starter CLAUDE.md file" … "then refine over time" — [best-practices](https://code.claude.com/docs/en/best-practices)
- "Claude makes the same mistake a second time" — [memory](https://code.claude.com/docs/en/memory)
- "Would removing this cause Claude to make mistakes?" — [best-practices](https://code.claude.com/docs/en/best-practices)
- "Bloated CLAUDE.md files cause Claude to ignore your actual instructions!" — [best-practices](https://code.claude.com/docs/en/best-practices)

出入与准确写法
- “先不写，观察纠偏，再 /init”只在课程里（课时文字里命令被吃掉了，但上下文就是 /init）。文档没有“先别写”这句，文档的推荐是：跑 /init 生成起步版，再慢慢改；并且“同一个错犯第二次就写进去”。两者精神一致（从真实的纠偏出发），但别说成“官方文档建议先不写”。
- “保持精简”：有据，文档给的做法是对每一行问“删掉它 Claude 会出错吗？”。
- 台本里这句要标成“官方课程建议”。

建议中文念法
- 官方课建议：先别写，看你总在哪纠偏。
- 官方文档的说法：/init 起个头，再慢慢改。

### 6. 软约定放 CLAUDE.md，硬规则放 hook：CLAUDE.md 是“请求”，hook 才是强制（核对 CLAUDE.md 的约束力）

**结论：✓**

官方原话
- "Claude treats them as context, not enforced configuration." — [memory](https://code.claude.com/docs/en/memory)
- "To block an action regardless of what Claude decides, use a PreToolUse hook instead." — [memory](https://code.claude.com/docs/en/memory)
- "there's no guarantee of strict compliance" — [memory](https://code.claude.com/docs/en/memory)（Troubleshoot：Claude 会尝试照做，但不保证严格遵守，指令含糊或冲突时更明显）
- "CLAUDE.md instructions shape Claude's behavior but are not a hard enforcement layer." — [memory](https://code.claude.com/docs/en/memory)
- "hooks are deterministic and guarantee the action happens" — [best-practices](https://code.claude.com/docs/en/best-practices)
- 课程原文（`claude-code-in-action__02`）："That's real enforcement, not a polite request."

补充与小出入
- 官方说的“强制”不止 hook 一条路：settings 里的 `permissions.deny` 也是客户端强制（memory 页表格：Block specific tools, commands, or file paths → `permissions.deny`）。说“硬规则交给 hook”没错，只是别说成唯一办法。
- “Claude 多数时候会照做”是课程的说法；文档的措辞是“尝试照做，不保证严格遵守”。台本用文档那句更稳。
- 有意思的一点：文档自己给托管 CLAUDE.md 举的例子里就有 "Never push directly to main."——写在 CLAUDE.md 是行为指导；要真正拦住，用 deny 规则或 PreToolUse hook。和视频的例子“永远不要推到 main”正好对上。
- 文档还说：越具体、越简洁，Claude 越稳定地遵守（同一页开头）。

建议中文念法
- CLAUDE.md 是请求，不是强制。
- 官方原话：是上下文，不是强制配置。
- 必须执行的硬规则，交给 hook。
- 想真拦住，用 hook 或 deny 规则。

## 附加核对

### A. /init 命令当前的行为

**结论：✓**

官方原话
- "If a CLAUDE.md already exists, /init suggests improvements rather than overwriting it." — [memory](https://code.claude.com/docs/en/memory)
- "build commands, test instructions, and project conventions" — [memory](https://code.claude.com/docs/en/memory)（Claude 分析代码库后写进去的东西）
- "Initialize project with a CLAUDE.md guide." — [commands](https://code.claude.com/docs/en/commands)
- "asks which artifacts to set up: CLAUDE.md files, skills, and hooks" — [memory](https://code.claude.com/docs/en/memory)（设了 `CLAUDE_CODE_NEW_INIT=1` 之后）

准确写法
- 默认：分析代码库，生成起步版 CLAUDE.md（构建命令、测试方法、它发现的项目约定）；已有 CLAUDE.md 就提改进建议，不覆盖。
- 默认还会读别家工具的指令文件并吸收有用部分（`.cursor/rules/`、`.cursorrules`、`.github/copilot-instructions.md`）。
- 环境变量 `CLAUDE_CODE_NEW_INIT=1`：变成多阶段交互流程——先问要建哪些东西（CLAUDE.md、skills、hooks），用子代理探索代码库，追问补缺，给出可审阅的方案后才写文件；这个变量只改 /init 的跑法，可以一直开着。
- 推荐流程（命令页）：新仓库先 /init，再用 /memory 打磨。

建议中文念法
- 已有 CLAUDE.md 时，/init 只提改进建议。

### B. 官方文档对 CLAUDE.md 篇幅 / 长度的建议

**结论：✓**

官方原话
- "target under 200 lines per CLAUDE.md file" — [memory](https://code.claude.com/docs/en/memory)（“Write effective instructions”→ Size）
- "Longer files consume more context and reduce adherence." — [memory](https://code.claude.com/docs/en/memory)
- "Keep CLAUDE.md under 200 lines." — [features-overview](https://code.claude.com/docs/en/features-overview)
- "Would removing this cause Claude to make mistakes?" — [best-practices](https://code.claude.com/docs/en/best-practices)
- 官方博客（[steering-claude-code…](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)，2026-06-18，经抓取摘录，引用前请回原页看一眼）："Keep CLAUDE.md under 200 lines"，后面还有“给它一个负责人、改动像代码一样评审”

准确写法
- 200 行是“建议”，不是截断线：文档说 CLAUDE.md 最多 4 MiB 都会全文载入，超过 4 MiB 才跳过；超过推荐长度会在启动时和 /status 里给警告，并且遵守率下降。
- 容易混的一条：“前 200 行或 25KB”的截断规则是 auto memory 的 MEMORY.md 的，不是 CLAUDE.md 的。
- 太长怎么办：拆到 `.claude/rules/`（带 `paths:` 的按需载入）或 skill；@import 只是整理，不省上下文。
- `/doctor` 能给已进库的 CLAUDE.md 提删减建议（砍掉目录结构、依赖清单、架构概述这类 Claude 能自己推出来的内容）。

建议中文念法
- 官方建议每份 CLAUDE.md 控制在 200 行内。
- 每一行都问：删掉它，Claude 会出错吗？

- “项目级优先 / 覆盖用户级”“有优先级”——✗。文档：全部叠加，冲突时 Claude 可能随便挑一条。
- “只有四个位置”——还有上级目录、子目录（按需）、`.claude/rules/`、`AGENTS.md`。
- “本地文件自动不进 git”——✗。CLAUDE.local.md 要自己加进 `.gitignore`（settings.local.json 才是 Claude Code 保存时自动排除的，别混）。
- “@ 引用能省上下文”——✗。展开后仍在启动时全部载入。
- “官方文档建议先别写 CLAUDE.md”——只有课程这么说；文档是 /init 起步再改。
- “超过 200 行会被截断”——✗。200 行是建议长度；“200 行或 25KB”截断的是 auto memory 的 MEMORY.md。
- “说‘记住’就是写进 CLAUDE.md”——✗。“记住”进 auto memory；写进 CLAUDE.md 要明说，或用 /memory 改。
- “# 开头快速写入记忆”这类老教程写法——？现行文档（memory 页、interactive-mode 页）都没有这个功能，别讲。（更新日志里应该有移除它的记录，这次没在日志页读到原句，未核实。）import 层数以现行文档的“四层”为准。
- “把依赖清单、目录结构、完整架构都写进 CLAUDE.md”——文档反着建议：这些 Claude 能自己推出来的内容应该删（/doctor 就是这么提删减建议的）。
