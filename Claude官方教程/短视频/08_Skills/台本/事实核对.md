## 说法 1：技能 = 文件夹 + SKILL.md；frontmatter；description

> 待核对：技能 = 一个文件夹，里面有 SKILL.md；frontmatter 写 name 和 description；description 决定 Claude 是否使用它。

**1a　✓ 技能是带 SKILL.md 的文件夹；description 决定 Claude 用不用**
- 官方原话：
  - "Create a SKILL.md file with instructions, and Claude adds it to its toolkit" — https://code.claude.com/docs/en/skills（开头）
  - "A skill is a directory containing, at minimum, a SKILL.md file" — https://agentskills.io/specification
  - `description`："Claude uses this to decide when to apply the skill" — https://code.claude.com/docs/en/skills#frontmatter-reference
- 官方排查没触发时的第一条也是这个："Check the description includes keywords users would naturally say" — 同页 Skill not triggering。
- 建议念法：「技能就是一个文件夹，里面放个 SKILL.md」；「描述写得好不好，决定 Claude 会不会想起它」

**1b　△ “frontmatter 写 name 和 description”——别说成必填**
- Claude Code 文档："All fields are optional. Only `description` is recommended" — https://code.claude.com/docs/en/skills#frontmatter-reference ；`name` 缺省 "Defaults to the directory name"。
- 开放标准里两个都必填（表里 Required: Yes）：name 最长 64 字符、只能小写字母 / 数字 / 连字符；description 最长 1024 字符 — https://agentskills.io/specification 。课时文字 03 把这些当通用规则讲（key takeaways 写 name 和 description 都是 required）。
- Claude Code 里实际的长度规则不同：技能清单里 description + when_to_use 合计超过上限会被截断，"truncated at 1,536 characters"（skills 页 frontmatter 表）。
- 准确写法：一般会写 name 和 description；在 Claude Code 里真正“推荐”的只有 description。
- 建议念法：「一般写两样：名字和描述，描述最要紧」

## 说法 2：启动只载入名称和描述；匹配后读全文；“确认”

> 待核对：Claude 启动时只加载每个技能的名称和描述；你的请求和描述匹配时，才把全文读入上下文（课时文字说匹配后会先请你确认）。请核对当前是否还有“确认”这一步。

**2a　✓ 启动只载入名称和描述，对上号才载全文**
- 官方原话：
  - "Claude Code loads a listing of skill names and descriptions into context" — https://code.claude.com/docs/en/skills#skill-descriptions-are-cut-short
  - "full skill content only loads when invoked" — https://code.claude.com/docs/en/skills（Control who invokes a skill 后的 Note）
  - "until a Skill is triggered, only its name and description occupy context" — https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview
- 补充（可做细节）：描述不是无限的——技能清单的预算是上下文窗口的 1%（"The budget scales at 1% of the model's context window"），单条 description + when_to_use 上限 1,536 字符，超预算先丢最少用的技能的描述；设了 `disable-model-invocation: true` 的技能连描述都不进上下文。
- 建议念法：「一开始只读名字和描述，对上号了才把全文读进来」

**2b　△ “匹配后会先请你确认”——对普通技能已过时，别讲**
- 课时文字 introduction-to-agent-skills__02-creating-your-first-skill.txt："Claude asks you to confirm loading the skill"
- 更新日志 v2.1.19（2026-01-23）："Changed skills without additional permissions or hooks to be allowed without requiring approval" — https://code.claude.com/docs/en/changelog
- skills 页没有任何“匹配后先确认”的描述；只有两处相关：`allowed-tools` 让这一轮里列出的工具不用逐个批准；claude.ai 同步下来的技能要靠 `Skill(anthropic-skills:名字)` 规则才不弹窗（"To approve a synced skill without a prompt, name it inside its reserved namespace"）。
- 工具总表（https://code.claude.com/docs/en/tools-reference ）的 "Permission required" 一栏，Skill 行写的是 "Yes"（手动模式）——所以带额外权限 / 钩子的技能、或你自己配了权限规则的，仍可能弹授权；文档没逐项写，别展开。
- 准确写法：普通技能直接加载，没有固定的“确认”步骤。
- 建议念法：不要讲。

## 说法 3：位置与优先级

> 待核对：位置：个人技能 ~/.claude/skills/；项目技能 .claude/skills/（谁克隆仓库谁就有）；还有插件、企业托管。名称冲突的优先级（企业 → 个人 → 项目 → 插件）。请核对 skills 文档的当前位置与优先级。

**3a　✓ 位置**
- 官方原话：表格（https://code.claude.com/docs/en/skills#where-skills-live ）里，个人技能 `~/.claude/skills/<名字>/SKILL.md` — "All your projects on this machine"；项目技能 `.claude/skills/<名字>/SKILL.md` — "Commit it so your team gets it too"；企业 — "in the managed settings directory"；插件 — 以 `/plugin-name:skill-name` 的形式出现。
- 课时文字没提、文档有的位置：子目录里的 `.claude/skills/`（用到那里的文件时才加载）、`--add-dir` 目录、claude.ai 账号同步的技能（v2.1.273+，下载到 `~/.claude/skills/synced/`）。个人技能在 Cowork / 云会话里不加载。所以课时文字的“启动时扫描四个位置”只是简化，文档现列七种来源。
- 建议念法：「个人技能跟着你走，项目技能跟着仓库走」

**3b　△ 优先级：企业 > 个人 > 项目 是对的；“→ 插件”最后一档要改**
- 官方原话："Enterprise over personal, and personal over project" — https://code.claude.com/docs/en/skills#resolve-skills-that-share-a-name
- 插件："Both load, because plugin skills are namespaced as `/plugin-name:skill-name`" — 同一张表。features-overview 也写 "Plugin skills are namespaced to avoid conflicts"（https://code.claude.com/docs/en/features-overview）。
- 课时文字 02 把 Plugins 列成优先级最低的一档；现行说法是插件技能带前缀、不抢名，不进这条链。
- 还有两条冲突规则可知道：同名技能会替换内置命令（别名除外）；同名的 `.claude/commands/` 文件和技能撞了，技能赢。
- 准确写法：同名冲突看 企业 > 个人 > 项目；插件技能另有前缀。
- 建议念法：「同名冲突，企业压个人，个人压项目」；「插件技能带前缀，不会撞名」

## 说法 8：技能 vs MCP 的上下文成本

> 待核对：技能和 MCP 的上下文成本对比：技能只在需要时才加载全文。

**8a　✓ 技能只在需要时才加载全文**
- 官方原话：features-overview 的 “Context cost by feature” 表，Skills 一行："Descriptions at start, full content when used"，成本 "Low (descriptions every request)" — https://code.claude.com/docs/en/features-overview#context-cost-by-feature
- 建议念法：「技能平时只占名字和描述，用到才展开全文」

**8b　△ “和 MCP 对比”——课时文字的 MCP 说法已过时，别讲谁省谁费**
- 课时文字 claude-code-101__11-mcp.txt（Context Costs 一节）："tool definitions to your context window — even when you're not actively using them"，并说工具超过上下文 10% 才自动切到 tool search。
- 现行文档：默认就开 tool search，"Tool search is enabled by default: MCP tools are deferred and discovered on demand" — https://code.claude.com/docs/en/mcp#configure-tool-search ；另一节写 "Only tool names and server instructions load at session start"（#scale-with-mcp-tool-search）。10% 阈值现在只是 `ENABLE_TOOL_SEARCH=auto` 这个可选模式。
- 例外：`ANTHROPIC_BASE_URL` 指向非官方地址（比如某些中转站）时默认不开 tool search，MCP 工具会预先全部加载（同页 Configure tool search）。
- 官方的定位不是二选一："MCP connects Claude to external services. Skills extend what Claude knows" — https://code.claude.com/docs/en/features-overview（MCP vs Skill 页签），两者 "work well together"。
- 准确写法：技能和 MCP 现在都是“用到才展开”；区别在作用——技能教做法，MCP 连外部服务。
- 建议念法：「教做法用技能，连外部服务才用 MCP」

## 可以多讲一句的具体细节（≤ 3）

1. **有副作用的流程设成只能手动叫**：部署、提交这类，在 frontmatter 加 `disable-model-invocation: true`；这样连描述都不占上下文。出处：https://code.claude.com/docs/en/skills#control-who-invokes-a-skill （"workflows with side effects or that you want to control timing"；表格里该行写 "Description not in context"）。念法：「有副作用的流程，设成只能手动叫它」
2. **技能和子代理能互相嵌套（正好接上一期）**：技能里写 `context: fork`，就在独立的子代理里跑；子代理用 `skills` 字段预载技能。出处：https://code.claude.com/docs/en/skills#run-skills-in-a-subagent （"Add `context: fork` to your frontmatter when you want a skill to run in isolation"）。念法：「技能能在子代理里跑，子代理也能预载技能」
3. **冷水：技能装得多也不是白装**——每个技能的描述每一轮都占上下文，`/skill-doctor` 能看每个技能花多少、用没用过。出处：https://code.claude.com/docs/en/skills#find-unused-skills （"adds to your context on every turn, whether or not Claude ever uses it"；需要 v2.1.252 以上）。念法：「技能装得多，描述每轮都占上下文」
