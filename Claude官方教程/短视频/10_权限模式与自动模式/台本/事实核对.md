## 1. 六种权限模式：名称与含义

- 结论：△（名称和含义基本对；Auto 一句要改措辞）
- 课时文字：04 L11-22；101-02 L31-40；101-04 L15-20
- 官方依据（转述）：
  - Config values are `default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`. The mode that reviews every action is labelled Manual in the CLI, VS Code, JetBrains and the desktop app; `default` is its config value and `manual` is accepted as an alias. https://code.claude.com/docs/en/permission-modes#available-modes ，https://code.claude.com/docs/en/permissions#permission-modes
  - `acceptEdits` also auto-approves `mkdir`, `touch`, `rm`, `rmdir`, `mv`, `cp`, `sed`, but only for paths inside the working directory; writes to protected paths such as `.git` and `.claude` still prompt. https://code.claude.com/docs/en/permission-modes#auto-approve-file-edits-with-acceptedits-mode
  - Plan researches and proposes without editing your source; edits stay blocked until you approve the plan. https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode
  - Auto: your allow/ask/deny rules resolve first; then read-only actions and file edits in the working directory pass without the classifier; everything else (shell commands, network and so on) goes to the classifier. https://code.claude.com/docs/en/permission-modes#how-the-classifier-evaluates-actions
  - Don't ask: anything that would prompt is auto-denied; reads in the working directories, read-only commands, `permissions.allow` rules and PreToolUse-hook approvals still run. https://code.claude.com/docs/en/permission-modes#allow-only-pre-approved-tools-with-dontask-mode
  - Bypass: removes prompts and safety checks, protected paths included; `--dangerously-skip-permissions` is equivalent; the docs say to use it only in isolated environments such as containers or VMs, and add that it gives no protection against prompt injection. https://code.claude.com/docs/en/permission-modes#skip-all-checks-with-bypasspermissions-mode
- 准确写法 / 有出入的地方：

  | 配置值 | 界面名 | 状态栏 |
  | - | - | - |
  | `default` | Manual | `⏸ manual mode on` |
  | `acceptEdits` | Accept edits（VS Code 里叫 Edit automatically） | `⏵⏵ accept edits on` |
  | `plan` | Plan | `⏸ plan mode on` |
  | `auto` | Auto | `⏵⏵ auto mode on` |
  | `dontAsk` | Don't ask | `⏵⏵ don't ask on` |
  | `bypassPermissions` | Bypass permissions | `⏵⏵ bypass permissions on` |

  - Auto：课程说“全部放行，分类器逐个动作审查”。文档的模式表格确实把 Auto 概括成“什么都能不问就做，带后台安全检查”，但细则是：读取和工作目录内的改文件直接放行，shell 命令、联网这类才交给分类器；显式的 ask 规则照样弹窗。台本别说“每一步都审”。
  - Don't ask：课程说“只允许预批准的工具”。文档里，只读操作（读工作目录内的文件、只读命令）也照常跑，所以是“预批准的 + 只读的”。
  - Bypass：别说成“什么都不拦”。deny 规则在任何模式（包括 Bypass）都有效；少数动作（显式 ask 规则、`rm -rf ~` 这类关键路径删除）仍会问；而且必须启动时就开启，会话中途切不进去；Linux / macOS 以 root 或 sudo 启动会被拒绝。
  - Plan：官方还写了一个例外——终端里开了 bypass 可用时，Plan 的拦截不强制执行。别说“Plan 绝对不会改文件”。
  - 命名：课程 101 的 02、04 课时把 Accept edits 叫 Auto-accept，并说“命令仍要批准”；in-action 的 04 课时和现行文档叫 Accept edits，且常见文件系统命令也免问。台本统一用 Accept edits。
- 念法：六档权限：从处处问你，到完全不问
- 分档念法（每条 ≤ 28 字）：
  - Manual：只读不问，其余先问你
  - Accept edits：改文件和常见文件命令免问
  - Plan：只研究出方案，不动源文件
  - Auto：多数放行，危险的交给分类器拦
  - Don't ask：只放行预批准的，其余直接拒
  - Bypass：全跳过，只在容器或虚拟机里用

## 2. Shift+Tab 循环切换日常四种，底部状态栏显示当前模式

- 结论：✓
- 课时文字：04 L25；101-04 L12-13
- 官方依据（转述）：
  - Shift+Tab cycles default, then acceptEdits, then plan, with optional modes slotted in after plan; from auto the first press goes to default. https://code.claude.com/docs/en/permission-modes#switch-permission-modes
  - Not every mode is in the cycle: auto appears when it is available; bypassPermissions appears only if the session was started with a bypass flag or setting; dontAsk never appears (use `--permission-mode dontAsk`). 同上。
  - The status bar shows the active mode (texts in the table above). 同上。
  - On Windows, Alt+M does the same job when the Node or Bun runtime has not enabled VT input mode. https://code.claude.com/docs/en/interactive-mode （键盘快捷键表里 Shift+Tab 那一行）
- 准确写法：说法成立。补一句精确度：Auto 要“可用”才在循环里；Bypass 和 Don't ask 平时不在循环里。录屏时若从 Auto 开始，第一下 Shift+Tab 回到的是 Manual，再依次是 Accept edits、Plan、回到 Auto。
- 念法：Shift+Tab 循环切四种日常模式，状态栏看当前

## 3. Auto 模式：设计上拦什么、放行什么

- 结论：△（拦截名单对；放行里“推送到你自己的分支”是旧口径）
- 课时文字：04 L28-34、L43
- 官方依据（转述）：以下对应文档的默认名单。https://code.claude.com/docs/en/permission-modes#what-the-classifier-blocks-by-default
  - 课程说法逐条对照：

    | 课程说法 | 文档 |
    | - | - |
    | 拦：生产部署和迁移 | ✓ 在默认拦截名单里 |
    | 拦：强推 | ✓ force push 在名单里 |
    | 拦：把下载的代码直接管道进 shell | ✓ 下载并执行代码（例：curl 管道给 bash） |
    | 拦：向外部端点发送敏感数据 | ✓ |
    | 拦：不可逆地销毁会话前就存在的文件 | ✓ |
    | 放：项目内本地编辑 | ✓ 工作目录内的本地文件操作 |
    | 放：按锁文件安装依赖 | ✓ 安装锁文件或清单里声明的依赖 |
    | 放：只读请求 | ✓ 只读 HTTP 请求 |
    | 放：推送到你自己的分支 | △ 见下 |

  - 推送：现行名单是“推送到你正在做的这个仓库的任意分支，含默认分支”；名字像部署或发布目标的分支（production、gh-pages 之类）不在放行范围，由分类器单独判断；强推、夹带密钥的推送仍拦。v2.1.211 之前是“只放行你起步的分支、Claude 建的分支、对默认分支的常规推送”，v2.1.203 之前直推默认分支会被拦。
  - 设计目标的总述：分类器拦“超出你的请求、指向不认识的基础设施、或像是被读到的恶意内容驱动”的动作。https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode
  - “护栏仍在演进”：成立。文档的名单带着版本注记（v2.1.198、203、205、211、257、261 都有变动），官方也提供命令打印当前完整规则：`claude auto-mode defaults`（v2.1.208+）。https://code.claude.com/docs/en/cli-reference
- 准确写法：台本把放行说成“推到当前项目的分支”，别说“自己的分支”；拦截名单可以直接念上面四项，再补“名单还在更新”。
- 念法：Auto拦强推、生产部署、外传敏感数据，名单会更新

## 4. 分类器只判断危险与否、不判断代码对错；所以要配跑测试的 Stop hook

- 结论：△（思路有官方依据；“分类器不判断对错”这句文档没写明）
- 课时文字：04 L37-43；08 L12-13、L25-33
- 官方依据（转述）：
  - 文档对分类器的描述全是安全维度：超出请求、不认识的基础设施、被恶意内容驱动。通篇没有“它会检查代码是否正确”的说法。https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode
  - Claude Code 自己发给分类器的请求里，分类器能看到：你的消息、非只读的工具调用、CLAUDE.md；工具返回内容被剥掉了。所以它根本看不到测试输出（这是我的推论，文档没这么写；这里指客户端发起的分类器请求，服务端审查的细节文档没展开）。https://code.claude.com/docs/en/permission-modes#how-the-classifier-evaluates-actions
  - Stop hook fires when Claude finishes responding; a hook can stop Claude from stopping and tell it why (exit code 2 with the message on stderr, or a JSON `decision` of `block` with a `reason`). https://code.claude.com/docs/en/hooks#stop-decision-control
  - The hooks reference's own example is a Stop hook that verifies all unit tests pass before Claude finishes. https://code.claude.com/docs/en/hooks （Agent hook configuration 一节）
  - Best practices: give Claude a check it can run (tests, build, screenshot) — that is what turns a session you watch into one you can walk away from. https://code.claude.com/docs/en/best-practices#give-claude-a-way-to-verify-its-work
  - Anthropic 工程博客（2026-03-25）把分类器定位为手动审批和完全不设防之间的折中，并说它不是高风险基础设施上人工仔细审查的替代品；该页经摘要工具读取，未逐字核对。https://www.anthropic.com/engineering/claude-code-auto-mode
- 准确写法：
  - “分类器不判断代码对不对”可以讲，因为与官方对它的描述一致、且它看不到工具输出；但别说成官方明文。
  - Stop hook 要点：每次 Claude 回复结束都会触发（不只是任务做完），用户中断不触发；连续阻止 8 次且中间没有工具调用，Claude Code 会强行放行（`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` 可调高）。https://code.claude.com/docs/en/hooks#stop-input ，https://code.claude.com/docs/en/hooks-guide#stop-hook-hits-the-block-cap
  - 课程 08 说“退出码 2 把失败直接喂回 Claude”：对 Stop hook 成立（stderr 内容作为理由交给 Claude）。
- 念法：分类器只管危险不危险，代码对不对，要靠测试。

## 5. Don't ask：适合 CI 流水线、定时任务、过夜批处理

- 结论：✓（CI 和批处理循环有官方示例；定时任务要补一句）
- 课时文字：04 L19-20、L46、L52-53
- 官方依据（转述）：
  - The mode table lists Don't ask as best for locked-down CI and scripts; the page says to use it for CI pipelines or restricted environments where you pre-define what Claude may do, so the session never waits for input. https://code.claude.com/docs/en/permission-modes#available-modes ，https://code.claude.com/docs/en/permission-modes#allow-only-pre-approved-tools-with-dontask-mode
  - Official CI recipe: `claude -p "<任务>" --permission-mode dontAsk --allowedTools "Bash(npm test)" "Read"`. https://code.claude.com/docs/en/permission-modes#common-setups
  - The best-practices batch example loops over a long list of files with `--permission-mode dontAsk` and notes it matters when you run unattended. https://code.claude.com/docs/en/best-practices#fan-out-across-files
  - For a scheduled job, the headless page's own example is Auto mode plus `--permission-prompts none` (anything that would prompt is denied, Claude is told not to retry; requires v2.1.259+). https://code.claude.com/docs/en/headless#turn-off-permission-prompts-in-unattended-runs
- 准确写法：台本说“CI 这类没人点确认的场景用 Don't ask”最稳；“定时任务、过夜批处理”是课程的例子，官方明确举例的是 CI 和批量循环，定时任务官方用的是 Auto + `--permission-prompts none`。另外：Don't ask 不在 Shift+Tab 循环里，要用 `--permission-mode dontAsk` 启动；云端会话会忽略设置文件里的 `dontAsk`。
- 念法：没人点确认的场景，比如CI，用Don't ask。

## 6. 无人值守的运行留在 Auto 而不是 Bypass；验证随“看得越少”加码；先看 diff 不看摘要

- 结论：✓（前半句官方明文支持；“先看 diff”是课程建议，方向一致）
- 课时文字：08 L9-21、L37-44
- 官方依据（转述）：
  - The docs warn that bypass gives no protection against prompt injection or unintended actions, and point to Auto when you want background safety checks with far fewer prompts. https://code.claude.com/docs/en/permission-modes#skip-all-checks-with-bypasspermissions-mode
  - The best-practices section on running autonomously with auto mode says to use Auto for uninterrupted runs with background safety checks (`claude --permission-mode auto -p <任务>`). https://code.claude.com/docs/en/best-practices#run-autonomously-with-auto-mode
  - The headless page shows an unattended task run in Auto with `--permission-prompts none`. https://code.claude.com/docs/en/headless#turn-off-permission-prompts-in-unattended-runs
  - The longer Claude works unattended, the more an independent check matters; a reviewer in a fresh context sees only the diff and your criteria, and the bundled `/code-review` skill reviews the current diff for bugs. https://code.claude.com/docs/en/best-practices#add-an-adversarial-review-step
  - The `acceptEdits` section itself suggests reviewing changes via `git diff` after the fact. https://code.claude.com/docs/en/permission-modes#auto-approve-file-edits-with-acceptedits-mode
- 准确写法：
  - 官方并非“无人值守一律不能用 Bypass”：在隔离容器里跑 `claude -p ... --dangerously-skip-permissions` 是官方列出的一种配置（要求容器、虚拟机或沙箱运行时，且非 root）。https://code.claude.com/docs/en/permission-modes#common-setups 台本说“在你自己的电脑或公司环境里，无人值守别开 Bypass”更稳。
  - “先看 diff 而不是摘要”官方没有这句话；最接近的是“让 Claude 拿出证据而不是只说做完了”。可以讲，但别说成官方原话。
  - ？课时文字 08 L17 的命令被编译吃掉，原文无法确认；官方里用来审查当前 diff 的是 `/code-review`（别名 `/review`）。https://code.claude.com/docs/en/commands

## 7. Auto 模式的可用条件与启用方式

- 结论：△（课程“取决于套餐和设置”已过时）
- 课时文字：101-02 L40（新会话从哪个模式开始，取决于套餐和设置）；04 L16
- 官方依据（转述）：https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode
  - Plan: all plans. Organization: on Team and Enterprise it is available by default, and admins can switch it off with `permissions.disableAutoMode: "disable"` in managed settings.
  - Model: on the Anthropic API and Claude Platform on AWS, Opus 4.6 or later, Sonnet 4.6 or later, or a Fable model; on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and signed-in Claude apps gateway sessions, only Sonnet 5 or later, Opus 4.7 or later and the Fable models. Older models (Sonnet 4.5, Opus 4.5, Haiku, claude-3) are not supported anywhere.
  - Also unavailable when a settings file turns it off, or when Anthropic has switched it off server-side; a session that asks for Auto then starts in Manual. https://code.claude.com/docs/en/permission-modes#which-mode-a-session-starts-in
  - Starting mode: the docs say that from v2.1.283 interactive terminal and VS Code sessions begin in Auto on every plan and provider, unless a setting overrides it (the changelog files the same change under 2.1.284, 2026-09-28); before that it was Pro, Max and Team only. 同上；https://code.claude.com/docs/en/changelog#2-1-284
- 准确写法（启用方式）：
  - 不需要任何开关。老的 `--enable-auto-mode` 参数已在 v2.1.111（2026-04-16）移除；现在可用时 Auto 就在 Shift+Tab 循环里，或用 `claude --permission-mode auto` 直接启动。https://code.claude.com/docs/en/cli-reference
  - 想让每个会话都从 Auto 开始：在 `~/.claude/settings.json` 里设 `permissions.defaultMode` 为 `auto`；写在项目的 `.claude/settings.json` 或 `.claude/settings.local.json` 里不生效。
  - 管理员关掉后，Shift+Tab 里没有 Auto，`--permission-mode auto` 也会退回 Manual。
- 念法：所有套餐可用，要较新模型，管理员能关

## 可以多讲一句的具体细节（≤ 3 条）

1. 想看当前最新的拦截 / 放行名单，命令行跑 `claude auto-mode defaults`（以 JSON 打印内置规则，v2.1.208+）；`claude auto-mode config` 看你这边生效后的配置。出处：https://code.claude.com/docs/en/permission-modes#what-the-classifier-blocks-by-default ，https://code.claude.com/docs/en/cli-reference
2. 在对话里说一句“先别推送，等我看完”，分类器会照着拦；但上下文压缩可能把这句话压没，要硬保证就写 deny 规则（或 ask 规则让它每次都弹窗）。出处：https://code.claude.com/docs/en/permission-modes#boundaries-you-state-in-conversation ，https://code.claude.com/docs/en/auto-mode-config#add-a-human-checkpoint
3. Auto 不是死磕：同一会话里分类器连续拦 3 次、或累计拦 20 次，Auto 会暂停、回到弹窗询问（这两个阈值不能改）；被拦的动作在 `/permissions` 的 Recently denied 页里，按 r 可手动放行重试。出处：https://code.claude.com/docs/en/permission-modes#when-auto-mode-falls-back

## 不要讲的

- “用 `--enable-auto-mode` 打开”“Auto 是研究预览、只有 Team 套餐有”：2026 年 3 月的老说法，参数已移除，现在所有套餐可用，新版默认就从 Auto 开始。（老博客 claude.com/blog/auto-mode 经摘要工具读取，未逐字核对。）
- “Auto 只放行推送到你自己的分支”：旧口径，见第 3 条。
- “Auto 逐个动作都审查”：读取和项目内改文件不过分类器。
- “Auto 能保证安全”：官方警告 Auto 只是减少弹窗，不保证安全，也不替代敏感操作上的人工复核。https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode
- “Bypass 什么都不拦 / 可以随时切进去”：deny 规则照样生效，必须启动时开启。
- “Don't ask 可以用 Shift+Tab 切到”：不在循环里。
- “Stop hook 只在任务全部完成时触发”：每次回复结束都触发，用户中断不触发。
