## 逐条核对

### 4-1　上下文窗口是什么　✓

- **说法**：上下文窗口 = Claude 能装下的“记忆”空间；每次提示、读文件、工具调用及其返回结果都会占用。
- **官方原话**：
  - 术语表 Context window："The working memory for a session" 。出处：[glossary](https://code.claude.com/docs/en/glossary)
  - "every message, every file Claude reads, and every command output" ；"LLM performance degrades as context fills" 。出处：[best-practices](https://code.claude.com/docs/en/best-practices)
  - 课时文字 06："it's all adding to the context window"
- **准确写法**：官方术语表直接把窗口叫 “working memory”，课程的“记忆”比喻有依据。但文档里单说 memory 通常指跨会话的 CLAUDE.md / auto memory，口播里说成“短期工作记忆”更不容易混。窗口里还有你看不到的东西：你还没开口，就已加载 "CLAUDE.md, auto memory, MCP tool names, and skill descriptions" （[context-window](https://code.claude.com/docs/en/context-window) 页，Before you type anything）。装满会变差：best-practices 说 Claude 可能 'start "forgetting" earlier instructions or making more mistakes'。
- **念法**：「上下文窗口，就是 Claude 一次能装下的内容」（24 字）；「窗口越满，表现越差」（9 字）

### 4-2　接近上限时自动压缩　✓

- **说法**：接近上限时自动压缩（compaction）：总结要点、清掉不必要的工具调用结果；可能丢失细节。
- **官方原话**：
  - "It clears older tool outputs first, then summarizes the conversation if needed" ；"detailed instructions from early in the conversation may be lost" 。出处：[how-claude-code-works](https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up)
  - 术语表 Compaction："Project-root CLAUDE.md and auto memory survive compaction and reload from disk" 。出处：[glossary](https://code.claude.com/docs/en/glossary)
  - 课时文字 06："Note that this process can potentially lose details"
- **准确写法**：顺序是先清旧的工具输出，不够再总结；“你的请求和关键代码片段”会保留（"Your requests and key code snippets are preserved"）。极端情况：一个超大的文件或输出压完立刻又装满，几次后 Claude Code 会停止自动压缩并报 "Autocompact is thrashing" （[troubleshooting](https://code.claude.com/docs/en/troubleshooting)）。
- **念法**：「快满时自动压缩：先清旧工具结果，再总结对话」（21 字）；「压缩会丢细节，早期的详细指令可能没了」（18 字）

### 4-3　/compact 手动压缩与带指令　✓

- **说法**：/compact 手动压缩（到此为止的一切被压缩，但保留之前所做事情的记忆）；可在命令后写指令来引导摘要保留什么（实战课说法）。
- **官方原话**：
  - 命令表 `/compact [instructions]`："Free up context by summarizing the conversation so far" ；"Optionally pass focus instructions for the summary" 。出处：[commands](https://code.claude.com/docs/en/commands)
  - "run /compact with instructions, like /compact focus on the auth bug fix" 。出处：[context-window](https://code.claude.com/docs/en/context-window#when-your-context-fills-up)
  - "add a 'Compact Instructions' section to CLAUDE.md" 。出处：[how-claude-code-works](https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up)
  - 课时文字（实战课 01）："Anything you write after the command shapes what the summary keeps"
- **准确写法**：官方写的是“摘要”（summarizing），不是原样保留，所以“保留记忆”建议说成“压成摘要接着干”。写法 `/compact [instructions]`；可以把默认指令写进 CLAUDE.md 的 “Compact Instructions” 小节。想只压一部分：`/rewind`（或连按两下 Esc）→ "Summarize from here" / "Summarize up to here" （[checkpointing](https://code.claude.com/docs/en/checkpointing)；更新日志 Week 20 加入了 “Summarize up to here”）。
- **念法**：「/compact 手动压缩，后面还能写要保留什么」（24 字）；「/compact 重点保留 API 改动」（20 字）

### 4-4　/clear 完全清空　△

- **说法**：/clear 完全清空，没有上一次会话的记忆。
- **官方原话**：
  - 命令表 `/clear [name]`："Start a new conversation with empty context" ，别名 /reset、/new。出处：[commands](https://code.claude.com/docs/en/commands)
  - "/clear starts fresh on a new task while keeping project memory" 。出处：commands（Commands across a typical workflow 的 Between sessions 一段）
  - 术语表 Session："the previous one stays stored and is available via /resume" 。出处：[glossary](https://code.claude.com/docs/en/glossary)
  - 课时文字 06："This removes everything."
- **准确写法**：对话上下文清零 ✓，但别说“清掉一切”：① CLAUDE.md 和 auto memory 新对话照常加载（“keeping project memory”）；② 旧对话没被删，`/resume` 能找回，同一进程里还能从 `/rewind` 菜单的 "previous session" 条目回去（[checkpointing](https://code.claude.com/docs/en/checkpointing)；更新日志 Week 26）。
- **念法**：「/clear 清空对话，CLAUDE.md 照常加载」（26 字）

### 4-5　/context 查看上下文用量　✓

- **说法**：/context 查看上下文用量：总大小、占用最多的类别、可视化图。
- **官方原话**：
  - `/context [all]`："Visualize current context usage as a colored grid" ；"optimization suggestions for context-heavy tools, memory bloat, and capacity warnings" 。出处：[commands](https://code.claude.com/docs/en/commands)
  - "a live breakdown by category with optimization suggestions" 。出处：[context-window](https://code.claude.com/docs/en/context-window#check-your-own-session)
- **准确写法**：名称没变，仍是 `/context`，可加参数 `all` 展开明细。除了看用量，还给优化建议，并能看到启动时加载了哪些 CLAUDE.md / 记忆文件（Memory files）。别和 `/usage` 混：`/usage`（别名 `/cost`、`/stats`）看的是花费和套餐额度。
- **念法**：「/context 看窗口用了多少、谁占得最多」（22 字）

### 4-6　经验规则　✓

- **说法**：同一功能做到快满时用 /compact；开始新功能时用 /clear；需要跨会话记住的放进 CLAUDE.md。
- **官方原话**：
  - "Clear between tasks" ；"run /clear when switching to unrelated work" 。出处：[context-window](https://code.claude.com/docs/en/context-window#when-your-context-fills-up)
  - "Put persistent rules in CLAUDE.md rather than relying on conversation history" 。出处：[how-claude-code-works](https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up)
  - "After two failed corrections, /clear and write a better initial prompt" 。出处：[best-practices](https://code.claude.com/docs/en/best-practices#avoid-common-failure-patterns)
- **准确写法**：方向一致。三处补充：① 自动压缩本来就会在快满时触发，手动 /compact 的价值是你来指定保留什么（"keeps what you choose instead of what the automatic pass guesses"，context-window 页）；② 跨会话记忆有两套：你写的 CLAUDE.md，和 Claude 自己记的 auto memory（[memory](https://code.claude.com/docs/en/memory) 页开头 "Two mechanisms carry knowledge across sessions"）；③ 同一个问题纠正两次还不对，直接 /clear 重来。
- **念法**：「同功能续做用 /compact，换功能用 /clear」（27 字）；「要跨会话记住的：写进 CLAUDE.md」（20 字）

### 4-7　提示越具体越省上下文　✓

- **说法**：含糊的提示看着短，却会让 Claude 多探索代码库、自己推理，反而更费上下文。
- **官方原话**：
  - "Vague requests like 'improve this codebase' trigger broad scanning" ；"let Claude work efficiently with minimal file reads" 。出处：[costs](https://code.claude.com/docs/en/costs)（Write specific prompts）
  - "Claude reads hundreds of files, filling the context" 。出处：[best-practices](https://code.claude.com/docs/en/best-practices#avoid-common-failure-patterns)（The infinite exploration）
  - 课时文字 06："A vague prompt might seem smaller"
- **准确写法**：成立。文档同时承认含糊提示在探索阶段有用："Vague prompts can be useful when you're exploring" （best-practices）。所以别说成“含糊提示一律不好”，说“目标明确的活要写具体”。
- **念法**：「提示越具体越省上下文，含糊反而来回翻文件」（20 字）

- **没确认的**：那个环境变量的名字，我这次抓 env-vars 页，两次结果写法不一致（CLAUDE_AUTOCOMPACT_PCT_OVERRIDE，另一次带了 CODE_ 前缀），没能确认，视频里别念变量名。

### 4-8b　另请核对：各模型的 token 触发边界　✓

- **官方原话**（出处：[model-config](https://code.claude.com/docs/en/model-config#default-auto-compact-thresholds)，Default auto-compact thresholds）：
  - "compact before the window fills, at about 967K tokens by default" ：Anthropic API 上的原生 1M 窗口模型，包括 Sonnet 5.5 / Sonnet 5、Fable 系列、Opus 4.7 及以后。
  - "compact at the 200K boundary" ：Sonnet 4.6 和 Opus 4.6 没开扩展上下文时；云厂商上以 200K 窗口跑的 Opus 4.8 及以后；设了 CLAUDE_CODE_DISABLE_1M_CONTEXT=1 的原生 1M 模型。
  - 云端会话："compact as the conversation approaches the model's limit"
  - Sonnet 5.5 / Sonnet 5：同页 "always run with the 1M context window"，没有 200K 版本，也不用选 [1m] 变体。
- **可调**：`/autocompact <tokens>`（窗口 100K 到 1M，需 v2.1.221+，存进用户设置）；`claude --autocompact`；settings 的 `autoCompactWindow`；环境变量 `CLAUDE_CODE_AUTO_COMPACT_WINDOW`（优先级最高）。定义原话："how full the context window can get before Claude Code compacts the conversation" 。
- **注**：967K 约等于 1M 窗口的 96.7%，这个百分比是我算的，文档没写。
- **念法**：「原生百万窗口模型，约 96.7 万 token 才压缩」（27 字）。可选，只在讲到具体模型时用；视频里别讲百分比。

## 可以多讲一句的具体细节

1. **压缩之后，CLAUDE.md 会从磁盘重新读一遍。** 项目根 CLAUDE.md、auto memory、plan 模式写的计划都是重新注入；最近读过或改过的文件，最多重读五个；调用过的技能正文每个最多 5,000 token、合计 25,000。出处：[context-window](https://code.claude.com/docs/en/context-window#what-survives-compaction) “What survives compaction” 表。
   念法：「压缩后，CLAUDE.md 会从磁盘重新读一遍」（23 字）
2. **同一个问题纠正两次还不对，就 /clear 重来。** 出处：[best-practices](https://code.claude.com/docs/en/best-practices#manage-your-session) "If you've corrected Claude more than twice on the same issue in one session" ，后面写 "almost always outperforms a long session with accumulated corrections" 。
   念法：「同一个问题纠正两次还不对，就 /clear 重来」（24 字）
3. **小问题用 /btw，答案不占上下文。** 出处：[best-practices](https://code.claude.com/docs/en/best-practices#manage-context-aggressively) "The answer never enters conversation history" ；命令描述见 4-8c 的 /btw 一行。
   念法：「小问题用 /btw，答案不占上下文」（17 字）

## 不要讲的

1. 具体百分比（95%、80% 之类）：文档没写（4-8a）。
2. “窗口就是 20 万 token”：现在分模型。Sonnet 5.5 / Sonnet 5 是原生 1M 窗口；Sonnet 4.6 / Opus 4.6 不开扩展上下文才是 200K（4-8b）。
3. “/clear 把对话彻底删了、找不回”：旧会话还存着，/resume 能回（4-4）。
4. “压缩之后什么都不会丢”：文档明说早期的详细指令可能丢（4-2）。
5. “一接 MCP 服务器窗口就被占满”：文档说 MCP 工具定义默认延迟加载，只占工具名和服务器说明（"MCP tool definitions are deferred by default"，[how-claude-code-works](https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up)）。未使用的服务器关掉仍是官方建议（[costs](https://code.claude.com/docs/en/costs)），但别讲成一次性吃掉一大块。Chrome 集成设成“默认启用”才会明显多占（[chrome](https://code.claude.com/docs/en/chrome)）。
6. “含糊提示一律更差”：官方承认探索阶段含糊提示有用（4-7）。
7. “/cost 看上下文”：/cost 是 /usage 的别名，看费用和额度，不是窗口占用（4-5）。
8. 念环境变量名（CLAUDE_AUTOCOMPACT_PCT_OVERRIDE 之类）：名称两次抓取不一致，没确认（4-8a）。
9. 课时文字 06 里那几条被编译吃掉的小标题（MCP 服务器、Skills、子代理的省上下文技巧）：原文丢了，不能凭残句写，要用得先去官方 [costs](https://code.claude.com/docs/en/costs) 页的 Reduce token usage 核。
