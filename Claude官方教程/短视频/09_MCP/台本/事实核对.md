## 2. claude mcp add；HTTP 与 stdio；SSE 是否弃用

- 结论：✓（“两类”是讲最常用的两种，别说成“只支持两种”）
- 课时文字：L17-27（两种类型：HTTP 远程服务、stdio 本机进程）
- 官方依据：
  - HTTP is the recommended, most widely supported transport for remote servers. https://code.claude.com/docs/en/mcp#option-1-add-a-remote-http-server
  - 逐字引用（仅此一处）："The SSE (Server-Sent Events) transport is deprecated" ，https://code.claude.com/docs/en/mcp#option-2-add-a-remote-sse-server
  - Since v2.1.265, `--transport http` tries HTTP first and falls back to SSE by itself when a server only speaks SSE. 同上页。
  - Stdio servers are local processes; the `--` separates Claude's own flags from the server's launch command, and everything after it goes to the server untouched. https://code.claude.com/docs/en/mcp#option-3-add-a-local-stdio-server
  - WebSocket (`"type": "ws"`) is configured only through `claude mcp add-json` or `.mcp.json`; `--transport` does not accept `ws`. https://code.claude.com/docs/en/mcp#option-4-add-a-remote-websocket-server
  - 最佳实践页的提示用的也是同一个格式（`claude mcp add --transport http <名字> <地址>`）。https://code.claude.com/docs/en/best-practices#connect-mcp-servers
- 准确写法（当前命令格式）：

  ```bash
  # 远程 HTTP（推荐）；需要令牌时加 --header
  claude mcp add --transport http <name> <url>
  # 本机 stdio：-- 前是 Claude 的选项，-- 后原样交给服务器
  claude mcp add [options] <name> -- <command> [args...]
  claude mcp add --env API_KEY=<key> --transport stdio myserver -- npx -y <package>
  # SSE（已弃用，只给老服务器用）
  claude mcp add --transport sse <name> <url>
  # 管理
  claude mcp list
  claude mcp get <name>
  claude mcp remove <name>
  ```

  JSON 配置里 `streamable-http` 是 `http` 的别名；写了 `url` 却没写 `type`，会被当成 stdio 而报错。
- 念法：远程用HTTP，本机用stdio，一条命令搞定

## 3. /mcp 查看已连接服务器、状态，禁用不用的

- 结论：✓
- 课时文字：L26-28（/mcp 看连接、查状态、禁用）、L44（服务器详情页：看工具、重连、禁用）
- 官方依据（转述）：
  - `/mcp` manages server connections and OAuth sign-in; with no argument it opens the interactive list, and it also takes `reconnect`, `enable`, `disable` plus a server name or `all`. https://code.claude.com/docs/en/commands （/mcp 一行）
  - The panel shows each connected server's tool count; toggling a server off stops Claude Code from connecting but keeps its configuration, and the server stays listed as disabled. https://code.claude.com/docs/en/mcp#tool-availability ，https://code.claude.com/docs/en/mcp#disable-a-server-without-removing-it
  - 官方成本页同样建议：用 `/mcp` 看配置了哪些服务器，把暂时不用的关掉。https://code.claude.com/docs/en/costs#reduce-mcp-server-overhead
- 准确写法：补充一点：禁用是按项目记的（写在 `~/.claude.json` 的 `disabledMcpServers`），不是删除；想彻底去掉用 `claude mcp remove <名字>`。
- 念法：输入/mcp，看连接状态，不用的直接关掉。

## 4. 三种作用域：local / user / project

- 结论：✓
- 课时文字：L31-39
- 官方依据（转述）：
  - Three scopes: local (the default; private to you, this project only), project (a `.mcp.json` at the project root, shared through version control), user (private to you, every project). When the same server name appears in several places, Claude Code uses the highest-precedence definition whole, without merging fields. https://code.claude.com/docs/en/mcp#mcp-installation-scopes ，https://code.claude.com/docs/en/mcp#scope-hierarchy-and-precedence
  - Where each one lives on disk, plus the Windows path. https://code.claude.com/docs/en/mcp-quickstart#find-your-configuration-on-disk
  - 功能总览也有一句同样的优先级：MCP servers override by name, local > project > user。https://code.claude.com/docs/en/features-overview
- 准确写法：

  | 名称 | 谁能用 | 存在哪 | 进版本库 |
  | - | - | - | - |
  | `local`（默认） | 只你、只当前项目 | `~/.claude.json` 里该项目路径下（Windows：`%USERPROFILE%\.claude.json`） | 否 |
  | `project` | 克隆这个项目的所有人 | 项目根目录 `.mcp.json` | 是 |
  | `user` | 只你、你的所有项目 | `~/.claude.json` 顶层 `mcpServers` | 否 |

  - 选作用域：`--scope local|project|user`，不写就是 local。
  - 优先级（同名时）：local > project > user > 插件自带 > claude.ai 连接器；同名按名字匹配，取优先级最高的那一整条，不合并字段。管理员用托管设置下发的服务器排在最前（v2.1.259+）。
  - `.mcp.json` 里的服务器，交互会话里第一次用要你确认（审批可用 `claude mcp reset-project-choices` 重置）。
  - 作用域加完就定了，要改只能删掉再重加；`claude mcp get <名字>` 能看到它在哪个作用域。
  - 易混：MCP 的 local 是存在 `~/.claude.json`，不是项目里的 `.claude/settings.local.json`。
- 念法：三档范围：自己用、跨项目、全队共享（.mcp.json）

## 5. MCP 把工具定义加进上下文，即使没在用；有 CLI 时 CLI 更省

- 结论：△（前半句已过时；后半句 ✓）
- 课时文字：L42-47
- 官方依据（转述）：
  - 现行默认：MCP tool definitions are deferred; only tool names and server instructions enter context until Claude uses a tool. https://code.claude.com/docs/en/costs#reduce-mcp-server-overhead ，https://code.claude.com/docs/en/mcp#scale-with-mcp-tool-search ，https://code.claude.com/docs/en/how-claude-code-works （上下文窗口一节）
  - 官方上下文成本表：MCP = tool names at start, full schemas on demand, so the cost stays low until a tool is actually used. https://code.claude.com/docs/en/features-overview#context-cost-by-feature
  - 快速上手页：每个连接的服务器仍会占一点空间，因为工具名和服务器说明每个会话都要载入。https://code.claude.com/docs/en/mcp-quickstart （删除服务器那一步的提示）
  - CLI: `gh`, `aws`, `gcloud`, `sentry-cli` are still more context-efficient than MCP servers, because they add no per-tool listing. https://code.claude.com/docs/en/costs#reduce-mcp-server-overhead
  - The best-practices page goes further: CLI tools are the most context-efficient way to work with external services, so tell Claude to use `gh`, `aws`, `gcloud`, `sentry-cli` where they exist. https://code.claude.com/docs/en/best-practices#use-cli-tools
- 准确写法：
  - “即使没在用也把工具定义加进上下文”是旧默认。现在默认只放“工具名 + 服务器说明”，完整定义用到才载入。只有把 `ENABLE_TOOL_SEARCH` 设成 `false`、`ANTHROPIC_BASE_URL` 指向第三方网关（默认关闭 tool search）等情况，才会一上来全载入。
  - 想看实际占用：`/context`（`/context all` 可看到每个已载入 MCP 工具的 token）。https://code.claude.com/docs/en/features-overview#understand-how-features-load
  - “服务器多了会吃上下文”：方向没错，但程度要说“占一点”，别说“吃掉一大块”。
- 念法：接得多会占点上下文，有gh、aws命令行就更省

## 6. 超过 10% 自动切到 tool search，“可能没那么可靠”

- 结论：△（10% 不是默认触发条件；“没那么可靠”？文档没写）
- 课时文字：L51
- 官方依据（转述）：
  - Tool search is on by default: MCP tools are deferred and found on demand; the start-of-session context holds only names and server instructions. https://code.claude.com/docs/en/mcp#configure-tool-search
  - `ENABLE_TOOL_SEARCH` values: unset = defer everything; `auto` = load upfront while the definitions stay under 10% of the context window, defer all once they reach it; `auto:N` = same with your own percentage 0–100 (example `auto:5`); `false` = load everything upfront. 同上页的取值表。
  - 更新日志 2.1.7（2026-01-14）确实写过：tool search auto mode 对所有人默认开启，MCP 工具描述超过窗口 10% 就自动延后加载——课程那句应该就是据此写的；2.1.9 加了 `auto:N`。现行 MCP 页、成本页、功能总览写的都是“默认就是延后加载”。https://code.claude.com/docs/en/changelog#2-1-7
  - 可靠性：MCP 页、成本页、功能总览、工作原理页里都没有“tool search 不太可靠”的说法。API 文档的 tool search 页说的是另一个方向：工具超过 30–50 个后选择准确率会下降，tool search 能把它保持住。https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool
- 准确写法：
  - 阈值：10% 只属于 `ENABLE_TOOL_SEARCH=auto`；`auto:N` 可自定义百分比。
  - 行为：默认所有 MCP 工具都延后，Claude 需要时用 `ToolSearch` 找并载入；需要支持 `tool_reference` 的模型（Sonnet 4.5 / Haiku 4.5 / Opus 4.5 及更新）。
  - 关闭 / 绕开：`ENABLE_TOOL_SEARCH=false`（全部一上来载入）；或在 `permissions.deny` 里写 `ToolSearch`；或给某个服务器配 `"alwaysLoad": true`，只让它的工具常驻。`ANTHROPIC_BASE_URL` 指向非官方主机、设置了 `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` 时会自动关。
- 念法：默认只先放工具名，用到哪个再加载哪个

## 7. 技能只把名称和描述放进上下文，需要时才加载全文——可作为替代

- 结论：△（加载方式 ✓；“替代”要改成“互补”）
- 课时文字：L48-50
- 官方依据（转述）：
  - In a regular session, skill descriptions sit in context so Claude knows what exists; the full skill text loads only when the skill is invoked. https://code.claude.com/docs/en/skills#control-who-invokes-a-skill
  - 功能总览的成本表：Skills = descriptions at start, full content when used；MCP = tool names at start, schemas on demand。https://code.claude.com/docs/en/features-overview#context-cost-by-feature
  - 功能总览专门有 “MCP vs Skill” 一节：二者解决不同问题、配合使用——MCP 提供工具和数据访问（连接与认证由服务器处理），技能提供知识和工作流（比如怎么用好这些工具）。https://code.claude.com/docs/en/features-overview （MCP vs Skill 标签页）
- 准确写法：技能能省的是“知识类”内容（接口规范、数据库表结构、操作流程）的上下文，不能代替 MCP 去连数据库、读工单。对“工具定义占上下文”这个问题，官方给的办法是 tool search、关掉不用的服务器、能用 CLI 就用 CLI，没有把“改用技能”当成标准答案。若要说“技能可以替代”，改成“有些场景，写个技能就够了”。
- 念法：技能平时只占名称和描述，用到才加载全文。
