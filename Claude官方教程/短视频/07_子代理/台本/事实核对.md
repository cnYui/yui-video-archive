## 说法 1：独立上下文，只回答案

> 待核对：探索代码库、做网页研究这类工具调用会吃掉大量上下文；子代理在自己独立的上下文窗口里完成，只把答案返回主对话，主上下文保持干净。

**1　✓ 文档支持**
- 官方原话：
  - "the subagent does that work in its own context and returns only the summary" — https://code.claude.com/docs/en/sub-agents（开头第一段）
  - "Subagents run in separate context windows and report back summaries" — https://code.claude.com/docs/en/best-practices（Use subagents for investigation）
  - 课时文字：introduction-to-subagents__01-what-are-subagents.txt — "only a summary comes back to your main conversation"
- 要加的限定（别讲成“完全不占 / 不花钱”）：
  - 子代理自己也发请求、也计入你的用量："which count toward the same usage limits" — sub-agents 页开头；"each subagent spends tokens of its own while it runs" — 同页 Common patterns 的警告。
  - 多个子代理各返回一大段结果，主上下文照样会涨（同一条警告）。
  - 子代理是从零开始的，"It doesn't see your conversation history" — https://code.claude.com/docs/en/sub-agents#what-loads-at-startup ；主代理会替它写一段任务说明。
- 建议念法：「子代理在自己的窗口里翻完资料，只把结论带回来」
- 可加冷水一句：「子代理自己也花用量，别当成免费的」

## 说法 2：定义文件、创建入口、文件位置

> 待核对：子代理定义在带 YAML frontmatter 的 Markdown 文件里；最简单的方式是让 Claude 帮你生成（/agents → Create new agent）。请核对当前命令和界面入口、文件位置。

**2a　✓ 定义在带 YAML frontmatter 的 Markdown 文件里**
- 官方原话："Subagents are Markdown files with YAML frontmatter" — https://code.claude.com/docs/en/sub-agents（Quickstart）
- 补充：文件正文就是系统提示词；子代理只拿到这段提示词加工作目录等基本环境信息，不带 Claude Code 自己的系统提示词（同页 Write subagent files）。
- 建议念法：「子代理就是带 YAML 头的 Markdown 文件」

**2b　✓ 最简单的方式是让 Claude 帮你生成**
- 官方原话："ask Claude to write it for you" — https://code.claude.com/docs/en/sub-agents（Quickstart，整句是 To create one, ask Claude to write it for you, or write the file yourself）
- 官方示例做法：在对话里描述想要的子代理和存放位置，Claude 就写出带 name、description、tools、model 的文件。
- 建议念法：「最省事：直接对 Claude 说，帮我建个子代理」

**2c　✗ “/agents → Create new agent”与现行文档不符**
- 官方原话：
  - "On Claude Code v2.1.197 and earlier, `/agents` opens an interactive wizard" — https://code.claude.com/docs/en/sub-agents（Quickstart 后的 Note）
  - 命令表里 `/agents` 的现行说明："Print a reminder to ask Claude to create or manage subagents" — https://code.claude.com/docs/en/commands
  - 更新日志 2.1.198（2026-07-01）："Removed the `/agents` wizard; ask Claude to create or manage subagents" — https://code.claude.com/docs/en/changelog
- 课时文字 introduction-to-subagents__02-creating-a-subagent.txt 和 claude-code-101__09-subagents.txt 讲的 “Create new agent” 流程（范围 → 生成方式 → 工具类别 → 模型 → 颜色）就是这个旧向导。
- 准确写法：现在没有向导。创建的办法是：让 Claude 写；自己写文件放进目录；命令行 `--agents` 传 JSON（只对当次会话有效，不存盘）；装插件。注意命令行 `claude agents` 现在是“后台会话总览”，和配置子代理无关，别混。
- 建议念法：不要讲向导；改用 2b 那句。

**2d　✓ 文件位置**
- 官方原话：表格里 `.claude/agents/` 的范围是 "Current project"，`~/.claude/agents/` 是 "All your projects" — https://code.claude.com/docs/en/sub-agents#choose-the-subagent-scope ；项目级建议进版本库："Check them into version control so your team can use and improve them collaboratively"。
- 同名时的优先级（高 → 低）：管理员托管设置 > 命令行 `--agents` > 项目 `.claude/agents/` > 用户 `~/.claude/agents/` > 插件的 `agents/`。
- 补充：文件改了不用重启，"within a few seconds" 生效；只有会话开始时还不存在的 `agents` 目录，第一次在里面建文件后要重启（同页 Write subagent files 的 Note）。
- 建议念法：「放项目里只在这个项目用，放用户目录哪都能用」

## 说法 3：frontmatter 字段

> 待核对：frontmatter 字段：name、description（决定何时调用）、tools、model 等；请核对当前支持的字段清单。

**3　✓ 文档支持（并给出当前完整清单）**
- 官方原话："Only `name` and `description` are required." — https://code.claude.com/docs/en/sub-agents#supported-frontmatter-fields
  - `description`："When Claude should delegate to this subagent"
  - `tools`："Inherits every tool available to subagents if omitted"
  - `model`：sonnet、opus、haiku、fable、完整模型 ID（如 claude-opus-5-5）或 inherit。课时文字只有 sonnet / opus / haiku / inherit，现在多了 `fable` 别名和完整模型 ID。
- 当前清单共 18 个：必填 `name`、`description`；可选 `tools`、`disallowedTools`、`model`、`permissionMode`、`maxTurns`、`skills`、`mcpServers`、`hooks`、`memory`、`background`、`omitClaudeMd`、`effort`、`isolation`、`color`、`initialPrompt`、`experimental`。
- `color` 可选 red / blue / green / yellow / purple / orange / pink / cyan（课时文字讲的“选颜色”对得上）。
- 小坑：字段名是 camelCase，要和表里完全一致，"Claude Code ignores a field it doesn't recognize without reporting an error"（写错了不报错，直接不生效）。
- 建议念法：「必填就两个：名字和描述，描述决定它什么时候出场」

## 说法 4：持久记忆、预加载技能

> 待核对：进阶：持久记忆（跨对话保留）；预加载技能（skills 字段；与主对话不同，整份技能都会载入子代理上下文）。

**4a　✓ 持久记忆（跨对话保留）**
- 官方原话："a persistent directory that survives across conversations" — https://code.claude.com/docs/en/sub-agents#enable-persistent-memory
- 写法：frontmatter 加 `memory: user | project | local`。三个范围的目录：`~/.claude/agent-memory/<名字>/`（所有项目）、`.claude/agent-memory/<名字>/`（本项目，可进版本库）、`.claude/agent-memory-local/<名字>/`（本项目，不进版本库）。文档推荐默认用 `project`："`project` is the recommended default scope"。
- 开了以后：系统提示词里带上记忆目录里 `MEMORY.md` 的前 200 行或 25KB，并自动给它 Read / Write / Edit 工具。
- 限制：记忆算“自动记忆”的一部分，关掉自动记忆，"the `memory` field has no effect"。
- 建议念法：「加一行 memory，子代理就能跨对话记住东西」

**4b　✓ 预加载技能，整份进上下文**
- 官方原话："The full skill content is injected, not only the description" — https://code.claude.com/docs/en/sub-agents#supported-frontmatter-fields（`skills` 行）
- 对比主对话："full skill content only loads when invoked" — https://code.claude.com/docs/en/skills（Control who invokes a skill 后的 Note；同一段明说带预载技能的子代理 "work differently"）
- 限定："This field controls which skills are preloaded, not which skills the subagent can access" — https://code.claude.com/docs/en/sub-agents#preload-skills-into-subagents ；没列出的技能子代理仍可以通过 Skill 工具自己调；设了 `disable-model-invocation: true` 的技能不能预载。
- 建议念法：「skills 字段预载技能，整份都塞进子代理上下文」

## 说法 5：内置子代理

> 待核对：内置子代理（如 Explore、Plan、general-purpose）：请核对当前内置子代理名单和各自用途。

**5　✓ 三个都对得上（文档另列三个辅助子代理）**
- 官方原话（都在 https://code.claude.com/docs/en/sub-agents#built-in-subagents）：
  - Explore："A fast, read-only agent optimized for searching and analyzing codebases"；工具是只读的（Write、Edit 被拒绝）；Claude 调用时会选深度："quick for targeted lookups, medium for balanced exploration, or very thorough"。
  - Plan："A research agent used during plan mode to gather context before presenting a plan"。
  - General-purpose："A capable agent for complex, multi-step tasks that require both exploration and action"；拥有子代理能用的全部工具。
- 文档另列三个辅助的（课时文字没提）：`claude`（兜底）、`statusline-setup`（你跑 `/statusline` 时）、`claude-code-guide`（问 Claude Code 功能时）。
- 与旧说法的差别：Explore 不再固定用 Haiku。更新日志 2.1.198："inherits the main session's model (capped at opus) instead of running on haiku"。Explore 和 Plan 还会跳过 CLAUDE.md 和 git status，为的是快和省："Explore and Plan skip your CLAUDE.md files and the git status snapshot"。
- 建议念法：「Explore 只读搜代码，Plan 做计划调研」；「通用子代理能探索，也能动手改代码」

## 说法 6：限制（嵌套、并行上限、权限）

> 待核对：请核对文档里关于子代理的限制：能不能再生成子代理、并行数量上限、是否继承权限等。

**6a　✓ 能再生成子代理，默认最多 3 层（与常见旧说法相反）**
- 官方原话："subagent can spawn subagents of its own, up to three layers" — https://code.claude.com/docs/en/sub-agents#let-subagents-spawn-their-own-subagents （层数从主对话下面算起；到了上限就不再给它 Agent 工具）
- 改上限：环境变量 `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`；"Set `1` to turn nesting off"。
- 版本沿革（同页 Note + 更新日志）：v2.1.172（06-10）最多 5 层 → v2.1.217（07-21）默认不嵌套 → v2.1.219（07-24）默认 3 层。
- 注意：官方 context-window 页的互动演示里还留着一句 "by default the Agent tool itself to prevent recursion"（https://code.claude.com/docs/en/context-window），与 sub-agents 页和更新日志相反，以后者为准。
- 建议念法：「子代理还能再叫子代理，有层数上限，目前三层」

**6b　✓ 同时运行上限 20 个；总数不限**
- 官方原话："when 20 subagents are running in a session, spawning another with the Agent tool fails" — https://code.claude.com/docs/en/sub-agents#concurrent-subagent-limit （报错 `Concurrent subagent limit reached`）
- "There's no limit on the total number of subagents Claude can spawn over a session" — 同页（上限只管“同时在跑的”）。
- 改上限：`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`；要求 v2.1.217 及以上。
- 建议念法：「默认同时最多跑二十个子代理，超了会报错」

**6c　✓ 默认继承权限**
- 官方原话："Each inherits the parent conversation's permission rules" — https://code.claude.com/docs/en/sub-agents#built-in-subagents ；自定义子代理不设 `permissionMode` 时 "the subagent inherits the main conversation's permission mode"（#permission-modes）。
- 主对话在 bypassPermissions / acceptEdits / auto 时，子代理跟着同一模式，它自己设的不生效："the subagent runs in that same mode and Claude Code ignores the `permissionMode` you set"。
- 拒绝规则对两边一起管："The rule applies to the main conversation and to subagents"（说的是写进 `permissions.deny` 的 Bash 规则）。后台子代理要权限时，"Claude Code surfaces the prompt in your main session"。
- 顺带可知：交互式会话里子代理现在默认放后台跑，更新日志 2.1.198 "Subagents now run in the background by default"，你可以接着聊，结果以通知回来；子代理看不到你的对话历史；不给它的工具包括 AskUserQuestion、EnterPlanMode 等；插件里的子代理会忽略 `hooks`、`mcpServers`、`permissionMode` 三个字段。
- 建议念法：「子代理默认继承你的权限设置」

## 说法 7：自动委派与显式指定

> 待核对：Claude 会根据 description 自动委派，也可以显式要求使用某个子代理。

**7　✓ 文档支持**
- 官方原话（自动）："Claude uses each subagent's description to decide when to delegate tasks" — https://code.claude.com/docs/en/sub-agents（开头）；想让它更主动，description 里写类似 “use proactively”："include phrases like “use proactively” in your subagent's description field"（#understand-automatic-delegation）。
- 显式有三档（https://code.claude.com/docs/en/sub-agents#invoke-subagents-explicitly）：
  - 自然语言："name the subagent in your prompt; Claude decides whether to delegate"（不保证）
  - @ 点名："guarantees the subagent runs for one task"（输入 @ 从弹出列表里选；手敲写法是 `@agent-<名字>`）
  - 整场会话："the whole session runs as that subagent via the `--agent` flag"（`claude --agent 名字`，或 settings 里的 `agent`）
- 与课时文字的小差别：课时文字 02 写的是 `@agent code-quality-reviewer`（中间一个空格）；文档的写法是 `@agent-<名字>` 或从弹出列表里选，以文档为准。
- 建议念法：「描述写得清楚，Claude 会自己决定派谁」
