## 1. macOS / Linux / WSL：一条 curl 命令一键安装；也可用 Homebrew，但 Homebrew 安装不支持自动更新

**结论：△ curl 部分 ✓；“Homebrew 不支持自动更新”要改成“默认不自动更新”**

- **文档里的准确命令**（页面：https://code.claude.com/docs/en/overview 、https://code.claude.com/docs/en/quickstart 、https://code.claude.com/docs/en/setup#install-claude-code ，三页一致，标签名 “Native Install (Recommended)”）

  ```bash
  # macOS、Linux、WSL
  curl -fsSL https://claude.ai/install.sh | bash

  # Homebrew（稳定通道）
  brew install --cask claude-code
  # Homebrew（最新通道）
  brew install --cask claude-code@latest
  ```

- **官方原话**
  - "Native installations automatically update in the background" —— https://code.claude.com/docs/en/setup#update-claude-code
  - "Homebrew installations do not auto-update." —— 同页 Homebrew 标签
  - "typically about a week behind" —— 同页：`claude-code` 稳定通道通常比最新版晚约一周
  - "set CLAUDE_CODE_PACKAGE_MANAGER_AUTO_UPDATE to 1" —— 同页 Auto-updates 一节；环境变量说明 https://code.claude.com/docs/en/env-vars 写着 "Applies to Homebrew and WinGet installations."
  - "apt, dnf, or apk on Debian, Fedora, RHEL, and Alpine" —— 同页：Linux 还可用这三个包管理器装
- **有出入的地方**
  - 课时说 Homebrew “doesn't support auto-updates”。文档现在的说法是**默认不自动更新**，但设 `CLAUDE_CODE_PACKAGE_MANAGER_AUTO_UPDATE=1` 后，Claude Code 会在后台替你跑升级命令（Homebrew 和 WinGet 适用）。所以“不支持”太绝对，改成“默认不自动更新”。
  - 手动升级：`brew upgrade claude-code`（装的是最新通道则 `brew upgrade claude-code@latest`）。
  - WSL：要在 WSL 终端里装和启动，不是在 PowerShell / CMD 里（同页 Option 2: WSL）。
- **建议的中文念法**
  - 「Mac 和 Linux，一行 curl 就装好。」
  - 「Homebrew 装的，默认不自动更新。」

## 2. Windows：PowerShell 用 Invoke-RestMethod（irm），CMD 用 curl，也有 winget（同样不自动更新）

**结论：✓ 文档支持**（命令名在文档里写成缩写 irm）

- **文档里的准确命令**（同上三页）

  ```powershell
  # Windows PowerShell（提示符带 PS C:\）
  irm https://claude.ai/install.ps1 | iex

  # WinGet
  winget install Anthropic.ClaudeCode
  ```

  ```batch
  :: Windows CMD（提示符是 C:\，没有 PS）
  curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
  ```

- **官方原话**
  - "irm fetches the file and iex runs it." —— https://code.claude.com/docs/en/terminal-guide#windows
  - "WinGet installations do not auto-update." —— https://code.claude.com/docs/en/setup （WinGet 标签；升级用 `winget upgrade Anthropic.ClaudeCode`）
  - "You do not need to run as Administrator." —— https://code.claude.com/docs/en/setup#set-up-on-windows
  - "The token '&&' is not a valid statement separator" —— https://code.claude.com/docs/en/quickstart#step-1-install-claude-code ：看到它说明你在 PowerShell 里敲了 CMD 那条
  - "'irm' is not recognized as an internal or external command" —— 同处：看到它说明你在 CMD 里敲了 PowerShell 那条
- **要补的准确写法**
  - 课时写的 Invoke-RestMethod 是 `irm` 的全名；`irm` 是 PowerShell 内置别名，微软文档列出了它：https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/invoke-restmethod （“aliases for Invoke-RestMethod: irm”）。屏幕上展示命令时用 `irm`，念的时候说 irm 即可。
  - winget 的“不自动更新”也是默认行为，同第 1 条可用环境变量开启；开启后官方另有提醒：Windows 在 Claude Code 运行时会锁住可执行文件，后台升级可能失败，那时 Claude Code 会改为显示手动命令。
- **建议的中文念法**：「PowerShell 用 irm，CMD 用 curl。」（也有 winget 的话另起一句：「也可以用 winget，同样不自动更新。」）

## 5. 其他入口：VS Code 扩展、JetBrains 插件、Claude 桌面应用的 Code 标签、网页 claude.ai/code（连 GitHub 仓库）

**结论：△ VS Code / 桌面 / 网页 ✓；JetBrains 要先装 CLI，课时没说**

- **官方原话**
  - VS Code："VS Code 1.94.0 or later" —— https://code.claude.com/docs/en/vs-code#prerequisites ；打开方式："select Open in New Tab" —— https://code.claude.com/docs/en/overview （VS Code 标签：命令面板 Cmd/Ctrl+Shift+P，输入 “Claude Code”）
  - VS Code："The extension bundles its own copy of the CLI" —— https://code.claude.com/docs/en/vs-code#prerequisites
  - JetBrains："It does not bundle its own copy of the CLI, so install both pieces" —— https://code.claude.com/docs/en/jetbrains#installation
  - 桌面："launch Claude, sign in, and click the Code tab" —— https://code.claude.com/docs/en/overview （Desktop app 标签）；"A paid subscription is required." —— 同处
  - 桌面："you don't need to install Node.js or the CLI to use the Code tab" —— https://code.claude.com/docs/en/desktop-quickstart
  - 网页："Start coding at claude.ai/code" —— https://code.claude.com/docs/en/overview （Web 标签）
  - 网页："You'll need a GitHub repository to get started" —— https://code.claude.com/docs/en/web-quickstart
  - 本课视频简介（官方 Claude 频道）："in the terminal, VS Code, JetBrains, Claude Desktop, or on the web" —— https://www.youtube.com/watch?v=0kILa02vKuI （视频自己也把网页算作安装位置之一）
- **要补的准确写法**
  - **JetBrains**：先按 quickstart 装好 CLI，再从 JetBrains Marketplace 装 “Claude Code [Beta]” 插件并重启 IDE；插件是在 IDE 内置终端里跑 `claude` 并连上它（"The plugin runs the claude command in your IDE's integrated terminal"）。找不到 `claude` 会弹 “Cannot launch Claude Code”。支持 IntelliJ IDEA、PyCharm、Android Studio、WebStorm、PhpStorm、GoLand 等；快捷键 Cmd+Esc / Ctrl+Esc 呼出。课时只说“装插件、重启”，漏了“先装 CLI”。
  - **VS Code**：扩展自带一份 CLI，面板里直接用；想在终端里敲 `claude` 还得另装独立 CLI。扩展也能装进 Cursor 等 VS Code 衍生编辑器。
  - **桌面应用**：macOS、Windows（x64 / ARM64）；Linux 是 beta（Ubuntu / Debian 用 apt）；顶部有 Chat、Cowork、Code 三个标签，Claude Code 在 **Code** 标签里；需要付费订阅（Pro、Max、Team、Enterprise）。
  - **网页**：云端会话要连 GitHub 账号（或在终端用 `claude --cloud` 打包本地仓库）；"Cloud sessions are available on Pro, Max, and Team plans"（Enterprise 要高级席位）—— https://code.claude.com/docs/en/web-quickstart
  - 手机上的 Claude app（iOS / Android）也能开 / 看云端会话，可顺带提一句，课时没讲。
- **建议的中文念法**：「VS Code、JetBrains、桌面端、网页也行。」

## 6. 官方课说：终端功能最先上线；IDE 体验几乎一样；桌面端适合让它在后台跑；网页适合远程用 GitHub 仓库

**结论：△ “最先上线”文档没写；“桌面端后台跑”和文档定位不一致；“网页 + GitHub 仓库”✓**

- **官方原话**
  - "The CLI is the most complete surface for terminal-native work" —— https://code.claude.com/docs/en/platforms
  - "Some features are only available in the CLI." —— https://code.claude.com/docs/en/vs-code#vs-code-extension-vs-claude-code-cli
  - "trade some CLI-only features for visual review" —— https://code.claude.com/docs/en/platforms （桌面端和 IDE 扩展用一部分仅 CLI 的功能换来可视化审查和编辑器整合）
  - "use Desktop when you want to manage parallel sessions in one window" —— https://code.claude.com/docs/en/desktop#coming-from-the-cli
  - "continue even if you close the app or shut down your computer" —— https://code.claude.com/docs/en/desktop （这是云端会话）
  - "An autonomous background agent that works on tasks independently" —— https://code.claude.com/docs/en/desktop-quickstart （这是 Cowork 标签，不是 Code 标签）
  - "Repos you don't have locally" —— https://code.claude.com/docs/en/web-quickstart （云端会话的适用场景之一）
- **逐句判断**
  1. “终端功能最先上线”：**？** 文档没有“先上线”的说法，只有终端是“Full feature set / most complete”，IDE 和桌面端缺一部分仅 CLI 的功能（例如 VS Code 扩展的命令是子集，没有 `!` bash 快捷方式和 Tab 补全）。可以讲“终端功能最全”，别讲“最先上线”。
  2. “IDE 体验几乎一样”：基本对，但命令 / 技能是子集（上一条）。
  3. “桌面端适合让它在后台跑”：文档对桌面端 Code 标签的定位是“可视化看改动、多会话并排”（platforms 页：Visual review, parallel sessions）。桌面端确实有“后台任务”面板（看会话里的子代理和后台命令，https://code.claude.com/docs/en/desktop#watch-background-tasks ），也能开多个会话并行；但“关了应用 / 关了电脑也继续跑”的是**云端会话**（桌面端选 Cloud，或用网页）。本地会话断开就停（https://code.claude.com/docs/en/web-quickstart 对比表 “Keeps running if you disconnect”：云端 Yes，本地 No）。台本可以说“桌面端适合并排多开会话”，别说“关了也继续”。
  4. “网页适合远程用 GitHub 仓库”：✓。云端会话需要 GitHub（或 `claude --cloud` 打包本地仓库），适合没在本地的仓库、不需要频繁盯着的长任务。
- **建议的中文念法**
  - 「终端功能最全；网页能远程跑 GitHub 仓库。」
  - 「桌面端适合并排多开会话、看改动。」

## 7. Shift+Tab 循环切换权限模式；计划模式 = 只读工具分析代码库、研究实现、会提澄清问题、最后给出详细计划

**结论：△ Shift+Tab ✓（仅限终端）；“只读工具”要改；“澄清问题”“给计划”✓**

- **官方原话**
  - "Press Shift+Tab to cycle permission modes" —— https://code.claude.com/docs/en/quickstart#pro-tips-for-beginners
  - "From auto, the first press switches to default" —— https://code.claude.com/docs/en/permission-modes#switch-permission-modes
  - "Plan mode tells Claude to research and propose changes without making them." —— https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode
  - "runs shell commands to explore" —— 同一段；同一句后半是 "does not edit your source"
  - "Clarifying questions are especially common in plan mode" —— https://code.claude.com/docs/en/agent-sdk/user-input#handle-clarifying-questions
  - "Presents a plan for approval and exits plan mode" —— https://code.claude.com/docs/en/tools-reference （ExitPlanMode 一行）
  - "Enter plan mode by pressing Shift+Tab or prefixing a single prompt with /plan." —— permission-modes 同一节
- **要补的准确写法**
  - **Shift+Tab 只在终端有效**（JetBrains 因为在 IDE 终端里跑 CLI，所以也有效）；VS Code 要点输入框下方的**模式指示器**，桌面端用发送键旁的**模式选择器**；终端和 VS Code 里还都能用 `/plan` 进计划模式（桌面端没查到 `/plan`，别讲）。极少数 Windows 终端 Shift+Tab 不响应时，官方写了可用 Alt+M（条件：Node 或 Bun 运行时没开 VT 输入模式，https://code.claude.com/docs/en/interactive-mode#general-controls ）。
  - **按几下**：从 Manual 起步，按 2 下到 Plan；从 Auto 起步按 3 下（Auto → Manual → Accept edits → Plan）。v2.1.283 起终端新会话默认就是 Auto，所以别说“按两下”，以状态栏出现 `⏸ plan mode on` 为准。
  - **“只读工具”要改**：官方措辞是“研究并提出改动，但不动手”；它能读文件、也会跑探索性的 shell 命令，只是不改你的源码，改动要等你批准计划。官方模式表里 plan 的一栏是 “Reads, plus classifier-approved commands when auto mode is available”。
  - **澄清问题**：来自 AskUserQuestion 工具（给你多选题）；官方说计划模式里“尤其常见”，不是每次必问。
  - **给计划**：计划好了会让你选：“Yes, and use auto mode”“Yes, manually approve edits”“No, keep planning”（https://code.claude.com/docs/en/permission-modes#review-and-approve-a-plan ）。
- **建议的中文念法**：「Shift+Tab 切计划模式：先研究，问问题，给计划。」

## 9. 系统要求：Windows 原生安装是否需要 Git for Windows、是否还需要 Node.js 等

**结论：✓ 文档有明确答案：Git for Windows 是可选的，Node.js 不需要**

  - Node.js：系统要求页的“额外依赖”里只列了 ripgrep（"usually included with Claude Code"），没有 Node.js；只有 npm 安装方式明说要 Node.js 22+。如果别处资料说“必须先装 Node.js”，那只适用于 npm 这条路。
- **建议的中文念法**
  - 「Windows 不用装 Node.js。」
  - 「Git for Windows 可装可不装。」

## 可以多讲一句的具体细节（≤ 3 条，都有出处）

1. **验证装好了**：装完开一个新的终端窗口，运行 `claude --version`，能打出版本号就成功；还有 `claude doctor` 做安装和设置的体检。出处：https://code.claude.com/docs/en/quickstart#step-1-install-claude-code 和 https://code.claude.com/docs/en/setup#verify-your-installation 。
   念法：「装完开个新终端，运行 claude --version。」
2. **分清自己在哪个终端**：提示符带 `PS C:\` 的是 PowerShell，不带 PS 的是 CMD；弄错了会报 “&&” 或 “irm” 那两条错。出处：https://code.claude.com/docs/en/quickstart#step-1-install-claude-code 。
   念法：「带 PS 的是 PowerShell，不带的是 CMD。」
3. **计划出来以后还能改**：按 Ctrl+G 在文本编辑器里直接改计划，再选三种批准方式之一。出处：https://code.claude.com/docs/en/permission-modes#review-and-approve-a-plan （"Press Ctrl+G to open the proposed plan in your default text editor"）。
   念法：「计划出来后，按 Ctrl+G 能先改，再批准。」

## 不要讲的（文档没依据 / 已过时 / 有争议）

- 「Windows 必须先装 Git for Windows / 必须装 WSL / 必须装 Node.js」——都不是必需。Git for Windows 是可选（官方建议装）。
- 「Homebrew、WinGet 装的永远不会自动更新」——默认不自动，可用 `CLAUDE_CODE_PACKAGE_MANAGER_AUTO_UPDATE=1` 开启；“不支持”这个词别用。
- 「首次启动一定会让你选主题」——文档没写，别当必经步骤；想换主题用 `/theme`。
- 「登录只有 Pro / Max / Enterprise / API」——漏了 Team、Console、云平台、公司网关；免费 claude.ai 账号不含 Claude Code。
- 「JetBrains 装个插件就行」——要先装 CLI。
- 「桌面端能让它在后台一直跑，关了也继续」——只有云端会话关了应用还继续；本地会话断开就停。
- 「终端功能最先上线」——文档没写“先上线”，只写终端功能最全。
- 「按两下 Shift+Tab 就进计划模式」——取决于起始模式；v2.1.283 起默认 Auto，要按三下，以状态栏为准。
- 「计划模式只用只读工具」——官方说它也会跑探索性命令，只是不改源码。
- 「Shift+Tab 在所有界面都能切模式」——只有终端（含 JetBrains）；VS Code 点模式指示器，桌面端点模式选择器。
- 「示例提示是官方文档里的」——只在课程里；文档里的计划模式例子是 Google OAuth。
