## 1. 与 Claude.ai 的区别：能直接访问文件、终端、整个代码库，不用来回复制粘贴

**结论：✓ 文档支持**（“不用来回复制粘贴”这句只在课时文字里，文档换了一种说法）

- **官方原话**
  - "chat-based assistants that only respond with text you must apply yourself" —— https://code.claude.com/docs/en/glossary （Agentic coding 词条）
  - "tools that let it act, not just advise" —— 同一词条
  - "If you can do it from the command line, Claude can too" —— https://code.claude.com/docs/en/how-claude-code-works#what-claude-can-access
  - "it goes in and does the work itself" —— 课时文字 `claude-code-101__01-what-is-claude-code.txt`
  - "reads your codebase, edits files, and runs commands" —— 官方 Claude 频道视频简介 https://www.youtube.com/watch?v=fl1DSmwQKKY
- **要补的准确写法**
  - 访问范围：运行 `claude` 的目录及子目录，目录外的文件要经你许可（见第 2 期第 4 条）。
  - “能直接动文件和终端”不等于“不问你”：默认还要按权限模式征求同意（见第 7 条）。
  - “不用复制粘贴”可以讲，但出处是官方课程，不是文档原话。
- **建议的中文念法**：「它不是聊天框，能直接读你的文件、跑命令、改代码。」

## 3. 能做的四类事：读懂代码库、跨文件修改、跑终端命令（构建 / 测试 / 装包）、搜网页查文档

**结论：✓ 文档支持**

- **官方原话**（https://code.claude.com/docs/en/how-claude-code-works#tools 的内置工具表）
  - File operations："Read files, edit code, create new files, rename and reorganize"
  - Search："Find files by pattern, search content with regex, explore codebases"
  - Execution："Run shell commands, start servers, run tests, use git"
  - Web："Search the web, fetch documentation, look up error messages"
  - "makes coordinated edits across them" —— 同页 What Claude can access（跨文件改）
  - "build tools, git, package managers, system utilities, scripts" —— 同页（装包对应 package managers）
- **要补的准确写法**
  - 官方把内置工具分成**五类**：文件操作、搜索、执行、网络、代码智能；代码智能（跳转定义、查引用）要另装 code intelligence 插件。课时的“四类”是把前四类换了说法，没有矛盾。
  - 文档没有单独写“装包”，写的是它能用包管理器等任何命令行工具。
- **建议的中文念法**：「读代码库、跨文件改、跑命令、搜网页，它都能自己来。」

## 4. 代理循环三步：收集上下文 → 采取行动 → 验证结果；没达成就回循环再试；全程可补充上下文、打断、引导

**结论：✓ 文档支持**

- **官方原话**（https://code.claude.com/docs/en/how-claude-code-works#the-agentic-loop）
  - "gather context, take action, and verify results"
  - "These phases blend together."
  - "A bug fix cycles through all three phases repeatedly."
  - "You can interrupt at any point to steer Claude in a different direction"
  - "Press Esc to stop Claude immediately." —— https://code.claude.com/docs/en/how-claude-code-works#interrupt-and-steer
  - "Type a correction and press Enter without stopping Claude." —— 同一段
- **要补的准确写法**
  - 三步不是死板的流水线：会混在一起；只问问题可能只做第一步；修 bug 会反复转圈。
  - 打断有两种：按 Esc 立刻停；或直接输入修正再回车，不用停（消息排队，Claude 在当前这批工具调用结束后读到）。
- **建议的中文念法**：「找线索、动手、验结果，没做好就再转一圈。」

## 5. 上下文窗口决定能存多少对话 / 文件 / 命令输出；到上限时自动压缩（compact）

**结论：✓ 文档支持**

- **官方原话**

  - "Claude compacts automatically" —— 同一段
  - "It clears older tool outputs first, then summarizes the conversation if needed." —— https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up

- **建议的中文念法**：「上下文窗口快满了，会自动压缩，早期细节可能丢。」

## 7. 权限模式（课时列了 4 个）：核对官方当前完整列表、名称、数量、含义，以及 Shift+Tab 循环哪几个

**结论：△ 部分支持，名称和数量要改**

- **官方原话**
  - "Available modes are default, acceptEdits, plan, auto, dontAsk, and bypassPermissions." —— https://code.claude.com/docs/en/glossary （Permission mode 词条）
  - "labeled Manual in the CLI" —— 同一词条（`default` 在界面里叫 Manual）
  - "From auto, the first press switches to default" —— https://code.claude.com/docs/en/permission-modes#switch-permission-modes
  - "when available, bypassPermissions and then auto" —— https://code.claude.com/docs/en/interactive-mode#general-controls （Shift+Tab 一行）
  - "never appears in the cycle" —— 指 dontAsk，https://code.claude.com/docs/en/permission-modes#switch-permission-modes
  - "auto mode is the built-in starting permission mode" —— https://code.claude.com/docs/en/permission-modes#which-mode-a-session-starts-in
  - "Auto mode reduces permission prompts but does not guarantee safety." —— https://code.claude.com/docs/en/permission-modes#eliminate-prompts-with-auto-mode
- **官方完整列表：共 6 个**

  | 状态栏显示 | 配置值 | 不用问就能做的事（官方表） |
  | --- | --- | --- |
  | Manual（`⏸ manual mode on`） | `default` | 只读 |
  | Accept edits（`⏵⏵ accept edits on`） | `acceptEdits` | 读、改文件、常见文件系统命令（mkdir、touch、rm、rmdir、mv、cp、sed） |
  | Plan（`⏸ plan mode on`） | `plan` | 读；自动模式可用时另加分类器放行的命令（计划模式本身只研究、提计划，不改源码） |
  | Auto（`⏵⏵ auto mode on`） | `auto` | 一切，但后台有分类器审查 |
  | Don't ask（`⏵⏵ don't ask on`） | `dontAsk` | 只读 + 预先批准的工具，其余一律拒绝；用 `--permission-mode dontAsk` 设置，不在 Shift+Tab 里 |
  | Bypass permissions（`⏵⏵ bypass permissions on`） | `bypassPermissions` | 一切；只用于隔离容器 / 虚拟机；启动时带特定参数才会出现在轮换里 |

- **Shift+Tab 循环哪几个**：日常是 4 个——Manual → Accept edits → Plan → Auto → 回到 Manual（Auto 在“可用时”才出现；从 Auto 按第一下先回到 Manual）。dontAsk 永远不在里面；bypassPermissions 只有启动时带了对应参数才会插在 Plan 和 Auto 之间。
- **与课时文字的出入**
  1. “Auto-accept”是旧叫法，官方现名 **Accept edits**（VS Code 里叫 Edit automatically；桌面端旧版叫 Auto accept edits，见 https://code.claude.com/docs/en/desktop#choose-a-permission-mode ）。
  2. 课时说 Auto-accept “commands still require approval”不全对：`mkdir`、`mv`、`cp` 等常见文件系统命令也不用问，其余命令才要问（https://code.claude.com/docs/en/permission-modes#auto-approve-file-edits-with-acceptedits-mode ）。
  3. Auto 的分类器，官方写的是拦 "scope escalation, unknown infrastructure, and hostile-content-driven actions"（越出你要求的范围、陌生的基础设施、被恶意内容牵着走），出处 https://code.claude.com/docs/en/best-practices#run-autonomously-with-auto-mode ；课时的 “irreversible, destructive” 对应默认拦截清单里的具体项（强制推送、删掉会话前就存在的文件等，https://code.claude.com/docs/en/permission-modes#what-the-classifier-blocks-by-default ）。可以讲大意，**别说成“绝对安全”**。
  4. “新会话用哪个模式取决于计划和设置”没错，但要补：Claude Code v2.1.283 起，终端和 VS Code 的新会话**默认就是 Auto**；更早的版本只有 Pro / Max / Team 如此；装完后的第一次会话还可能不同（同页 Which mode a session starts in）。
  5. 网页端 / 云端会话只有 Accept edits、Plan、Auto（没有 Manual；Auto 要组织允许、模型支持才出现，https://code.claude.com/docs/en/permission-modes#switch-permission-modes 的 Web and mobile 标签）。
- **建议的中文念法**：「Shift+Tab 轮换：手动、接受编辑、计划、自动。」

## 可以多讲一句的具体细节（≤ 3 条，都有出处）

1. **修失败的测试，它大概这样转**：跑测试看哪里挂 → 读报错 → 搜相关源文件 → 读文件 → 改 → 再跑测试验证。出处：https://code.claude.com/docs/en/how-claude-code-works#tools （“When you say 'fix the failing tests'…”）。
   念法：「比如让它修测试：先跑，读报错，找文件，改，再跑一遍。」
2. **按两下 Esc 能回退文件改动**：Claude 改文件前先拍快照；但只管文件，远端的数据库、接口、部署撤不回。出处：https://code.claude.com/docs/en/how-claude-code-works#undo-changes-with-checkpoints （"File edits are reversible." 以及 “Actions that affect remote systems … can't be checkpointed.”）。
   念法：「改错了？按两下 Esc，文件能回到改之前。」
3. **它到底看得到什么**：当前目录和子目录的文件、你的终端、git 状态（当前分支、未提交改动、最近提交）、CLAUDE.md。出处：https://code.claude.com/docs/en/how-claude-code-works#what-claude-can-access 。
   念法：「它能看到目录、终端、git 状态和 CLAUDE.md。」
