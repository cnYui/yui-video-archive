## 逐条核对

### 3-1　工作流四步　✓

- **说法**：Explore（探索）→ Plan（计划）→ Code（编码）→ Commit（提交）。核对官方文档有没有这个四步说法及原文。
- **官方原话**：
  - "The recommended workflow has four phases" ；小节标题 "Explore first, then plan, then code" ；四个步骤标题依次是 Explore / Plan / Implement / Commit。出处：[best-practices](https://code.claude.com/docs/en/best-practices#explore-first-then-plan-then-code)
  - Commit 一步的提示词："commit with a descriptive message and open a PR"（同页）。
  - 课时文字 05 的标题与小结："Explore, Plan, Code, and Commit"。
- **准确写法**：文档第三步叫 **Implement**，课程叫 **Code**。文档第三步原文："Switch out of plan mode by approving the plan or pressing Shift+Tab"，然后 "let Claude code, verifying against its plan"。前两步在文档里都是在计划模式里做的，和课程“最快的做法是用计划模式一次做完前两步”一致。画面上若出现英文，写课程原词 Code 没问题；口播念“编码”两边都兼容。
- **念法**：「官方推荐四步：探索、计划、编码、提交」（18 字）

### 3-2a　计划模式下 Claude 不能编辑文件　△

- **官方原话**：
  - "research and propose changes without making them" ；"but does not edit your source" 。出处：[permission-modes](https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode)
  - "Claude reads files, runs shell commands to explore, and writes a plan" （同页）
  - 术语表："researches and proposes changes without editing your source files"。出处：[glossary](https://code.claude.com/docs/en/glossary)
- **准确写法**：说“不改你的源码”比“不能编辑文件”准。它会把计划本身写成文件（[context-window](https://code.claude.com/docs/en/context-window#what-survives-compaction) 表里 “The plan Claude wrote in plan mode” 一行，压缩后 "Re-injected from disk"），也会跑探索用的 shell 命令（auto 模式可用时由分类器审，否则非只读命令要你批准）。例外：交互终端里开了 bypass permissions 时，计划模式的拦截不强制，文档原话 "Claude is still instructed to plan without editing"（permission-modes 页，bypass 小节）。
- **念法**：「计划模式下，Claude 只读不改你的源码」（21 字）

### 3-2b　只读文件、搜网页来收集信息　？

- **官方原话**：
  - 术语表："It can read, search, and run exploration commands" （没说是不是网页）。出处：[glossary](https://code.claude.com/docs/en/glossary)
  - 工具页：WebSearch 的描述是 "Performs web searches" ，手动模式下 Permission required 为 Yes。出处：[tools-reference](https://code.claude.com/docs/en/tools-reference)
  - 课时文字 05 的示例："run some web searches"。
- **准确写法**：文档任何一页都没写“计划模式会搜网页”。只读文件 ✓；网页搜索只出现在课程示例里，没有官方文档背书。
- **念法**：「它先把相关文件读一遍」（10 字）。“搜网页”这半句不要讲。

### 3-2c　用 Shift+Tab 进入计划模式　△

- **官方原话**：
  - "Enter plan mode by pressing Shift+Tab or prefixing a single prompt with /plan" 。出处：[permission-modes](https://code.claude.com/docs/en/permission-modes#analyze-before-you-edit-with-plan-mode)
  - "Shift+Tab until the status bar shows ⏸ plan mode on" 。出处：[best-practices](https://code.claude.com/docs/en/best-practices#explore-first-then-plan-then-code)
  - "From auto, the first press switches to default" 。出处：[permission-modes](https://code.claude.com/docs/en/permission-modes#switch-permission-modes)
- **准确写法**：Shift+Tab 是**循环键**，顺序 default（状态栏叫 Manual）→ acceptEdits → plan（之后按情况还有 bypass、auto）。v2.1.283 起 auto 是交互终端的内置起始模式，从 auto 出发要按**三下**才到 plan，所以别说“按一下”。直接进的办法：输入 `/plan`（可带任务，例如 `/plan fix the auth bug`），或启动时 `claude --permission-mode plan`（原话 "start the session with claude --permission-mode plan"）。状态栏标志是 `⏸ plan mode on`。再按 Shift+Tab 退出（不批准）。Windows 上若 Node / Bun 没开 VT 输入模式，键位是 "Alt+M on Windows when the Node or Bun runtime doesn't enable VT input mode"（[interactive-mode](https://code.claude.com/docs/en/interactive-mode)）。
- **念法**：「Shift+Tab 多按几下，切到计划模式」（21 字）；「输入 /plan 也能直接进计划模式」（18 字）

### 3-3　审阅计划、改特定部分、最好的纠偏时机　✓

- **官方原话**：
  - "No, keep planning" ；"stay in plan mode and tell Claude what to change" 。出处：[permission-modes](https://code.claude.com/docs/en/permission-modes#review-and-approve-a-plan)
  - "open the plan in your text editor for direct editing" （按 Ctrl+G）。出处：[best-practices](https://code.claude.com/docs/en/best-practices#explore-first-then-plan-then-code)
  - "preventing expensive re-work when the initial direction is wrong" 。出处：[costs](https://code.claude.com/docs/en/costs)（Work efficiently on complex tasks）
  - "Correct Claude as soon as you notice it going off track" 。出处：best-practices（Course-correct early and often）
  - 课时文字 05："ask it to revise specific areas" ；"best place to course-correct" （整句只在课程里）
- **准确写法**：官方没有“最好的纠偏时机”这句，但 costs 页的 “preventing expensive re-work” 是同一个意思。批准计划时现在的选项是 "Yes, and use auto mode" / "Yes, manually approve edits" / "No, keep planning"（auto 不可用时第一项显示 "Yes, auto-accept edits"）。
- **念法**：「计划阶段纠偏最划算：还没写一行代码」（17 字）；「不满意？告诉它具体改哪一块」（13 字）

### 3-4　不进计划模式也能只运行 Explore 子代理　✓

- **官方原话**：
  - "A fast, read-only agent optimized for searching and analyzing codebases" ；"Claude delegates to Explore when it needs to search or understand a codebase" 。出处：[sub-agents](https://code.claude.com/docs/en/sub-agents#built-in-subagents)
  - "give me an overview of this codebase" ；"use a subagent to investigate how our auth system handles token refresh" 。出处：[common-workflows](https://code.claude.com/docs/en/common-workflows)
  - 课时文字 05："run the explore subagent without being in plan mode"
- **准确写法**：内置子代理有 Explore、Plan、general-purpose（另有 statusline-setup、claude-code-guide）。计划模式里 Claude 派的是 **Plan** 子代理（"A research agent used during plan mode"），平时探索派 **Explore**；两个都只读（"Write and Edit are denied"）。文档没有专门“运行 Explore”的命令，做法是直接问概览，或点名 “use a subagent to investigate …”，由 Claude 派 Explore。模型这一项：文档现在写 "the main conversation's model"（主会话跑 Fable 时按订阅 / 网关走 opus 别名），口播别报具体模型名。
- **念法**：「Explore 子代理只读，帮你先摸清代码库」（22 字）

### 3-5a　编码建议一：定义成功标准　✓

- **官方原话**：
  - "Give Claude a check it can run: tests, a build, a screenshot to compare" ；策略名 "Provide verification criteria" ；"Have Claude show evidence rather than asserting success" 。出处：[best-practices](https://code.claude.com/docs/en/best-practices#give-claude-a-way-to-verify-its-work)
  - `/goal`："sets a completion condition" 。出处：[goal](https://code.claude.com/docs/en/goal)
- **准确写法**：官方词是 verification criteria / “a check it can run”，课程叫 success criteria，是同一件事。官方还给了几种把“标准”变硬的办法：写在提示里；`/goal <条件>` 让独立评估器每轮复核；Stop hook 当确定性门槛；让验证子代理做第二意见（best-practices 同节）。
- **念法**：「写代码前先定好成功标准，让它能自己验证」（19 字）

### 3-5b　编码建议二：装 Claude in Chrome 扩展测 UI　✓

- **官方原话**：
  - "Claude opens new tabs for browser tasks" ；"test form validation, check for visual regressions, or verify user flows" 。出处：[chrome](https://code.claude.com/docs/en/chrome)
  - 前提："A direct Anthropic plan (Pro, Max, Team, or Enterprise)" ；扩展 "version 1.0.36 or later" 。
- **准确写法**：官方名 Claude in Chrome（Chrome 应用商店扩展）；启动 `claude --chrome`，或会话里 `/chrome`。限制要讲清：只支持直连 Anthropic 的 Pro / Max / Team / Enterprise；用 API key 或 setup-token 登录时 "Claude Code keeps Chrome integration off, even when you pass --chrome" ；Bedrock、Vertex、Foundry 这类第三方通道不可用；WSL 不支持（"Chrome integration isn't supported in Windows Subsystem for Linux (WSL)"）。设成“默认启用”会多占上下文（"increases context usage since the browser tools and their instructions are always loaded"）。更新日志 Week 27：Claude in Chrome 对所有直连计划正式可用。
- **念法**：「装 Claude in Chrome，让它自己测界面」（26 字）

### 3-5c　编码建议三：给测试套件让它持续验证　✓

- **官方原话**：
  - "a test suite, a build exit code, a linter" （best-practices 列的“检查”例子）；"iterates until the check passes" 。出处：[best-practices](https://code.claude.com/docs/en/best-practices#give-claude-a-way-to-verify-its-work)
  - "Claude can generate tests that follow your project's existing patterns and conventions" 。出处：[common-workflows](https://code.claude.com/docs/en/common-workflows)（Work with tests）
- **准确写法**：无出入。
- **念法**：「给它一套测试，让它反复跑、反复验证」（17 字）

### 3-5d　保证测试可靠、避免假阳性　△

- **官方原话**：
  - 课时文字 05："reliable source of truth to avoid false positives"
  - 文档里最接近的是 best-practices 的 “The trust-then-verify gap”，修法："If you can't verify it, don't ship it" 。出处：[best-practices](https://code.claude.com/docs/en/best-practices#avoid-common-failure-patterns)
  - 课时文字 07 给了具体检查项："skipped, deleted, or loosened until they passed"
- **准确写法**：文档没有“测试要可靠 / 避免假阳性”这句。文档里出现 false positives 的地方（[code-review](https://code.claude.com/docs/en/code-review)）说的是审查产品过滤误报，不是测试，别混。这一条的依据只有课时文字。
- **念法**：「测试本身要靠谱，别让它改弱测试蒙混过关」（19 字）

### 3-6a　提交前跑子代理审查（新视角、无偏见）　✓

- **官方原话**：
  - "have a subagent review the diff in a fresh context" ；"Claude won't be biased toward code it just wrote" ；"not the reasoning that produced the change" 。出处：[best-practices](https://code.claude.com/docs/en/best-practices#add-an-adversarial-review-step)
  - "/code-review checks the current diff for correctness bugs" 。出处：[commands](https://code.claude.com/docs/en/commands)（Before you ship）
  - "The review runs as a background subagent with its own context window" 。出处：[code-review](https://code.claude.com/docs/en/code-review#review-a-diff-locally)
  - 课时文字 05："it doesn't carry the bias the main agent might have from the session"
- **准确写法**：官方内置的审查就是 `/code-review`（别名 `/review`）：后台子代理、独立上下文，结果回到对话；默认只报告，加 `--fix` 才改；`low` / `medium` 只报最有把握的，`high` 到 `max` 覆盖更广、可能带上不太确定的发现。“code-reviewer”**不是内置子代理**，是 [sub-agents](https://code.claude.com/docs/en/sub-agents) 页的示例自定义子代理名（description: "Reviews code for quality and best practices"）。也可以直接大白话让 Claude 发起审查。别和团队版 Code Review（GitHub PR 上的托管审查，管理员开启、另计费）混。官方还提醒 "will usually report some, even when the work is sound" ，"Chasing every finding leads to over-engineering" ，所以每条都改不对，可以拿来泼冷水。课时文字 07 补充：这种审查 "counts against your usage like any other task"。
- **念法**：「提交前，先让子代理审一遍代码」（14 字）；「它只看改动本身，不知道你当时怎么想的」（18 字）；「审查可以用内置的 /code-review」（21 字）

### 3-6b　让 Claude 按你的风格生成提交信息　△

- **官方原话**：
  - "commit with a descriptive message and open a PR" 。出处：[best-practices](https://code.claude.com/docs/en/best-practices#explore-first-then-plan-then-code)
  - "commit my changes with a descriptive message" 。出处：[quickstart](https://code.claude.com/docs/en/quickstart)
  - "Repository etiquette (branch naming, PR conventions)" （best-practices 里 CLAUDE.md 该写的内容）；"Prefix commit subjects with the package name" （[large-codebases](https://code.claude.com/docs/en/large-codebases) 里写在根 CLAUDE.md 的提交约定示例）
  - 课时文字 05："generate a commit message in your style"
- **准确写法**：文档写的是 descriptive message，没有“自动学会你的风格”这个说法。想要自己的格式，文档的办法是把提交约定写进 CLAUDE.md。另外 Claude Code 内置的提交指令默认会让提交信息末尾带一行 Co-Authored-By 署名，可以用 `attribution.commit` 改成自己的文字或置空去掉（出处：[settings-reference](https://code.claude.com/docs/en/settings-reference) 的 attribution 条目；[modifying-system-prompts](https://code.claude.com/docs/en/agent-sdk/modifying-system-prompts) 页的 "Co-Authored-By" 说明）。
- **念法**：「提交信息的格式，写进 CLAUDE.md 它就照做」（25 字）

### 3-7　总踩同一个坑 → 存进 CLAUDE.md　✓

- **官方原话**：
  - "Claude makes the same mistake a second time" （memory 页“何时往 CLAUDE.md 加内容”的第一条）；"add this to CLAUDE.md" ；对比 "Claude saves it to auto memory" 。出处：[memory](https://code.claude.com/docs/en/memory)
  - 课时文字 05："save the solution to its CLAUDE.md file"
- **准确写法**：措辞要明确。只说“记住 X”，Claude 默认存进 **auto memory**（它自己的笔记）；要进 CLAUDE.md 得明说 “add this to CLAUDE.md”，或用 `/memory` 自己改。CLAUDE.md 是上下文不是强制配置（"as context, not enforced configuration"），非遵守不可的事用 hook。
- **念法**：「老踩同一个坑？让它写进 CLAUDE.md」（21 字）；「光说‘记住’，它会存到自动记忆里」（16 字）

- **准确写法**：无出入。
- **念法**：「官方提醒：直接上手写，可能解决了错的问题」（20 字）；「改动一句话说得清，就别计划了」（14 字）

## 可以多讲一句的具体细节

1. **按 Ctrl+G，直接在编辑器里改计划。** 出处：[best-practices](https://code.claude.com/docs/en/best-practices#explore-first-then-plan-then-code) "open the plan in your text editor for direct editing"；批准时的三个选项见 [permission-modes](https://code.claude.com/docs/en/permission-modes#review-and-approve-a-plan)。
   念法：「按 Ctrl+G，能直接在编辑器里改计划」（20 字）
2. **计划是写成文件的，长对话压缩后会重新注入，不会丢。** 出处：[context-window](https://code.claude.com/docs/en/context-window#what-survives-compaction) 表 "Re-injected from disk" ；[large-codebases](https://code.claude.com/docs/en/large-codebases) "re-injects the plan file after each compaction" 。（可以顺手引到第 4 期）
   念法：「计划写成了文件，长对话压缩后也还在」（17 字）
3. **提交前看三样，再加一个 /diff。** 出处：课时文字 07 "Changes you didn't ask for" / "Tests that got weaker" / "New packages and hard-coded values" ；命令出处 [commands](https://code.claude.com/docs/en/commands)：/diff "Review the changes in your working tree" 。
   念法：「提交前看三样：没要求的改动、变弱的测试、硬编码」（23 字）

## 不要讲的

1. “计划模式会上网搜资料”：文档没写（3-2b）。
2. “按一下 Shift+Tab 就进计划模式”：是循环键，auto 起步要按三下（3-2c）。要么说多按几下，要么说 /plan。
3. “计划模式绝对不会改文件”：开了 bypass permissions 的交互终端里，拦截不强制，只是被要求别改（3-2a）。
4. 报 Explore 子代理具体用哪个模型：文档现在写的是跟随主会话模型，网上的旧说法不可靠（3-4）。
5. “Claude 会自动学会你的提交风格”：文档没写，要靠 CLAUDE.md（3-6b）。
6. “code-reviewer 是内置子代理”：不是，内置的是 /code-review；code-reviewer 只是文档示例（3-6a）。
7. 把 /code-review 和 GitHub 上的团队版 Code Review 说成一个东西：后者要管理员开启、另外计费（[code-review](https://code.claude.com/docs/en/code-review) 页的 Setup 和 Pricing 小节）。
8. “所有任务都先计划”：官方说小改动直接做，一句话说得清的 diff 就跳过计划（3-8）。
9. “装上 Claude in Chrome 谁都能用”：API key 登录、第三方通道、WSL 都不行（3-5b）。观众里有人用中转 / API key，要点一句前提。
10. “测试通过就等于没问题”：官方恰恰提醒过 trust-then-verify gap，以及测试被削弱的风险（3-5d）。
