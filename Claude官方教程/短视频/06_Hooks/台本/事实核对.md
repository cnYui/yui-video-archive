## 逐条核对

### 1. hook = 挂在事件上的确定性代码，总会运行；对比：CLAUDE.md 里写“每次编辑后跑 Prettier”，Claude 多数时候会做，但有时不会

**结论：✓**

官方原话
- "certain actions always happen rather than relying on the LLM" — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)（原句前面是 deterministic control）
- "write it as a hook instead" — [memory](https://code.claude.com/docs/en/memory)（Troubleshoot：要在某个固定时点执行的事，比如“每次提交前”“每次编辑后”，就写成 hook）
- "apply regardless of what Claude decides to do" — [memory](https://code.claude.com/docs/en/memory)
- "Always fires on its event; the trigger is guaranteed" — [features-overview](https://code.claude.com/docs/en/features-overview)（Hook vs Skill 表）
- "hooks are deterministic and guarantee the action happens" — [best-practices](https://code.claude.com/docs/en/best-practices)（原句对比的是 CLAUDE.md 指令是 advisory）
- 课程原文（`claude-code-101__12`）："Most of the time it will. But sometimes it won't."

补充与小心之处
- “确定性”说的是触发：事件发生、matcher 命中，就一定运行。但 prompt 型和 agent 型 hook 是让模型做判断的（原文："decisions that require judgment rather than deterministic rules"），所以“hook = 代码”只对命令型成立。
- “总会运行”的前提是配置对。脚本路径写错或没有执行权限，shell 返回 127，属于非阻塞错误，动作照常进行，守卫等于悄悄失效——文档原话："a mistyped path in settings.json leaves the gate silently disabled"（[hooks 参考页](https://code.claude.com/docs/en/hooks)“Other exit codes”一节）。matcher 还区分大小写（"Matchers are case-sensitive"，hooks-guide 排错一节）。
- “Claude 多数时候会做”是课程的说法；文档对 CLAUDE.md 的措辞是“没有严格遵守的保证”。
- 文档在 memory 页里直接拿“每次编辑后”当例子说明该改用 hook，和视频这个对比完全一致。

建议中文念法
- hook 是挂在事件上的代码，每次都会运行。
- 写在 CLAUDE.md 里，不保证次次照做。
- 格式化放 hook，次次都跑，不靠 Claude 记得。

### 2. 常用事件：PreToolUse、PostToolUse、UserPromptSubmit、Stop、Notification、SubagentStop、PreCompact / PostCompact、InstructionsLoaded、SessionStart；实战课说“大约 30 个事件”

**结论：△**（名单全对；总数文档没写，要换说法）

- PreToolUse："Before a tool call executes. Can block it"
- PostToolUse："After a tool call succeeds"（失败的是另一个事件 PostToolUseFailure）
- UserPromptSubmit："When a prompt is submitted, before Claude processes it"

- 课程原文（`claude-code-in-action__05`）："Claude Code fires around 30 hook events"

事件总数
- 文档没有任何一句写出总数。事件表我逐行数过：hooks-guide 原文表 33 行，hooks 参考页的表一致。“大约 30 个”不算错，但台本别写“30 个”或“40 个”，念“三十多个”最稳（以后文档加事件也不会过时）。

建议中文念法

- PreToolUse 在工具调用前，能拦下来。
- PostToolUse 在调用成功后，常用来格式化。
- Stop 在 Claude 想收工时，能让它接着干。

### 3. PreToolUse：stdin 收到 JSON（工具名和输入）；退出码 0 = 放行；2 = 阻止，stderr 反馈给 Claude；其他 = 非阻塞错误，只显示给用户

**结论：△**（“2”和“其他”都对；“0 = 放行”措辞要改）

官方原话
- "Claude Code passes event-specific data as JSON to your script's stdin." — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)（PreToolUse 收到 `hook_event_name`、`tool_name`、`tool_input`）
- "Exit 2 means a blocking error." — [hooks 参考页](https://code.claude.com/docs/en/hooks)（Exit code 2）
- "passes the script's Blocked: message to Claude as feedback" — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)（PreToolUse 退出 2 的示例）
- "Any other exit code doesn't block on its own for most hook events." — [hooks 参考页](https://code.claude.com/docs/en/hooks)
- "this doesn't approve the tool call" — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)（原句：对 PreToolUse，退出 0 并不批准这次调用）
- "the normal permission flow still applies" — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)
- 课程原文（`claude-code-in-action__05`）："like an error, but it does not block"（讲退出码 1）

准确写法
- 输入：对，stdin 上是 JSON，PreToolUse 的专有字段是 `tool_name`（工具名）和 `tool_input`（参数；Bash 的话里面有 `command`）。
- 退出码 2：阻止这次工具调用；你写在 stderr 里的原因会反馈给 Claude，它据此调整。对。注意：退出 2 一旦触发，连 JSON 里的 `permissionDecision: "allow"` 都推翻不了。
- 其他退出码（包括 1）：对大多数事件不阻止，动作照常进行；记录里出现一条 hook error 提示，带 stderr 的第一行（前缀 "Failed with non-blocking status code:"），完整 stderr 要开 debug 日志才看得到。所以“只显示给用户”基本准确。例外：如果脚本在 stdout 打印了合法 JSON，就以 JSON 为准，退出码被忽略。
- 退出码 0：文档说的是“你的 hook 没有异议”，对 PreToolUse 不等于批准，照常走权限流程（该弹确认还是弹确认）。要明确批准 / 拒绝 / 询问，要输出 JSON：`hookSpecificOutput.permissionDecision`，取值 `allow`、`deny`、`ask`（还有只在 `-p` 非交互模式用的 `defer`）。所以别说“0 = 放行”，说“0 = 没意见”。
- 一个 hook 里二选一：“Choose one approach per hook.”（要么退出 2 加 stderr，要么退出 0 加 JSON）。
- 退出码 2 在各事件上的效果不一样（hooks 参考页分事件表）：PreToolUse 拦工具调用；UserPromptSubmit 拦提示；Stop 拦 Claude 停下；PreCompact 拦压缩；SubagentStop 拦子代理停下。PostToolUse 拦不了（工具已经跑完，只是把 stderr 给 Claude 看）；SessionStart 和 PostCompact 只给用户显示 stderr；Notification 的退出码和 stderr 被忽略。

建议中文念法
- 退出码 2：拦下操作，原因反馈给 Claude。
- 退出码 0 是没意见，不等于自动批准。
- 其他退出码不拦，只显示一条报错。

### 4a. 配置在 settings.json 的 hooks 里：选事件、可选 matcher、写要运行的命令（文件路径）

**结论：✓**

官方原话
- "add a hooks block to a settings file" — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)
- "Yes, can be committed to the repo" — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)（`.claude/settings.json` 那一行）
- "No, local to your machine" — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)（`~/.claude/settings.json` 那一行）
- "No, gitignored when Claude Code saves a setting to it" — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)（`.claude/settings.local.json` 那一行）
- "Without a matcher, a hook fires on every occurrence of its event." — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)
- "Hooks merge: all registered hooks fire for their matching events regardless of source." — [features-overview](https://code.claude.com/docs/en/features-overview)

准确写法
- 三个常用文件：`~/.claude/settings.json`（你的所有项目，只在你机器上）；`.claude/settings.json`（单个项目，可提交进仓库，全队共用）；`.claude/settings.local.json`（单个项目，你自己的覆盖，Claude Code 自己写入时会排除出 git，手建的要自己加 .gitignore，见 [settings](https://code.claude.com/docs/en/settings)）。Windows 上 `~/.claude` 就是 `%USERPROFILE%\.claude`（[claude-directory](https://code.claude.com/docs/en/claude-directory)）。
- 另外还有：托管策略设置（组织统一下发）、插件的 `hooks/hooks.json`、skill 和子代理的 frontmatter。各来源的 hook 会合并，所有匹配的都会运行（并行）。
- 结构：`hooks` → 事件名 → 数组，每项是 `matcher` 加 `hooks` 数组，里面是 `{ "type": "command", "command": "…" }`。matcher 省略 / 空 / "*" 就是该事件每次都触发。
- 改文件后：文档说文件监视器一般会自动加载；没出现就重启会话。

建议中文念法
- 在 settings.json 里选事件、写命令。

### 5. 示例：PostToolUse + matcher “Edit|MultiEdit|Write”，按文件扩展名运行格式化器（Prettier / gofmt）

**结论：△**

官方原话
- "uses the PostToolUse event with an Edit|Write matcher" — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)（“Auto-format code after edits”）
- "the exact strings you use in permission rules, subagent tool lists, and hook matchers" — [tools-reference](https://code.claude.com/docs/en/tools-reference)（原句：工具名就是这些精确字符串）
- "Claude can also create or modify files by running shell commands." — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)（matcher 一节的 Note）
- "When the hook succeeds, Claude Code shows nothing in the conversation." — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)
- 课程原文（`claude-code-101__12`）：matcher 写作 Edit|MultiEdit|Write；The command checks the file extension and runs the appropriate formatter

出入与准确写法
- 事件和思路对：PostToolUse（工具成功之后）加一个只匹配文件编辑工具的 matcher，然后跑格式化器。
- 文档示例的 matcher 是 `Edit|Write`，命令是 `jq -r '.tool_input.file_path' | xargs npx prettier --write`（用 jq 从 stdin 的 JSON 里取出刚改的文件路径）。当前工具表里没有 MultiEdit（列的是 Edit、Write、NotebookEdit、Bash、PowerShell 等）。课程写法不会出错——不存在的工具名只是匹配不到——但画面上展示配置时，请用文档版本 `Edit|Write`，别画 MultiEdit。
- gofmt：文档没出现。“按扩展名挑 Prettier 或 gofmt”是课程对脚本做法的描述；文档示例只有一条 Prettier。要按扩展名分派，需要你自己写脚本——视频里这么讲可以，但要说清是“脚本自己判断”，不是 hook 自带。
- 局限（值得一提）：这个 matcher 只抓 Edit / Write；Claude 用 Bash 命令改的文件抓不到。文档的办法：加一个 Stop hook 在每轮结束时扫一遍工作区；或者同时匹配 `Bash|PowerShell` 并用 `git status --porcelain` 找改动；或者用 FileChanged 事件盯具体文件。
- PostToolUse 触发时工具已经跑完了，撤不回（"PostToolUse hooks can't undo actions since the tool has already executed."，hooks-guide Limitations）。

建议中文念法
- 编辑后自动格式化：匹配 Edit 和 Write。
- Bash 改的文件，这个 matcher 抓不到。

### 6. 要在压缩后重新注入上下文，用 SessionStart 的 compact matcher，不是 PostCompact

**结论：✓**

官方原话
- "Use a SessionStart hook with a compact matcher to re-inject critical context" — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)（原句后面还有 after every compaction）
- "doesn't support decision control or context injection for this event" — [hooks 参考页](https://code.claude.com/docs/en/hooks)（说 PostCompact）
- "adds their output to the compacted context" — [context-window](https://code.claude.com/docs/en/context-window)（“What survives compaction”表里，匹配 compact 来源的 SessionStart hook 那一行）
- "Summarized with the rest of the conversation" — [context-window](https://code.claude.com/docs/en/context-window)（同一张表：之前 hook 加进来的上下文，压缩时会被一起总结掉）
- "For injecting context on every session start, consider using CLAUDE.md instead." — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)

补充
- SessionStart 的 matcher 匹配的是“会话怎么开始的”：startup、resume、clear、compact、fork；compact 指自动或手动压缩之后。
- SessionStart 是少数会把 stdout 纯文本直接加进 Claude 上下文的事件之一（UserPromptSubmit、UserPromptExpansion、SessionStart、PostModelSwitch）；PostCompact 只用来观察（记录、清理），它返回的 JSON（包括 additionalContext）会被丢弃。
- 文档示例里的命令就是一条 `echo`，输出项目约定；也可以换成 `git log --oneline -5` 之类动态输出。
- 如果要补的是固定不变的内容，不用 hook：根目录的 CLAUDE.md 压缩后会从磁盘重新注入（context-window 表："Re-injected from disk"）。

建议中文念法
- 压缩后补上下文，别用 PostCompact。
- 要用 SessionStart，匹配 compact。
- 静态内容直接写进根目录 CLAUDE.md 就行。

### 7. hook 以你的权限在本机运行命令（安全提醒）

**结论：✓**

官方原话
- "Command hooks execute shell commands with your full user permissions." — [hooks 参考页](https://code.claude.com/docs/en/hooks) 的 “Security considerations”（hooks-guide 末尾的 Learn more 也指向这一节：review before deploying hooks in shared or production environments）

补充
- 同一节还说：它们能修改、删除或读取你这个用户账号能碰的任何文件；加进配置前先检查、先测试。
- 范围要说准：在本机以你的权限跑 shell 命令的是命令型 hook。http 型是把事件 JSON 发到你指定的地址；prompt / agent 型是让模型判断；mcp_tool 型是调 MCP 服务器上的工具。
- 这个来源是搜索摘录，不是抓到的页尾原文——见取证说明，上字幕前请打开原页确认一次原句。

建议中文念法
- 命令型 hook 以你的权限运行，先测再用。

## 附加核对

### A. hooks 当前支持的 hook 类型

**结论：✓**（五种）

官方原话
- "Four other types are available" — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)（command 之外还有四种）
- "There are five types" — [hooks 参考页](https://code.claude.com/docs/en/hooks)（Hook handler fields）
- "Agent hooks are experimental and may change." — [hooks-guide](https://code.claude.com/docs/en/hooks-guide)

清单
- `command`：跑 shell 命令（最常用）
- `http`：把事件 JSON 用 POST 发到一个 URL；靠响应体返回结果，只靠 HTTP 状态码拦不了动作
- `mcp_tool`：调用已配置 MCP 服务器上的一个工具
- `prompt`：把你的提示词和事件数据发给 Claude 模型，单轮判断，返回 `ok: true / false`
- `agent`：起一个子代理，能读文件、搜代码后再下结论；实验功能，将来可能变

建议中文念法
- hook 一共五种类型，不只有命令一种。
- 还有 http、prompt、agent 等。
- agent 型 hook 还是实验功能。

## 可以多讲一句的具体细节（≤ 3 条）

1. 退出码 1 拦不住：想拦必须退出 2。出处：hooks 参考页 “Other exit codes”（"Any other exit code doesn't block on its own for most hook events."）；实战课 05 也专门强调了这个坑。念法：想拦就退出 2，退出 1 拦不住。
2. 跳过权限也拦得住：PreToolUse hook 在任何权限模式之前触发，返回 deny 连 bypassPermissions 模式或 `--dangerously-skip-permissions` 都照样拦。出处：[hooks-guide](https://code.claude.com/docs/en/hooks-guide)“Hooks and permission modes”（"A hook that returns permissionDecision: "deny" blocks the tool even in bypassPermissions mode"，13 词）。反过来 hook 返回 allow 绕不过 settings 里的 deny 规则。念法：就算跳过权限，hook 的 deny 照样拦。
3. Stop hook 拦不了无限次：连续拦了八次，Claude Code 会强制放行（原文 "after it blocks eight times in a row"，条件是中间 Claude 没调用过工具）；脚本里要读输入里的 `stop_hook_active`，为 true 就退出 0；确实要更多次可调环境变量 `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`。出处：[hooks-guide](https://code.claude.com/docs/en/hooks-guide)“Stop hook hits the block cap”。念法：Stop hook 连续拦八次，会被强制放行。

## 不要讲的（文档没依据 / 已过时 / 有争议）

- “30 个事件”“40 个事件”等具体总数——文档没写总数；念“三十多个”。
- “用 /hooks 配置 / 新增 hook”——✗。/hooks 是只读浏览器。
- “退出码 0 = 放行 / 批准”——✗。对 PreToolUse，0 只是没意见，仍走正常权限流程。
- 示意图里写 MultiEdit——当前工具表没有这个工具；示例用 Edit|Write。
- “用 PostCompact 在压缩后注入上下文”——✗。PostCompact 只观察，不支持注入。
- “PostToolUse 能拦住 / 撤销操作”——✗。工具已经执行完，只能把 stderr 反馈给 Claude。
- “Stop = 任务完成时触发”——✗。每次回复结束都触发；用户打断不触发。
- “SessionStart、PostCompact、Notification 能用退出码 2 拦”——✗。这几个拦不了。另外，Notification 的 stderr：实战课说“会显示”，hooks 参考页的分事件表写的是 “Exit code and stderr are ignored”，两处不一致，不要讲这个细节。
- “InstructionsLoaded 能阻止某个文件载入”——✗。它只观察。
- “hook 一定不会失败 / 100% 生效”——脚本路径写错、没执行权限、matcher 大小写不对，hook 都会悄悄不生效；Edit|Write 也抓不到 Bash 改的文件。
- “hook 都在本机跑”——只有命令型是；http 型发请求到别处，prompt / agent 型调模型。
- “agent 型 hook 稳定可靠”——官方标注为实验功能。
- 工作区信任弹窗会先挡住 hook、`-p` 模式不弹窗等细节——只在搜索摘录里见到，没读到页内原文，？不要讲。
