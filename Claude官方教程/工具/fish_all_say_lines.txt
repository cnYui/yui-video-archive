Claude Code 干活，就三步：找线索，动手，验结果。
官方入门课第一课，五月发布，出镜的是 Lewis Menelaws。
它和聊天窗口最大的差别，是能直接动你的文件和终端。
聊天框给你一段代码，你得自己复制粘贴。它自己进去改。
怎么改？先收集上下文，再动手改文件、跑命令，最后验证结果。
没达标，就回到第一步重来，一直循环到能验证为止。
整个过程里，你随时能插话、打断、纠偏。
撑起这个循环的有四样：循环本身、上下文窗口、工具、权限。
窗口满了会自动压缩，什么时候调用工具由它判断，权限由你来定。
终端、编辑器插件、桌面应用、网页版，都能用。
官方课自己也提醒：它可能理解错、写出 bug、把事情做过头。
聊天框交答案，代理交结果。结果对不对，还得你来验。
装 Claude Code，三大系统都只要一条命令。
Mac 和 Linux 用 curl，Windows 用 PowerShell。
Homebrew 和 win get 也能装，不过默认不会自动更新。
装完在项目目录里敲 claude，第一次运行要先登录。
登录能用 Pro、Max、Team 或企业账号，也能用 API key。
它能访问你启动的那个目录和所有子目录，目录之外的要经你许可。
不想用终端也行：编辑器插件、桌面应用、网页版都能用。
不过终端的功能最全，有些功能只有终端里才有。
第一个提示别急着动手：按 Shift 加 Tab，轮换到计划模式。
计划模式只研究、只提方案，不改你的源码，最后交一份计划。
官方示例：整个应用要暗色模式，顶栏加个切换开关，再挑个对比度合适的颜色。
装它一条命令，用好它，从 Shift 加 Tab 开始。
Claude 动手写代码之前，最该做的，是不让它动手。
官方入门课教的标准工作流，就四步：探索、计划、编码、提交。
前两步放在计划模式里：它先把相关文件读一遍，研究、出方案，但不改你的源码。
计划出来先看一遍，不满意就告诉它具体改哪一块。
这时候纠偏最划算，因为一行代码还没写。
编码阶段给它三样东西：成功标准、趁手的工具、能反复跑的测试。
装上 Claude in Chrome，它能自己测界面，需直连官方账号。
官方课还提醒：测试要靠得住，别让它削弱测试来蒙混过关。
提交之前，先让子代理审一遍：它没参与写代码，眼光是新的。
提交信息想要固定格式？把约定写进 Claude 点 md，它就照做。
官方也说：一句话说得清的小改动，别计划，直接做。
先看后改，先审后交。
目标明确的活，提示写得越含糊，Claude 越费上下文。
Anthropic 官方入门课专门有一课，讲怎么管这块“记忆”。
上下文窗口，是 Claude 这次会话的工作记忆。
你的提示、读过的文件、命令的输出，全都占位。
装满了会自动压缩：先清掉旧的工具输出，不够再总结对话。
代价是，早期的详细指令可能丢。
三个命令管它：斜杠 compact 压成摘要，斜杠 clear 清空对话，斜杠 context 看占用。
同一个功能做到快满，用 compact。开新功能，用 clear。
要跨会话记住的事，写进 Claude 点 md：压缩之后，它会从磁盘重新读一遍。
还有个反直觉的：目标明确的活，提示写得越具体，越省上下文。
含糊的提示看着短，它却得自己到处翻代码、自己推理，反而更费。
上下文是预算，不是仓库。
Claude Code 每开一个新会话，上下文都是全新的，像第一天上班。
官方课说：没有 Claude 点 md，结构、依赖、功能都得重新摸。
解法是项目根目录的一个 Markdown 文件，每次开会话，它都会自动读。
官方的比喻：给代码库写的入职手册。
写什么？常用命令、代码风格，这些读代码也猜不到的规矩，每份别超过两百行。
项目级的进版本库，全队共享；用户级的放你的配置文件夹，只给你自己。
几份是叠加着一起读，不是谁覆盖谁。
同一个错纠正第二遍，就写下来，比如“别用 API 路由”。
想进文件，要明说“加到 Claude 点 md”；只说“记住”，进的是自动记忆。
项目文档用艾特加路径引用，不过引用的内容照样一启动就全载入，不省上下文。
官方课还建议：一开始先别写，看它总在哪被纠偏，再用斜杠 init 生成。
但它是上下文，不是强制配置。必须照做的硬规矩，交给 hook。
提示里写“改完代码要格式化”，Claude 通常会照做。
通常，不等于每次。Hooks 的卖点就一句：它想跳也跳不过去。
官方列了三十多个钩子事件，常用的就几个。
PreToolUse，在工具调用之前触发，能在事情发生前把它拦下来。
PostToolUse，在调用成功之后触发，自动格式化、自动检查放这里。
Stop，在它想收工时触发。一句“你还没做完”，就能让它接着干。
PreToolUse 能返回三种决定：放行、拒绝、交给你来定。
不返回 JSON 的钩子看退出码：2 是拦截，0 是没意见，别的都不拦。
最容易踩的坑：退出码 1 看着像报错，其实不拦，命令照样跑。
还有一招：不拦，改写。把命令里的密钥换成占位符，再放行。
压缩后补上下文，别用 PostCompact，用 SessionStart。
提示词是请求，Hooks 才是规矩。不过路径写错，它会悄悄失效。
查一个问题，Claude 翻了一大堆文件，主对话的上下文就这么被占满了。
子代理就是解法：它在自己的上下文窗口里干活，只把摘要交回来。
比如问一句：这个应用在哪处理退款？Claude 会派探索型子代理去翻代码。
翻的过程留在子代理那边，主对话里只剩结论。
自带几个子代理：Explore 只读搜代码，Plan 做计划调研。
想自己做一个？最省事的办法，是直接让 Claude 来建。
官方课演示的斜杠 agents 创建向导，新版本已经删了，别照着找。
描述写得好，Claude 才知道什么时候该叫它；用艾特点名，则一定会派它。
子代理就是带亚马尔头的 Markdown 文件，必填只有两个：名字和描述。
加一行 memory，它就能跨对话记住东西，越用越熟。
还能预载技能：写进 skills 字段，整份技能都会塞进它的上下文。
不过子代理自己也花用量，别当成免费的。脏活外包，只收结论。
每次让 Claude 审 PR，都得把同一大段审查标准重新粘贴？
Skills 治这个：把流程写成文件，Claude 需要时自己取用。
技能是个文件夹，里面放 skill 点 md：名称、描述，加上步骤。
放在个人目录，所有项目都能用；放在项目里，整个团队共享。
关键区别：它不会一开始就全塞进上下文。
Claude 先只读每个技能的名称和描述，对上号了，才把全文读进来。
Claude 点 md 是每次会话都载入的规矩，技能是需要时才翻开的手册。
输入斜杠加技能名能直接调用，也能让它自己判断；改完不用重启，当场生效。
官方课的经验法则：同一套多步指令打了两遍，就该做成技能。
比如视频里演示的：提交信息、PR 描述、调试、写文档。
别高兴太早：技能装多了，描述每一轮都占上下文，用不到的别装。
常驻的规矩进 Claude 点 md，偶尔用的手册做成技能。
很多上下文，其实不在代码库里：在数据库、协作软件、公开仓库里。
MCP，模型上下文协议，就是把外部工具接进 Claude Code 的桥。
团队用 Linear 管项目？加个 MCP 服务器，就能直接读工单。
要查依赖的最新文档，有 Context7 这类文档服务器。
用 claude mcp add 添加，常用 HTTP 和 stdio 两种。
会话里敲斜杠 mcp，能看连接状态，不用的直接关掉，配置不会丢。
范围有三档：本地，只有你、只在这个项目；用户，你的所有项目。
第三档是项目：写进 mcp 点 json 提交进版本库，全队拿到同一套服务器。
要记住代价：每个服务器的工具名和说明，每个会话都要载入，会占一点上下文。
有现成命令行的，比如 gh、aws，更省；技能管怎么用，和 MCP 互补。
默认只先放工具名，用到才加载。用第三方中转的，默认可能是关着的。
多接一个，就多占一点上下文，不用的，关掉。
Claude Code 有六种权限模式，从事事问你，到完全放手。
手动：只读不用问，其余先问你。接受编辑：改文件和常见文件命令，也不问。
计划：只研究、只提方案，不改你的源码。
自动：多数直接放行，命令、联网这类，交给另一个分类器模型先审。
不再询问：只放行预先批准的，其余直接拒绝，适合 CI 无人值守。
绕过权限：跳过所有检查，只能放在隔离的容器或虚拟机里。
日常按 Shift 加 Tab，在前四种间轮着切，状态栏随时显示当前模式。
自动模式拦强制推送、生产部署、把下载的代码直接丢进 shell。
新版本里，终端新会话默认就是自动模式，先看状态栏。
分类器管意图，不管对错：认证写坏了，它照样放行。
所以要搭一个跑测试的 Stop 钩子：一个管动手前，一个管收工后。
放手可以，但要有人验收。
