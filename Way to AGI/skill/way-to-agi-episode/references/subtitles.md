# 字幕规范（去口癖、术语、括号注释、中英双语、终检）

写 `make_cues.py` 前读一遍；把字幕交给用户看之前，按最后的「终检」过一遍。

来源：2026-09-29 用户要求把 ChatCut 里的字幕精修技能 `zh-caption-polish-annotations` 并进来。编辑器专属的操作（改透明度隐藏、自动翻译、改源转写）没有搬，其余按本流程的做法改写；逐条对照见 `D:\大疆\docs\ai\context\20260929-185438-zh-caption-polish-merge_CN.md`。

## 总原则

- **字幕和成片里听到的一致**：声音里剪掉的口癖、半句，字幕里也没有；声音里还在的，字幕里也留着。
- 只改被要求改的。看到范围外的问题（说法不准、疑似张冠李戴、画面文字的错别字），列出来让用户决定，不顺手改。
- 用户改过的字幕、自己加的括号，不改、不叠加；重新生成 `make_cues.py` 时保留。
- 拿不准的（数字、人名、引用是谁说的、听不准的词）标出时间点问用户，不猜。不改变含义的（明显的同音错字）先按上下文最合理的写，并标出来。
- 中文先定稿（口癖、错字、术语、注释都做完），再写英文；之后中文再改，回头对一遍英文有没有跟着改。

## 去口癖

| | |
|---|---|
| 剪掉（声音用 `skip`，字幕同步没有） | 呃、嗯、额；句首或句中的“啊，”“哦”；句尾当口癖用的“啊”（“做做自媒体啊”→“做做自媒体”）；当填充词用的“就是”“那个”“这个这个”；说错重来的半句（保留最后一遍完整的） |
| 留着 | 有语气作用的“呀、吧、呢、吗”；音节级口吃（“一一部”“攻攻击”），声音和字幕都不动，用户要求才剪 |

- 口癖是**单独的语气字**，不是词的一部分：“额度”“金额”里的“额”不动。找口癖要看上下文，别整篇搜索替换。
- 整条只有口癖：整条不要（声音一起剪掉）。不要留 `zh` 或 `en` 为空的条：画面上会留一个空条，SRT 里也会出空条。
- 删了什么都告诉用户（说错的数字、说法不准的整句，写明）。

## 术语和识别错误

- **术语表**：开写前先列本期的专有名词和写法（产品名、模型名、缩写、人名），同时放进 `asr.py` 的 `PROMPT` 和 `make_cues.py` 顶部注释。
  - 写法以用户已经用过的为准（标题、封面、用户改过的字幕）；用户没写过的用官方写法；拿不准的（如 VSCode / VS Code、Opus5.5 / Opus 5.5）先问。
  - 全片统一：改一处，全片搜一遍。
- **常见误识别**（AI 类视频）：Opus → “OPS”“OPPO”，Claude → “Cloud”，OpenClaw → “OpenCloud”，3A → “三 D3A”。`qa_asr.py` 之后搜一遍。
- 听不准的词、拿不准的意思：标出时间点问用户。疑似张冠李戴（把 A 说的话安在 B 身上）提醒用户，由用户决定怎么改。

## 碎片条

- 每条字幕要读得完（页面里从开始前 0.1 s 显示到结束后 0.45 s，不和下一句重叠）。
- 手动拆分或剪辑后只剩半个词的碎片（例如单独一个“式，”，说话不到约 0.3 s）会在画面上闪一下：并进相邻条（改 `s` / `e`，同一个 pid），不要把文字清空。
- 完整的短句（“拜拜。”）不算碎片。

## 括号注释

给观众听不懂的引用、典故、术语、冷门信息补一句，帮他们跟上。示范：说到“给猴子一部打字机”，括号里加“这是无限猴子定理”。

- **格式**：全角括号“（）”，紧跟在被解释的词后面；一般 12 字以内；点名典故、定理用“这是……”，术语给最短的定义。
- **该加**：

  | 类型 | 例子 |
  |---|---|
  | 引用、典故 | 那给猴子一部打字机（这是无限猴子定理） |
  | 术语缩写 | 没想到是这样实现 AGI（通用人工智能）的 |
  | 技术概念 | 在使用了 Loop Transformer（循环复用网络层的架构）之后 |
  | 行业黑话 | 做一个 3A（高成本 高体量 高质量）大作 |
  | 冷门产品、项目 | 半年前 OpenClaw（开源 AI 智能体）刚出来的时候 |
  | 支撑观点的背景事实 | 黑神话悟空一些场景（多扫描自山西古建筑） |

- **不加**：大众熟知的名字（GPT、豆包、马斯克等）；自己不能核实的内容；用户已经自己加过括号的地方；不在注释里反驳或纠正说话人（用户要求才行）。
- **位置**：放在第一次出现的地方；那一条太短（约 1.5 s 以内）读不完，就放到相邻、提到同一概念、时间更长的那一条。
- **密度**：大约每分钟一条，宁少勿滥。
- **准确**：注释是给观众看的事实陈述，只写有把握的；拿不准就不加，并告诉用户。
- **一行放得下**：字幕带的中文只有一行、不换行，中文（含注释）约 28 字以内，英文（含注释）约 90 字符以内，超了会冲出画面。放不下就缩短注释；还不行就把长句拆成两条（各带自己的 `s` / `e`）。
- **括号里只放没说出口的话**：页面里的 `cueT` / `tm.at()` 和 `mix_audio.py` 的 `phrase_time` 用字数比例推算“说到哪个词的时刻”，会跳过全角括号里的字（`spoken()`）。口播里真说出口的话别放进全角括号，否则时间会错位。

## 中英双语

- **版式沿用本合集已定的**：中文 52 px 一行 + 英文 30 px 一行，居中，字幕带在 y 922 以下；不用编辑器里“白字、最多三行”那套。
- **翻译**：
  - 口语、简洁，按意思翻，不逐字直译（英文一行，约 90 字符以内）。
  - 专有名词保留英文原名：Opus 5.5、Claude、OpenClaw、Gemini、GPT、AGI、Loop Transformer；中文特有的名称用通行英文名：豆包 → Doubao，黑神话悟空 → Black Myth: Wukong，UP主 → creator，悠一 → Yui。
  - 中文括号注释也翻成简短的英文括号注释（半角括号），例如（这是无限猴子定理）→ (the infinite monkey theorem)。
  - 用户自己写的玩笑或更正，保留原意，不“纠正”：“马斯克（不是马斯克）”→ “Musk (actually, not Musk)”。
- **画面里我们自己排的中文文字层**（标题卡、章节名、要点卡片、标签；不含录屏和截图里本来的文字）也要配英文小字，同一处、同一风格。发 YouTube 的期数必做。

## 终检（渲染前、导出 SRT 前）

1. **全片扫一遍**：残留的识别错误、同一个词的写法是否统一、口癖有没有漏、碎片条、注释长度和一行放不放得下、`zh` / `en` 为空的条、改过中文的条英文有没有跟着改。
2. **看画面**：`render_all.py --stills …` 抽几处，看中英上下位置和字号对比、有没有冲出画面或压到出镜框、注释读得完读不完、英文专有名词和注释对不对。
3. **汇报**：用表格给用户看改动：时间（分:秒）+ 改后的字幕；说明哪些只改了字幕、声音有没有变；没改的问题和原因。

## 不要做

- 不要为了改字幕去改识别结果（`asr/*.json`、`_qa_asr.json`）：那是证据，改字幕只改 `make_cues.py`。
- 不要靠清空文字来“删除”一条字幕：整条不要（声音一起剪），或者并进相邻条。
- 不要改用户手写的内容和注释；不要顺手改范围外的东西，列出来让用户决定。
