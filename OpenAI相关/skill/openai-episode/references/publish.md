# B 站投稿（Chrome 插件填表）

细节的总表在记忆 `bilibili-publish-form-quirks` 和 `AI科普/skill/yuanlai-ruci-episode/references/bilibili.md`；这里写 OpenAI相关 第 1 期（BV1wYaU6oEbw）实际做的一遍。

## 投稿前

- `投稿信息.json`：`title`（草稿，用户定）、`tags`（10 个）、`desc`（≤ 2000 字，第 1 期 1833）、`video`、`cover_16x9` / `cover_4x3`、分区人工智能（tid 231）、创作声明“含AI生成内容”。
- **简介的写法**（第 1 期）：①一句话说这条视频是什么；②【官方说的】带核对日期、只写官方原文对得上的；③【N 个作品】每个一行：名字（@账号）原帖链接，注明“模型名都是发布者自己标的”；④【几处要说明】官方没有的名字、没法核实的数字、转发的原作者、合作伙伴的利益相关、Pro 档 / 非标准版、Magnific 这类自家宣传；⑤其他链接（演示页，注明“他人发布，内容未经验证”）；⑥声明：配音为 AI 生成（曼波声线）；画面来自 X 平台账号和 <官方发布会>，版权归原作者，如有问题请联系，立即处理；价格和功能会变，以官方为准。
- 标题：封面写短钩子，标题写完整一句、不抄封面（**封面和标题的协定**（用户 2026-10-03：「封面文字中最下面一行的小字可以删除，因为用户根本看不见……封面中的文字要简略要大，标题则需要详细，这个规则对我目前做的所有的视频skill都要生效」）：封面上只放几个**简短的大字**（关键词 / 钩子），**不放最下面那行小字**（副标题、说明、清单、来源署名之类，缩到信息流里根本看不见）；**标题写详细**，把封面放不下的信息（时间、数量、对象、结论……）写进标题，不和封面是同一句。例：封面「大模型 / 谁夯谁拉？」→ 标题「2026下半年大模型谁夯谁拉？18个模型锐评」。系列名、期号这类合集标识照旧。）；模型名用官方写法；不夸成“官方发布的效果”。用户可能在页面里手改标题，他开始打字时我只读不写。
- **加入合集**：先点开“加入合集”下拉看有没有「OpenAI相关」（第 1 期我没点开就以为没有，其实用户已经建好、里面已有 DevDay / dots 4 条；漏选后要在编辑页补加）。有就选，没有再问用户要不要新建。
- 用户**明说“发布 / 填表发布”**才点“立即投稿”；只说“填写”就停在点之前。

## 上传视频（只能用户来）

插件 `file_upload` 单次 ≤ 10 MB，在插件控制的标签里点“上传视频”也不会弹出系统文件框；绕过大小限制（分块塞进页面再拼）会被权限分类器拦下，不要试。做法：Chrome 插件开 `https://member.bilibili.com/platform/upload/video/frame`（登录态正常；页面上“本地浏览器存在 N 个未提交的视频”是用户别的草稿，**别点“继续编辑”**）→ `mcp__ccd_host__reveal_path` 把成片在资源管理器里选中 → 请用户把 mp4 拖进上传区，拖好说一声。上传 253 MB 约 1–2 分钟，期间表单可以填。

## 填表（用户拖好之后）

页面的视口大小在上传过程中会变，**坐标点击会打偏**：弹窗里的按钮、“完成”、“立即投稿”都用 `javascript_tool` 按文字 / 类名点；顶层 `await` 可用，包成 async IIFE 会返回 `{}`；返回内容里带 URL 的 query string 会被拦。

1. **封面**：JS 点文字是“添加封面”的元素 → 弹窗“封面制作”→ 勾“双比例同步改动”（`.sync-checkbox`）→ `find` 出封面文件输入框、`file_upload` 传 16:9（1920×1080）→ 取消勾选（再点一次 `.sync-checkbox`）→ JS 点文字是“首页推荐封面（4:3）”的元素 → 同一个文件框传 4:3（1440×1080）→ 截图确认两个位各是对应排版 → JS 点 `div.button.submit`（“完成”）。
2. **标题**：`find` “请输入稿件标题” → `form_input`。
3. **创作声明、分区**：先读一遍当前值（这次默认就是“含AI生成内容”和“人工智能”），对就不动。
4. **标签**：B 站会自动填几个（“模型 / 效果 / 建模”），点每个标签里的 `svg.close`（派发 click）删，**一次只删一个（会重新渲染），要循环**；再点标签输入框（`find` “按回车键Enter创建标签”，页面里有两个，取表单里那个）→ `type` → `Return` → 等 2 s，**每个标签都要先点一下输入框**；上限 10 个。手敲小写带连字符的标签（`gpt-6-astra`）会被悄悄丢掉，要点“推荐标签”里的同名项（JS 点文字等于它的叶子元素）；大写 `Claude` 会被拒；话题专用标签也会被丢。
5. **简介**：`document.querySelector('.ql-container').__quill.setText(文本, 'user')`，读回长度和页面右下角计数（1833/2000）。
6. 其余默认：不定时、不选话题、不开商业推广；合集按上面的“加入合集”处理。
7. 提交前把标题、封面、标签（10 个）、简介计数、声明、分区、合集过一遍；点“立即投稿”→ 页面出“稿件投递成功”（投成功后页面会自己多开一个视频页标签，一并关）。

## 投完核对（页面里 `fetch`，`credentials: 'include'`，返回只取要的字段）

- `https://member.bilibili.com/x/web/archives?status=is_pubing,pubed,not_pubed&pn=1&ps=3`：`bvid`、`state` / `state_desc`、`tid`、`tag`、`duration`、`desc` 长度、标题。
- `https://member.bilibili.com/x/vupre/web/archive/view?bvid=…`：`archive.cover`（16:9）和 `archive.cover43` 要是**两张不同的图**（下载后看尺寸 1920×1080 / 1440×1080、平均色 / 蓝像素占比和本地一致）。
- `https://api.bilibili.com/x/web-interface/view?bvid=…`：`ugc_season` 看合集。
- 把 BV 写进 `投稿信息.json`、本期 README、`AGENTS.md`、根 `README.md` 的视频存档表、记录文件；GitHub release / 提交 git 用户没说就不做。

## 已发布后发现缺东西

- 缺英文字幕 / 要换配音：只能在编辑页「更换视频」（用户自己选文件），改完状态“修改内容待审核”，要重新过审；不改视频时可以把 SRT 当外挂字幕。
- 漏选合集：编辑页“加入合集”补选（用户要求时才做，不改视频内容）。
