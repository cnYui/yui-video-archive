# 台本

目标：5–7 分钟的正片（不含片头片尾），讲清楚一个 AI 知识点。用户对第 1 期 v1 台本的否决意见是这套规则的来源：v1 太 AI、太生硬、例子太多、角色梗太多。写之前先看 `D:\大疆\AGENTS.md` 的「台本风格规则」，那里可能有比这里更新的要求。

## 结构（第 1 期 v3 的骨架，每期照这个排）

| 场景 | 内容 | 要点 |
|---|---|---|
| S00 片头 | 片头（打出“悠一”，以前是 UE 字标），现成 | `("gap", 3.7, "片头")`，不写台词 |
| S01 开场白 | 一句话 | “大家好，我是{讲解员}。今天给大家介绍 XX。”（讲解员 = `episode.json` 的 `presenter.name`：山田凉 / 鲸鱼娘）说完就结束，不寒暄、不自我吹捧 |
| S02 N 个疑问 | 观众实际会遇到的 2–3 个困惑 | 先给一个日常场景（一两句），再列“第一……第二……第三……”，最后一句“这期视频，就把这 N 个问题讲清楚”。这一场结束时疑问卡飞到右上角变成「本期目录」 |
| S03… 逐题拆解 | 每个疑问一个章节，标题「一、……」「二、……」 | 定义、全称、原理、具体操作，直接给干货 |
| 补充章节（可选） | 和本期强相关、用户点名要讲细的内容 | 第 1 期的「四、主流的三种调用方式」就是用户要求加的；它不属于任何一个疑问，目录不高亮 |
| 实操（可选） | 具体操作步骤 | 用“步骤卡 + 示意界面”，不录屏 |
| 总结 | 3–4 条要点 | 和开头的疑问一一对应，可以打勾回收。**不做下期预告** |
| S99 片尾 | 片尾（印章签“悠一”），现成 | `("gap", 4.8, "片尾")` |

`episode.json` 的 `questions[].scenes` 把疑问和章节对上，`chapters` 写进度条上的章节名（短，6–10 个字）。

## 写法

- 短句、口语、分点。一句话只说一件事。
- 少用语气词（“呢”“哦”“啦”“其实呢”）；不用“不是……而是……”“值得注意的是”“总的来说”这类 AI 腔句式。
- 不堆例子、不堆比喻：一个概念最多一个例子，能直接说清就不用比喻。第 1 期 v2 连唯一的“点餐窗口”比喻都删掉了。
- 只讲和本期知识有关的内容：不加讲解员的角色梗（山田凉：吃草、借钱、怪人、弹贝斯、睡觉、饿肚子；鲸鱼娘：白饭、不许叫胖），不引用原作台词。
- 讲解员自称只用本期的 `presenter.name`（开场、结尾“我是{讲解员}，我们下期见”）：鲸鱼娘那期不要写“我是山田凉”“我是大肥鱼”，反过来也一样，`build_script.py` 会提醒。
- 英文术语第一次出现时给全称和中文名（例如 API = Application Programming Interface，应用程序编程接口）。
- 数字、价格、接口地址、模型名要可核实。查官方文档，把来源和查询日期记进 `docs\ai\context`；台本里的说法要稳妥（“通常”“截至 2026 年 9 月”），查不到原文的细节列进“待用户确认”。
- 示意界面、代码卡都标“示意”；Key 一律打码（`sk-••••`）；不出现真实品牌 logo，品牌只以文字出现。
- 字数：配音速度约每秒 4.3 字（build_script.py 按这个估时），6 分钟正片约 1400–1500 字、60–70 段。

## `台本\script_data.py` 格式

```python
SCENES = [
    dict(id="S01", title="开场白", char="从左侧走入", rows=[
        ("gap", 1.2, "【动作：走动】背景淡入"),
        ("say", "大家好，我是山田凉。今天给大家介绍API。",      # 字幕原文（屏幕上显示的）；名字 = 本期 presenter.name
                "大家好，我是山田凉。今天给大家介绍 A P I。",   # TTS 文本（送去 Fish Audio 念的）
                "画面中央大字「API」"),                        # 画面说明（写 scenes.js 的依据）
    ]),
]
```

- 段号由 `build_script.py` 按全片顺序生成（`S03-12`），不要手写。
- 开场自称照旧用讲解员的名字（“大家好，我是鲸鱼娘”），用户自己配音以后也不变（用户 2026-09-28：“开场还是说我是鲸鱼娘，配音署名写UE”）。
- 画面说明写清楚这一段屏幕上出现什么、强调什么。白板版（新一期默认）写「手写什么、画什么」：`手写「Jev = 决策模型」，圈「决策」`、`画两个框 LLM / Jev，中间写 vs，箭头指向结论`、`贴一张代码卡（示意）`。要手写的字短一点（一行 ≤ 14 字，一个汉字约 0.3 秒），别堆在一章的最后一句（画面比声音早 1 秒淡出）。
- 角色动作写成 `【动作：词】`，从词表里选（`pipeline-contract.md` §4；怎么选、用多少见 `visuals.md`「角色动作」）。动作要贴着台词：列举写 `【动作：数一@第一】`…，指向内容写 抬手 / 指这里，下结论写 叉腰，“对”“没错”写 点头，否定写 `摇头+认真`，讲完一题写 `好耶@末尾`（拉炮，每期 1–2 次）。说话时的小手势、句末点头、看向内容由引擎自动层加，台本不写。第 2 期档位：全片 20–30 个，一段最多 1 个，大动作 ≤ 12 且间隔 ≥ 15 s；`build_script.py` 会数一遍并提醒。
- `gap` 是纯画面停顿（秒），用于转场、打勾、让观众看一眼图。

## TTS 文本怎么写（Fish Audio S1 的经验）

字幕原文给人看，TTS 文本给模型念，两者可以不同：

| 情况 | 字幕 | TTS |
|---|---|---|
| 大写缩写逐字母读 | API、HTTP、AI | `A P I`、`H T T P`、`A I` |
| 品牌名拆开，避免念成一个怪词 | DeepSeek、OpenAI | `Deep Seek`、`Open A I` |
| 路径、字段名去掉符号 | `/chat/completions`、`previous_response_id`、`x-api-key` | `chat completions`、`previous response id`、`x api key` |
| 长句加停顿 | 一整句 | 用逗号和句号切成短句 |
| 能正常念的词 | JSON、Key、Claude | 原样 |

英文专有名词（Anthropic、Claude 等）S1 可能念不准，配音后要请用户重点听。

## 审校（写完、交给用户之前）

两路独立审校，意见合并后再改：
1. **口播编辑**：有没有 AI 腔、句子是否够短、有没有多余例子和梗、开场和疑问是否符合结构、节奏是否拖沓。
2. **技术审校**：每个事实对照官方文档；过时或说不准的地方改成稳妥说法；列出需要用户对照真实页面确认的细节。

## 交给用户确认 ✋

- 给出：分场表（场景、时长估计、章节名）、全部台词（按场景分组）、需要用户确认的事实、本期台本动作（`build_script.py` 打印的「动作：…」一行：各是什么、合计多少、大动作和贴纸各几个）和自动层档位（`auto_gestures`）、背景安排、片尾清单问题（如果还没问）。
- 用户可能改多轮；每轮只改台本源 `script_data.py`，再重跑 `build_script.py`，不要手改生成的 `台本.md`。
- 旧版本不删：改名为 `台本_v1.md` 等留作记录，或移到 `_旧稿\`。
