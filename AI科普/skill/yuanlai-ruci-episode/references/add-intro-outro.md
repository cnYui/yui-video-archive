# 给任意视频加片头片尾（悠一）

用于用户自己拍的视频（例如 Pocket 4P 口播），不是《原LAI如此》正片流程的一部分。

名字：2026-09-29 起片头打出“悠一”、片尾印章签“悠一”（以前是 UE 字标；用户：“之后统一换成悠一”）。默认值在 `片头片尾\intro\data.json` 的 `name` 和 `outro\data.json` 的 `signature`，片尾清单不写 `signature` 时也是悠一。写回 `"UE"` 仍会画原来的 UE 字标 / 印章，除非用户要，不要写。

```bash
python "D:/大疆/AI科普/skill/yuanlai-ruci-episode/scripts/add_to_video.py" "<视频.mp4>" --outro-data "<片尾清单.json>"
python "D:/大疆/AI科普/skill/yuanlai-ruci-episode/scripts/add_to_video.py" "<视频.mp4>" -o "<输出.mp4>" --outro-data "<片尾清单.json>"
python "D:/大疆/AI科普/skill/yuanlai-ruci-episode/scripts/add_to_video.py" "<视频.mp4>" --outro-data "<片尾清单.json>" --no-music
```

用技能里的这份：BGM 取 `素材\音频\bgm.wav`。`片头片尾\add_to_video.py` 是第 1 期时的旧副本，BGM 路径指向 `第01期_什么是API\制作\audio\bgm.wav`，不要再用。

- 输出默认在原视频旁边：`<名字>_片头片尾.mp4`，**原文件不动**。
- 片头 3.8 秒、片尾 4.8 秒按原视频的分辨率和帧率渲染（4K 用 2 倍像素渲染，不是放大）；正片 H.264 不重编码，直接拼接，画质不变。
- 比 16:9 宽的视频（例如 2340×1080 = 19.5:9、3120×1440）：片头片尾页面按视频的比例开成更宽的画布（高 1080，宽 = 视频宽 ÷ 缩放，2340×1080 就是 2340 宽、缩放 1），并把 `canvas` 传给页面：名字 / 小票居中，纸色和墨色底、纹理、四角裁切标、片头收尾的整屏墨黑铺满全宽，没有空白边、不拉伸。脚本会打印 `intro / outro page 2340x1080 at scale 1`。
- 16:9 的视频（1920×1080、3840×2160、640×360…）和以前完全一样（1920×1080 页面按比例缩放）。比 16:9 窄的视频（4:3、竖屏）目前也还是 1920×1080 的页面缩放到视频尺寸，会被拉伸，片头片尾暂不支持这种比例。
- 片头片尾下面垫一小段系列 BGM，比口播低约 7 dB，避免几秒完全静音；`--no-music` 改成静音。

## 片尾清单要先问

片尾写的是“本期制作清单”（例如 拍摄：Pocket 4P / 剪辑：ChatCut / 视频剪辑模型：Opus 5.5）和结束语“感谢大家看到最后”。每个视频的实际情况不同：**用户没告诉你就问**，不要用 `片头片尾\outro\data.json` 里的默认值。把用户说的内容写成一个 JSON 传给 `--outro-data`：

```json
{
  "items": [
    {"label": "拍摄", "value": "Pocket 4P"},
    {"label": "剪辑", "value": "ChatCut"}
  ],
  "closing": "感谢大家看到最后",
  "signature": "悠一"
}
```

`items` 1–6 条。不要改 `片头片尾\outro\data.json` 本身，把本次的清单放在视频旁边（不要放会话临时目录：那里的路径超过 260 个字符，Windows 上 Python 打不开）。脚本自己的临时文件放在输出文件旁边（`_tmp_add_to_video_*`，跑完自动清掉）。

## 交付前检查

- `ffprobe` 看分辨率（和原视频一样）、帧率、时长 ≈ 3.8 + 原时长 + 4.8。
- 完整解码一遍（`ffmpeg -v error -i out.mp4 -f null -`）没有报错。
- 在两个接缝处各抽一帧看画面，听一下片头到口播的音量衔接；宽画面（2340×1080 等）再看一眼片头片尾两边没有空白边、构图居中。
- 同一个视频跑两次，成片的逐帧 md5 可能对不上：这种开页方式（非整数 / 2 倍缩放）每次启动浏览器可能整帧差 ±1 个色阶，不是版面变了。
