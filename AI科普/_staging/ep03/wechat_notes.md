## A. 差评X.PIN《被全网吹爆的Jev，真有那么神吗？》（江江 / 撰文 不咕，2026-09-27 01:12）
https://mp.weixin.qq.com/s/aFkhX2xJoiGssaWBXywOwg

- 官宣推文近 4000 万浏览、7 万多赞；创始人是前 OpenAI 研究员（文中说是“研发 ChatGPT 的关键人物”，待核实）。
- “不会说话的模型”，官方叫 System One 模型：只负责判断、不负责说话；“模仿直觉”。
- 官方：一次调用 70–500 ms；每百万输入 token 0.042 美元，输出不收费。
- 网友玩法：接微信分析领导意图、8 分 43 秒速通《我的世界》、地铁跑酷、马里奥；有人做实时交易机器人亏了 31680 美元。反对派：老式分类器也能做，是营销。
- 作者实测三款游戏：
  - 《我的世界》：用网友开源项目，配 GLM 5.3 当“军师”，12 分 39 秒通关；但代码预先标好了路线、打龙用固定模块；274 个决策里 250 个只有一个选项。
  - 1v1 斗地主：作者输了；同一残局重跑 6 次，4 次王炸、2 次对 K（两个选项概率接近，结果会变）。
  - 《杀戮尖塔》单打 10 局没通关，最好 19 层、平均约 11 层。一局里 3 张防御牌被列成 3 个选项（17/20/18 分），“结束回合”21 分 → 选了结束回合。结论：它给所有选项出概率分布，选项怎么列（harness 设计）会影响结果。
  - 1000 多次操作里一半决策在 400 ms 以内。
- 作者结论：不会规划、没有记忆，离开写好的程序就是“手速很快、会瞎蒙的选择机器”；适合内容审核、客服分流、信息分类，像大模型身边的“跑腿小弟”。

## B. 腾讯科技《深入底层看Jev，能否戴上“范式革新”的王冠｜Hao好聊趋势》（博阳，2026-09-26 20:18）
https://mp.weixin.qq.com/s/ZkfxAuaFrXs9aq8cyraZng

- 前史：BERT（2018，Encoder-only，做分类）；奖励模型（OpenAI 2019 偏好微调、2020 摘要）；《Let's Verify Step by Step》（2023）；Galileo Luna-2“单 Token 分类器”；Skywork-Reward-V2。→ “继承语言模型的理解能力、但不生成文字”不是 Jev 独有。
- 作者认为 Jev 的两点不同：
  1. 通用概率接口 + 后训练方法 RLCD（文中译“面向校准决策的强化学习”），目标是校准到真实世界事件的概率，而不是人类偏好（RLHF）。
  2. 并行：同一份材料一次最多可问 250 道题，题目之间没有依赖就并行算。
- 官方公开的接口：State（状态，共享材料）+ Questions（多个互相独立的问题）。三种原语：
  - Noul（是非题）：返回 0–1 的概率；
  - Choice（选择题）：返回各选项概率分布；
  - Score（打分题）：返回各等级概率和加权得分。
  - State 只读一次，所有问题并行、互相看不到；题 2 依赖题 1 就要分两次请求。官方鼓励“Speculative fan-out（推测性并发）”：一开始就把可能用到的题全问了，下游代码丢掉没用的。
- 第三方黑盒测试（Archer Hume）：1 题计费 268 个输入 token、2 题 276 个（State 不重复计费）；题数到近百道前延迟几乎不变；“暗号”实验：暗号放在题 A 里，题 B 选对的概率 0.00，放进 State 后 >0.90（题目之间隔离）；加一个干扰选项会改变其他选项的相对比例（选项之间会互相影响）；选项从 2 个加到 200 个，处理时间没有按比例变长（没有逐字生成）。
- 开源复刻：Kev（KV Cache 共享 + 指针头）、NanoJev（候选间注意力）、openjev（读选项字母 token 的 logits）、minojev、Winnow（Gemma 4 12B 上 LoRA + 教师蒸馏）等。架构“不复杂，谈不上范式革新”。
- 校准测试（Archer Hume）：1200 道 MMLU，校准误差 0.031；三位数乘法 30 题正确率 86.7%、平均把握 83%；两步应用题正确率 32%、平均把握 30%。Kev-9B 温度校准后校准误差 10.6 → 4.2 个百分点。
- 准确率与边界（都是第三方测试）：
  - Nimble：13 组、3880 条公开数据（事实核查、意图路由、蕴含、审核、医学问答），按数据集平均 76.0%。
  - JevBench 困难题：多步查找 85.7%、长政策判断 60.5%、时间与数字 26.7%；合计 Jev 74.1% vs DeepSeek V4.1 Flash 95.0%；中位耗时 0.67 s vs 3.15 s。
  - briantrust：和 GPT 5.6 Luna 比二选一 616 题，知识题差 1.6 个百分点、数学推理 19.3、代码 20。
  - OpenProse：关键关系放在文本前面 80.5%，挪到中间 40.9%。
  - JevBench v1.4 新增 308 道封闭难题：Jev 从公开题 86.6% 跌到 36.7%；DeepSeek V4.1 Flash（思考模式）94.8%。
  - 提示注入检测（Agent Journal）：83.65% → 外部数据集 95.58%；软件更新安全（Scarif Labs）：换生态后 AUROC 0.851 → 0.605。
- TypeSafe 自己也建议：数学运算和日期比较交给代码，尽量减少判断里的多层依赖。
- 成本账：记忆检索实验里加一道 Jev 判断，总延迟 649 → 1087 ms，每千次费用翻了两倍多。先调 Jev 再调主模型，要省下足够多的后续工作才划算。
- 结论：规则清晰、材料齐备的环节里是好用的工程工具；“范式革新”为时尚早。

## C. 逛逛GitHub《一周就收割 2 万 Star，这个 GitHub 项目把近期爆火的 Jev 模型开源了》（2026-09-26 12:18）

## D. 开源星探《Jev Skill 技能包来了！全球开发者砸出 500 个开源项目！》（2026-09-28 08:52）
https://mp.weixin.qq.com/s/SSVs6c8mELMqIf7UiL7RiA

- 2026-09-16，旧金山创业公司 TypeSafe AI 发布 Jev。“一个字都不生成”：只给数字、选项、概率分布；36氪称“哑巴模型”。
- 几天内全球近 500 个开源项目；Vercel 上 24 小时内近 13% 付费团队用上（文中称 Vercel 历史上采用最快）。
- System One 来自卡尼曼《思考，快与慢》：系统一快、自动、直觉；系统二慢、刻意、逻辑。TypeSafe 说软件里需要的判断 90% 是系统一。
- 三种题：Choice（选中项 + 各选项概率 + 置信度）、Score（分数 + 各等级概率 + 置信度）、Noul（命题为真的概率 0–1）；可以混在一个请求里并行，问 1 题和 10 题延迟差不多。
- 文中列的 TypeSafe 官方对比（对标 GPT-5.6 Terra）：响应 114 ms vs 8.5 s（约 75 倍）；单次成本 $0.000081 vs $0.013880（约 171 倍）。输入 $0.042 / 百万 token，输出免费。
- “零幻觉输出”：API 规定只能在给定选项里选——可以选错，但不会输出不存在的选项（例如三个部门里不会冒出第四个）。
- jev-skill（github.com/wuyoscar/jev-skill，MIT）：5 个 skill（jev / triage / documents / eval / act）；烟雾测试 24 条工单 Jev 24/24、DeepSeek V4 Flash 23/24，成本 $0.0011。接入：OpenRouter 或 TypeSafe 官方（console.typesafe.ai）。
- 链接：官网 https://typesafe.ai 、文档 https://docs.typesafe.ai 、展示墙 https://madewithjev.com

## 四篇共同的口径

1. Jev = 只做判断、不生成文字的“系统一 / 决策模型”，和 LLM 分工，不是替代。
2. 快、便宜：几十到几百毫秒；输入按 token 计费，输出不收费。
3. 输出受约束：只能在给定选项里选，可能选错，但不会编出选项。
4. 局限：难题（多步、日期数字计算）明显不如 LLM；结果受选项怎么列、信息放哪里影响；没有记忆、不会规划。
