# 短视频Playwright自动上传复盘与发布文档更新

## 用户要求与范围

用户在CCBaga发布完成后要求：“复盘一下‘点击上传’这样一个自动流程，然后写入短视频发布这里。尤其是使用Playwright时的流程（而不是Claude使用浏览器插件）”。本轮维护短视频发布文档和相关入口，没有再次操作浏览器、上传或修改已发布稿件。

## 核实依据

- 本轮已完成的CCBaga发布记录：`20261014-164400-ccbaga-short-video-published_CN.md`。
- 本期 `制作/B站发布核验.json`：BV1CxpC69ESE，三个接口state0、开放浏览，人工智能tid231、合集9223239、AI声明、六标签、两比例封面。
- 实际脚本 `pw_media.py`、`pw_code.py` 和 `pw_*.js`：完整小文件参数传入页面，不用Claude浏览器插件、不压缩、不分块、不起上传服务器。

## 主要结论

1. 「点击上传」只打开文件选择器；真正可点击的是父级 `.upload-area`，`.upload-text.no-events` 文字不接事件。
2. file chooser打开成功，但标准setFiles报 `DOM.setFileInputFiles: Not allowed`。错误原因未证实，不能推断Chrome某个设置一定能修复，也不能说成自动审批拒绝。
3. 实际成功的是本机读取完整7.2MB原片，base64参数传入Playwright执行的页面JS，File/DataTransfer赋给已有input.files、触发change，再由站点自身上传器处理。分别核对选入文件、开始上传、上传完成。
4. 用户已明确允许小于10MB原片自动上传，并要求将这次流程固化。现行短视频规则按保守的10,000,000字节阈值分流；大文件手动上传，不压缩/分块/起服务。其他平台及替换已发布视频的Playwright上传没有被标成已验证。
5. 标签必须逐个读回；两比例封面先关闭同步、各传一张；Quill getText核对简介；同名隐藏表单与同步开关要先定位。
6. 已授权则读回后点击投稿一次。超时只读检查，防止重复投稿；三个接口核对状态、标题、简介、标签、声明、分区、合集与封面实际尺寸，再更新台账。
