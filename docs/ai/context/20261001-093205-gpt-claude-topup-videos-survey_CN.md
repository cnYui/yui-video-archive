## 跨视频的共性和矛盾

1. **几乎所有路线都要翻墙**；“自己动手”的路线几乎都要填**不是本人住址的账单地址**（地址生成器、AI 生成或地图上找的美国免税州 / 日本地址）。这违反 Google / Apple / OpenAI 的付款地区规则。视频里对封号风险几乎不提，少数提到的：#6P1（被苹果拦下等 48 小时）、#34、#10 和 #32 的礼品卡须知（被拒或封号不退款）、#36 的店规（质保掉订阅，不质保封号）、#6P2 的退款说明（承认可能封号）。
2. **说法互相矛盾**：跨境线上支付是否自动开通（#1 说自动，#8 说默认关闭要柜员开通）；Google 换区是否一年一次（#12 说是，#25 说自己一个月换了两次）；微软邮箱能不能用（#40 教用 Outlook 注册，#39 #36 #22 的说明或店规明确说不要用，#16 #20 演示的账号本身就是 Outlook 邮箱）；接码平台要不要（#1 #12 建议用，#8 说不可用）；学生优惠“没有条件”（#19）与官方页面写的“美国大学生”；5 小时限额只限 Plus（#17，8/27）、Plus 和 Pro 都有（#30）、官方 9/29 称不会重新启用（#29）。
3. **时效**：多数录于 2026-08～09；#6（2025-09）、#25（2025-09）、#12（画面推算 2025-10）已过一年；2026-09-29 的额度调整之后，凡是写套餐倍率、5 小时限额的内容都可能过期。发布日期多数视频不标，是我从画面日期、账单日期推算的，笔记里都标了“不确定”。
4. **“礼品卡最安全”的说法和实际对不上**：#6P1 开头说无风险，结果被苹果拦下；#2 和 #21 完全不提风控。

## 对做聚合教程的含义

- 方法应按“谁付款、账号在哪个区、收款方是谁”归类，而不是按视频；同一渠道有很多条重复视频。
- 本项目对订阅 / 充值 / 防封的口径（`B站互动` 技能 `faq.md`，AGENTS.md「B 站操作要点」）是：先说官方渠道，不引导代充、中转站、盗版，不教绕过地区限制、验证和风控，提醒防骗。按这个口径，这批视频里“自己动手”的路线（填非本人住址、翻墙、接码）和全部代充类都不能原样写进教程，只能作为“有哪些做法、各自为什么有风险”来讲。
- Claude 的订阅覆盖很薄，要写 Claude 部分得另搜一轮（例如“claude 订阅”“claude pro 充值”）。

## 怎么做的（过程和坑，坑已写进 AGENTS.md「批量下载 B 站视频 / 取字幕」）

1. Chrome 插件（用户已登录的 Chrome）打开搜索页，用页面里的脚本取每张卡片的 BV 号。
2. PeanutDL 解析 → 注入全屏 `<a>` 真实点击 → 新标签页 `<a download>` 存盘；一个批处理里“触发上一轮下载 + 解析下面 3 个”，共约 40 分钟。逐个核对：字节数 ÷ 1048576 与页面显示 MiB 一致，ffprobe 全部可读（41 个都是 H.264 + AAC；#37 是竖屏 576×1280，#35 是 1280×640）。
3. 内容：每约 20 秒抽一帧，3×3 拼成带时间戳的拼图（约 130 张）；字幕用 B 站 AI 字幕，**`x/player/v2` 不带 aid 会返回别的视频的字幕（约一半是错的）**，改用 `x/player/wbi/v2?aid&cid`，并用“文件去重、末句时间≈时长、关键词命中、和 whisper 稿对字数”核对；#3、#6 没有字幕，用本地 whisper（large-v3-turbo，CPU）。
4. 分 4 组并行分析（每个视频一份笔记：字幕说的 vs 画面看到的，带时间戳），我读完 41 份笔记，抽查了几处数字回字幕（#24 的 122 元、#25 的 JP¥2,860 ≈ 138 元、#12 的免税州说明），都对得上。
