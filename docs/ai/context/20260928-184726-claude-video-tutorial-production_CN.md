## 出镜预留和计时的做法（建议，待用户确认）

- 出镜画面统一按 16:9 裁：大框（A）和左上角小框（B/C）用同一段自拍，小框裁得紧一点（头和肩）。
- 先出一版“录制用”视频：出镜框里显示这一段要念的稿子（当提词器用）和倒计时。用户对着它录自拍。
- 用户录完，用语音识别把自拍的声音和稿子对齐，再按实际语速重排整条视频的时间（和《原LAI如此》自己配音的做法一样）。用户不用卡着秒数念。
- 录制建议：横拍 16:9，1080p 或 4K、30 fps；人在画面中间、头顶留一点空；背景干净；尽量用外接麦或在安静的房间；开头拍一下手（备用对齐点）。

## 整片 v1（无字幕、出镜占位，2026-09-28 19:5x，`Way to AGI/02_如何使用Claude来低成本的生成视频/制作/00_整片/`）

- 做法：
  - `build_timeline.py`：稿子分 43 段（长段拆成两半只为换画面），按每秒 3.9 个字估时长（汉字 1、英文单词 1.5、数字每位 1.1、逗号 0.9、句号 1.6），每段后多留 0.6 s、每个画面后多留 0.4 s；作品展示固定 23 s；“这里放你自己的档位”那段留 10 s；角色那段至少 38 s（录屏剪辑 23.2 s）。输出 `timeline.json` / `timeline.js` / `分段时间表.md`（录制时对照：每段的开始时间、画面、版式、要念的话）。
  - `prep_media.py`：GPT-6 10 s 片段、屏幕录制全部帧（原尺寸）、第 4 期片头片尾帧、第 4 期静帧、各种图；`data.js` 放第 4 期 S04-31/32 的配音波形、逐句时间、嘴型；`audio/mix.wav` 只有作品展示原声、BGM 示范（BGM 那段，bgm.wav 30 s 起，−8 dB）、“嗒”“叮”两个音效。
  - `index.html`：32 个画面 + 引擎。出镜位按版式在大框（A：120,150 1156×666）和左上角（B/C：48,48 696×402）之间移动 0.7 s；版式 B 左下是本章目录（开场 / 原理 / 拆解 / 成本，当前项橙色竖条）；出镜框右下角写当前段号（P01…），录制时对着分段时间表念。字幕带（y 930 以下）空着。
  - 动作那段从鲸鱼娘动作帧里挑了：台本层 抬手、数一二三（带数字）、叉腰、好耶；自动层 小手势（手放胸前 → 合手 → 轻摊轮换）、句末点头、看向内容。嘴型那段用第 4 期真实的逐帧嘴型数据驱动。
  - 屏幕录制那段按内容剪辑（不是统一倍速）：走路帧 → 手臂 / 手 / 眼睛 / 整个小人的字符底稿（放大、放慢）→ 第 36 秒它自己挑毛病（停住、框出）→ 可疑小黑框 → 结论不是画错 → 走入时间条 → 节奏对了。剪辑表在 `S.character` 的 `CUTS`，框选坐标按原片 1402×1020 量的。
  - `render_all.py`：4 路并行（开渲前查了进程，没有别的渲染），每路一段帧 → `parts/` → 拼接 + 混音。`--stills-auto` 每个画面出一张检查图，`--stills t…` 出指定时刻。
- 自查时改掉的：`</script>` 写在内联脚本的字符串里会提前结束脚本（改成 `<\/script>`）；本地图片画到画布上不能读像素（扩散示意改成另画一张噪点图叠上去）；GPT-6 画框、表情表、日报画面的标签压到标题（挪进画框里）；BGM 那页“正在播放”压标题；屏幕录制按统一 2 倍速时放大镜头对不上字符底稿（改成按内容剪辑）。

### 用户录完以后怎么对齐（下一步）

1. 用户的自拍（带声音）→ 抽音频，语音识别拿到逐句 / 逐词时间，和稿子 P01…P40 对上，得到每段实际的开始和结束。
2. `build_timeline.py` 改成读实测时长（没念的段按估时），画面里按短语出现的元素（`at(段, 短语)`）会跟着走；需要的话用逐词时间把短语时刻对准。
3. 自拍抽帧，由页面画进出镜框（大框 / 左上角 / 移动都跟现在一样），不再是占位。
4. 字幕按录音生成，放在 y 930 以下的字幕带；混音：人声为主，作品展示原声和 BGM 示范压在人声下面，整片 −16 LUFS。
