## 结论（细节见规范和分析）

- 量化（10 条中位）：语速 5.2 字/s（含停顿），停顿 ≥ 0.25 s 每分钟约 5 次（几乎一口气），一个逗号段 9 字（P90 14），一句 22 字，每分钟 10 个数字，问句每分钟 0.5 句。
- 骨架：钩子（最反常识的事实 + 数字，前 5 秒）→ 背书（日期 + 机构 + 期刊）→ 拆机制（“先说清楚”“怎么找到的？”）→ 加码 / 对照（前情、纪录、代价，全是数字）→ 泼冷水 → 收尾金句（对仗 / 反转，能单独转发；短条不喊关注）。
- 播放 16.9 万 / 12.8 万 / 5.7 万的三条和几百播放的几条写法一样，差在题材（死 / 脑 / 疼 / 你的孩子）。写法是底线，选题和第一句决定上限。
- 不学：把两项研究接成一条线讲（人猴胚胎那条）、“不是……是……”、“炸裂”。

## 过程和坑

- **SnapAny 免费额度只够 4–5 次解析**，第 5 次起弹「开通会员」（月 ¥45 / 年 ¥188 / 5 年 ¥399），没付费；用它下了 4 个。解析结果的“下载视频”是 B 站 CDN 直链，页面里 `fetch` 跨域能读。剩下 8 个在已登录的 B 站里用 B 站自己的接口（`x/web-interface/view` → `x/player/playurl?…&qn=64&fnval=0&platform=html5`）取同一类 CDN 链接。
- 浏览器 → 本地：多个 blob 拼成一个包（8 字节头长度 + JSON 头 + 文件字节）一次 `<a download>`，本地 `unpack.py` 拆。
  - **space.bilibili.com 是单页应用，点 `blob:` 链接会被当成站内跳转**，页面被带走、内存里 6 个视频丢了；改在 `api.bilibili.com/x/web-interface/nav`（纯 JSON 页）里做。
  - 同一标签页第二次自动下载被 Chrome 拦，换新标签页。
  - 插件的标签页组中途被关过一次（不是我关的），内存里的数据丢了重下：拿到东西尽快存盘。
  - 后台标签页的定时器被节流，SnapAny 的解析轮询很慢。
- `x/player/wbi/v2?aid&cid`（不签名）拿 AI 字幕时有时无：同一批第二次请求 6 个返回空，重试 2–3 次都拿到了。12 个都核对过：末句时间 ≈ 时长、内容和标题对得上、互不重复。
- 识别质量：这个号语速快、配乐，whisper（large-v3-turbo）和 B 站 AI 字幕都错得多，而且错的地方不同（whisper：“痛结系号”；B 站：“余秀G1”“当代玄武协”）。校对稿是两份对照按上下文改的，没听原片，拿不准的标 〔?〕。节奏统计只依赖时间和字数，不受错字影响。
- 删除临时文件的 Python（`os.remove`）被 dcg 钩子拦；改成把临时文件写进 scratchpad，不删。
