## 图形界面用法

来源是官方文档 + 源码。**我没能在图形界面里完整走完一遍**（见下面“意外录制”），命令行那条线是实测过的。

### 录制条（HUD）按钮分工（源码 `LaunchWindow.tsx` + 中文文案）

- **写着源名的按钮（默认“屏幕”）= 选源。** 点开弹出选源窗口，“屏幕”“窗口”两个标签，点缩略图再确认。
- **最右边的圆点 = 录制。** 没选过源时它的提示写“请选择要录制的源”，点它会先弹选源窗口，选完自动开始录制；选过源就直接开始。
- **“使用系统光标”是光标模式开关，别点。** 源码提示：“使用系统光标：将关闭自动缩放和光标效果”；默认的“可编辑光标”把光标当数据单独记录，自动放大才有点击可用。
- 其他：系统音频、麦克风（有电平表）、摄像头、设备设置、打开工作室（编辑器）、打开笔记（提词器，Windows 上不会被录进画面）、语言、隐藏、关闭应用。
- 没有区域录制，只能录整屏或单个窗口，之后在编辑器里裁剪。
  - **录窗口只录窗口内容**（实测：窗口下缘压在任务栏下面，录出来也没有任务栏）；录整屏会录到一切，包括通知弹窗。
  - Windows 上录制条和 Notes 窗口不会进画面（文档）。
- 3-2-1 倒计时关不掉。录制中可以暂停、重来、取消（丢弃）、停止。停止后自动打开工作室。

### 自动放大

- 录制在编辑器里打开时自动跑一遍；没出来就点时间轴工具栏的魔法棒 → “Automatic zooms”，它会提示有没有找到。
- **只认点击**：停留、指着讲、打字都不算。开头 2.5 秒和最后 1 秒保持全景，所以开头留一个空拍。
- 每个放大块可改：倍数（1.25 / 1.5 / 1.8 / 2.2 / 3.5 / 5×）、聚焦（Auto 跟随光标 / Manual 固定点）、3D 镜头。
- 手动：`Z` 在播放头加一个放大（默认 1.8×、焦点在中心），`Ctrl+D` 删除；工具栏的“自动对焦”十字准星打开后，所有放大都跟随光标。
- 终端打字段落不会自动放大，要手动加。
- 手动放大 + 手动聚焦不需要光标数据，别的录屏工具录的视频导入后也能用。
- 按源码，图形界面的自动放大会等视频时长探测完再算，应该不受命令行那个 bug 影响（**没实测**）。

### 画面、标注、剪辑、导出

- **满屏无留白**：右侧浮动面板 → “Composition（构图）”：背景、阴影（无 / 轻 / 中 / 强）、内边距、圆角、Format。Format 选 “Original（原始）”，内边距、圆角设 0，阴影选“无”。（这几个字段的效果在命令行项目里验证过，面板控件名来自文档。）
- **打码**：`A` 加标注 → 类型“模糊”（平滑 / 马赛克，矩形 / 椭圆），把区间拉满出现 API key 的所有时间段，再逐帧拖动检查。
- 剪辑：`T` 在播放头放一个 2 秒的裁剪区（拖边调整），`S` 变速，`V` 录旁白，`M` 加音乐，`Space` 播放，`Ctrl+S` 存工程（`.openscreen`，保留所有可编辑的层；导出的视频不能再编辑）。
- 转写（本机 Whisper）：**第一次要下载约 264 MB 的模型（huggingface.co）**。那次意外录制的编辑器打开后不到 20 秒就出现了 42 MB 的 `.partial`，说明打开录制时可能自动开始下载。
- **导出**：右上角“导出”，先选目的地：Web / YouTube（MP4 1080p 60 fps）、Social（同上 30 fps、码率更低）、Studio（MP4 原始分辨率、按项目比例，60 fps）、README GIF（480p、15 fps）。“高级”里：MP4 分辨率 720p / 1080p / Source，帧率 24 / 30 / 60，H.264 / H.265；GIF 帧率 15 / 20 / 25 / 30。码率不可调（1080p 约 8 Mbps）。然后在原生对话框选保存位置。
  - 你的成片是 30 fps：选 Social，或在高级里选 30。

## 命令行（Store 版）

- 没有 `openscreen` 命令，要用完整路径。实测 `help` 能跑：
  `C:\Program Files\WindowsApps\EtienneLescot.OpenScreen_1.13.0.0_x64__hedpjctvqwhq0\app\Openscreen.exe help`
  - 路径里的版本号会随更新变，用 `Get-AppxPackage EtienneLescot.OpenScreen` 的 `InstallLocation` 找。
  - 命令行加 `--user-data-dir=<目录>` 可以不碰应用自己的数据目录，但录制会存到那个目录，不是应用默认的录制目录。
- 常用：`sources`、`record --window "<标题>" --duration 30 --project demo.openscreen --json`、`export demo.openscreen -o out.mp4 --quality source --json`。
- **`--auto-zoom` 对命令行录的项目返回 0 个放大**（v1.13.0 的 bug），绕法和脚本见 `20260929-125117-screen-zoom-tools-trial_CN.md` 文末。导出固定 H.264 60 fps，要 30 fps 用 ffmpeg 再转。

## 意外录制（事实与处理）

- 我在临时数据目录里启动便携版 OpenScreen 图形界面、通过调试端口做验证时（约 12:57），出现了一段 **8.5 秒、1920×1080 的整屏录制**。
  - 我没有看内容，已删除（单个文件 `rm` 没被拦）；同一目录里没有留下缩略图或图片。
  - 遗留在临时目录的 `os-gui-data`：一个工程 JSON（不含画面）、一个 42 MB 的语音模型未下完的文件。
- **起因没弄清。** 我用调试端口点的是“选源”按钮，按源码它只会弹出选源窗口，不会开始录制；当时用户也在场，可能同时点了录制。不能确定是谁触发的。
- 教训：
  - 驱动别人的录屏软件前，先读源码确认每个按钮的含义；
  - 只驱动“窗口”源，不给它录整屏的机会；
  - 这次我一开始把两个按钮的分工判断反了（以为写着“屏幕”的是录制），是读了源码才纠正的。
