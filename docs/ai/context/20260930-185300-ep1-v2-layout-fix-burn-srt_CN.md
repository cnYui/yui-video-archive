v2 出镜版渲染完成后，用户发现第一个场景切换附近有视觉异常，要求抽帧诊断。

## 诊断过程

### 截图特征

用户提供的截图显示：布局 B（pip 小框 + 目录）的场景里，左上角出镜框正常，但左下角出现了一个白色便签卡片，内容是手写文字，和出镜框形成奇怪的上下堆叠。

### 抽帧定位

列出全部 34 个场景的布局（A/B），找到 10 个布局切换点。用 `render_all.py --stills` 在两个最可疑的切换点密集抽帧：

- **S04(A)→S05(B) 42.07s**：第一次 A→B 切换，用户截图疑似这里
- **S32(B)→S33(A) 662.77s**：B→A 切换，截图里"P81"段落在这附近

### 根本原因

`engine.js` 第 42 行，布局切换时给内容淡入设了 0.3 秒的延迟：

```js
// 修复前
const delay = prev && prev.layout !== s.layout ? 0.3 : 0;
```

但相机从 A 大框移动到 B 小框（或反向）的动画时长是 `MOVE = 0.7` 秒。这意味着在 lt = 0.3s 到 lt = 0.7s 的 0.4 秒窗口里，相机还在中间状态，新场景的内容已经开始淡入。

S05（terms）场景的词卡位置是 `{left: 60, top: 500}`，正好在 pip 出镜框（`CAM.P = {x:48, y:48, w:696, h:402}`，底部 y ≈ 450）正下方，两者同时可见时视觉上像叠了两张便签。

S33（summary）场景的内容在右侧 `RX = 1400`，远离相机动画路径，所以 B→A 切换没有问题。

### 验证

修复后抽帧：42.40s 帧（相机动画进行到一半）屏幕干净，无词卡；42.77s 帧（lt = MOVE = 0.7s，相机刚落定）内容才开始以接近零的 opacity 淡入——时序正确。

## 修复

**文件**：[`engine.js:42`](../../../AI震惊瘫坐时代计算机研究生必须掌握的技能/01_别再用VSCode了/制作/00_整片/engine.js)

```js
// 修复前
const delay = prev && prev.layout !== s.layout ? 0.3 : 0;
// 修复后
const delay = prev && prev.layout !== s.layout ? MOVE : 0;
```

这个修改覆盖全片所有 10 个布局切换点（S04↔S05、S05↔S06、S06↔S07、S11↔S12、S12↔S13、S19↔S20、S20↔S21、S21↔S22、S22↔S23、S32↔S33）。

## 经验

布局切换的内容淡入延迟必须 ≥ `MOVE`（相机动画时长），否则内容会在相机移动过程中出现。本期 `MOVE = 0.7`，原来的 `delay = 0.3` 是留白板版时的值，嵌入出镜版后没有更新。下次新建场景时注意。
