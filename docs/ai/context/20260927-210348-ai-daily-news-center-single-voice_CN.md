## 做了什么

### 居中（技能规则 + 引擎）
- 技能「用户定下的规则」新增“居中”一条：开场日期大字、今日要闻卡、每条新闻的标题卡（大字和收起后的小标题）、来源行、正文卡片、回顾卡，都以画面中线 x = 1170（和字幕同一条线）居中；右上角目录除外；正文左右两栏对称，右边不压目录、左边不压角色。
- 引擎：
  - `core.js` 的 `CX` 从内容区中线 1360 改成 `W / 2`（1170）。
  - `components.js` 的 `c.title` 收起后按中线居中（算出左边 `L = CX − 宽 × 0.6 / 2`）。原来收到左上角 x = 440。
  - `scenes.news.js`：
    - 来源行居中。
    - 正文半宽 `half = min(690, 目录左边 − 24 − CX)`：左栏要点 `CX − half … CX − 20`，右栏截图 `CX + 20 … CX + half`。8 条时目录宽约 438，两栏各约 648 px，上沿都在 y 236。
    - 没截图时整行居中；回顾卡 1560 宽居中（两栏）。
  - 开场卡片、日期大字本来就用 `ENG.CX`，跟着居中。
- 两栏变窄后，要点从 ≤14 字宽改成 **≤12 字宽**（`make_episode.py` 的 LIMITS），字号约 41–52 px。
- 验证：用首期内容和网页版配音按新版面完整出片（`AI日报/_试跑_API/`，2340×1080，H.265 上传版 8.50 MB，事实核对 0 处提示）。抽帧看：标题、来源、两张卡、字幕都在同一条中线上，右上目录不动。

### 整期一次配音
- `daily.py build`：chunk_voice 分批后，默认把整期合成一批 `C01`（scene = ALL），分批结果留在 `配音/chunks_batches.json`；`--batches` 保留分批（只在退回网页版配音时用）。重跑 build 时先把分批版放回去，免得 chunk_voice 以为分批变了而拒绝。
- `tts_api.py`：一次请求生成整期音频，超时从 180 秒放宽到 600 秒；台本改过就整期重新生成，旧版本挪进 `配音/raw/_旧稿_*`；读得不好就 `--only C01` 整期再生成一版（约 $0.08）。
- segment_audio 本来就按每段的文字在整批音频里对齐，所以一整段也能切开、对上字幕（按句切）。
- 技能第 4、5 步和踩坑表已同步。
