# 短视频第 1 条《设计师喝了两杯咖啡，Claude 一次出四版》（Claude Design 官方演示的二次剪辑，竖屏 28.3 秒）

2026-10-04 09:34 起（本机时间），成片 10:50。目录 `短视频/01_ClaudeDesign设计师用法/`（README 有文件表、台本、版式、重做命令、踩的坑）。

## 用户要求（三条消息，原话）

1. “之后我也要做短视频，你尝试把这个视频剪辑成20秒到30秒”（给了 `Downloads\videoplayback.webm` 4K 画面 + `videoplayback (1).weba` 音频）
2. “配音可以使用曼波配音做翻译，因为视频里是英文，短视频也是需要遵循双语字幕的要求，你可以看一下其他的分集skill中字幕的要求是如何设定的”
3. “短视频的话，需要你把这个长视频的两个不冲突的分镜放在同一个画面中出现（比如当前视频里一个人脸一个电脑操作的画面），你控制好时长，同时用ai配音讲解，就是进行二次剪辑，把视频里的观点更快更密集的讲出来”

中途另一个会话（“浏览器插件页面记录”，在写技能 `short-video`）转告用户当天定的规矩：竖屏 = 横屏 2340×1080 竖过来 = **1080×2340**；短视频不加悠一片头片尾；台本照 AI大圆镜（`docs/台本风格_AI大圆镜.md`）。AGENTS.md 里都已有对应条目，我核对过。

## 结果

- 成片 `成片_竖屏_中英字幕.mp4`：1080×2340、30 fps、28.28 s、6.5 MB、-16.0 LUFS（真峰值 -3.7 dBFS）；另有无字幕版、540×1170 手机预览、三份 SRT（时间从 0 起）。`qa_mix.py` 自查：规格通过，每句开口和时间线差 +5…+10 ms。
- 内容：把 102 秒的原片压成 9 句中文讲解（曼波，1.0× 不加速），上框 Nate 的人脸、下框电脑操作（从 4K 按裁切框放大），顶上两行大标题一直在；字幕中文 52 px + 英文 30 px（项目双语标准，竖屏每条中文 ≤ 17 字宽）。
- **还没做 / 等用户**：听配音（N01 “设计师”、N09 “掌舵” 被识别成别的字，是这个声线的老毛病）；发哪个平台、进哪个合集（现在在顶层 `短视频/`，按用户的新目录规则以后归 `<合集>\短视频\`）；要不要封面（技能里有 `make_cover.py` 三比例）；投稿没做。

## 做法（和技能里的 HTML 引擎是两条路，这条是 ffmpeg 直接剪）

1. **看素材**：转写英文（faster-whisper large-v3-turbo）、每秒一帧联系表、`gridframes.py`（抽帧叠 120 px 坐标网格）逐个量裁切框和切点。原片是官方 Claude 频道 2026-10-02（美西）的《Build an App With Claude Design》，简介原文核对过（脚本开头抄了出处）。
2. **台本**：先按“解说词”写了一版（11 句），后来读到 AI大圆镜 规范和技能 `short-video` 后重写：钩子 = 两杯咖啡（视频里确实喝了两次，不夸大成“两杯咖啡的工夫做完”）→ 答案 → 拆机制 → 官方原话（简介最后一句）→ 官方金句；只引最关键的一句原话（评论 “Bigger bird.”）；英文字幕写我们这句中文的英文，不用第三人称代词称呼 Nate。
3. **配音**：Fish 故事工作室空白项目 + 赛马娘（曼波欧耶版）+ S2 Pro。**第一次生成 10 句，总长 30.4 s，比估的长；第一版我用 1.15× 加速凑时长，读了技能后改回 1.0×（技能规定别靠加速凑时长）并删句**，重新生成（点“重新生成”是整稿重来，9 句全是新 take，所以第一版的识别核对作废、重做）。共生成 2 次、导出 2 次。
4. **画面**：版式照技能 `layout.md`（标题 280–570、上框 590–1165、字幕 1195–1305、下框 1325–1900，1000×575 外框 + 972×546 画面）；每句话的上下框各取哪一段原片、怎么裁切写在 `shots.json`；`render_clips.py` 把 26 个子镜头从 4K 裁切 + 变速成小片段（人脸 0.94–1.0×、操作画面 0.9–2.3×），`render.py` 用 ffmpeg 叠静态层（PIL 画的米白底 + 点阵 + 标题 + 外框）、圆角蒙版、ASS 字幕、混音。
5. **同步**：配音的每句开口 = 画面切点 + 0.05 s，句间空 0.12 s，字幕开口时间用配音的能量低点量过；最后一句念完画面再停 0.8 s（技能规定）。

## 踩到的坑（也发给了写技能的会话）

- Fish 改区块：窗口大小在操作中途变，按坐标点区块点歪、误删两个区块 → 用 `find` 的 ref；“重新生成”整稿重来；导出 zip 里 mp3 / wav 混着；“00:00:42:25” 是播放头。
- x264 要偶数尺寸（972×547 → 972×546）；faster-whisper 喂 numpy 数组按 16 kHz 解释；`Remove-Item` 对 `build\stills\*` 被拦（换目录名）；PowerShell 没有 here-doc。
- 切点要逐帧看（全屏人脸 30.0 s 才干净、39.7 s 起模糊转场；第二杯咖啡 76.4 s 才出现；框上的文件名标签别被裁一半）。
- 人脸素材只有约 26 秒，28 秒的成片要复用：Hi-Nate 框首尾各出现一次（有意做成首尾呼应）。
