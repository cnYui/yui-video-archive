# 日报 routine 改竖屏 + 四个平台（2026-10-05）

## 用户要求（原话）

- “抖音、视频号、小红书你创建一个 "AI每日日报" 合集。之后日报的 routine 都是竖屏，并且都要发四个平台”（发 10/5 竖屏版的过程中补的）。
- 同一轮里：“标题就用 1，然后四个平台同时发这个短视频”（= 10/5 竖屏版标题 ① + 授权发布）；“你能不能用 js 脚本帮我上传这些视频” → 我提了分块上传，权限分类器拦了第一次读页面的 JS 调用，用户：“别这样”“等我上传吧”。

## 做了什么

### 1. 三个平台各建「AI每日日报」合集
- 抖音：内容管理 → 作品合集 → 创建合集（标题 AI每日日报、简介 51 字、封面 1080×1080 = `AI日报/素材/合集封面/封面_合集_1x1.png`：白底、鲸鱼娘蓝大字 + 挥手的鲸鱼娘，`scratchpad/make_series_cover.py` 复用 `make_cover_white.py` 的鲸鱼娘合成）。创建成功，状态“待发布”（合集里还没视频）；**发布页下拉里选不到，要先发布这条，再在合集页“编辑合集 → 点击添加作品”加进去**（10/5 这条发完补；之后合集里有视频，下拉里就有）。
- 视频号：发布页内联“添加到合集 → 创建新合集”（标题 ≤ 10 字、创建后不可改，“AI每日日报”6 字）；小红书：发布页“内容设置 → 加入合集 → 创建合集”（名称 ≤ 20、简介 ≤ 50）。这两个要上传视频后才看得到发布表单，等用户拖好成片后在填表时建。

### 2. 竖屏版通用化（`make_vertical.py`）
- 引擎：`AI日报/skill/ai-daily-news/assets/vertical-engine/`（`index.html` + `engine.js`），脚本：`scripts/make_vertical.py`（`all` = data → check → stills → mix → render → finish，各步也能单跑）。从 10/5 手工版改：新闻条数 N 不写死（3–8）、来源截图 / 橙框 / 数字卡都可以没有（没有截图的条目框里放机构名 + 标题；清单行数 = ⌈N/2⌉）、背景印花按日期种子随机、鲸鱼娘 / BGM / 混音 / 渲染都一样。
- **字幕自动拆条**（10/5 手工版靠 9 条手动断点 + 3 条合并修）：真实像素字宽（PIL 量同一个字体文件，和浏览器差 ±1.5%，上限 950 px 拆、浏览器里 940 px 硬上限校验，超了自动收紧 15 px 重拆最多 3 轮）；jieba 分词 + **词性规则**给断点加罚分（介词 / 副词 / 助词 / 连词 / 代词后面不断、动词后面接宾语不断、方位词和助词前面不断、名词 + 名词少断）、受保护片段里不断（英文词 / 型号 / 数字 + 单位 / 日期 / 书名号 / 引号）、AI 圈常用词和台本标题里的 3–8 字词组加进 jieba 词典（“智能体”“提示词”）、日报横屏版里的几字短条先合并再拆。不理想的写台本 `vertical.cuts`。
- 来源截图：`snap_sources.py` 新增记 `h1box`（标题在截图里的位置），竖屏版用它画橙框；旧的 snaps.json 没有就不画框。
- 其余：并发锁 `制作/vertical/.lock`（试跑时两个进程同时跑抢 `parts/`）；`finish` 出 `封面_3x4_1080x1440.png`（第 0 帧 y450–1890）和两个上传版；渲染路数按空闲内存挑（≥ 10 GB 4 路、≥ 6 GB 3 路、否则 2 路）。

### 3. `daily.py` 改动
- `render`：build_timeline → mix_audio → bilingual_subs → 封面（`make_cover_white.py`）→ `make_vertical.py all --upload` → review；`--horizontal` = 旧的横屏退路。`encode_upload` 加了 `vf`（缩到 720×1560）。
- `review` / `build_publish_info`：投稿信息.json 顶层仍是 B 站（`title` 现在是事实陈述标题），新增 `titles`（四个平台）、`video_h264`、`cover_3x4`、`douyin` / `xiaohongshu` / `weixin_channels` 三个块；标题优先用台本 `titles`（逐个校验限长），缺 / 超限用 `auto_titles`（第 1、2 条的 rundown_key 拼）。
- `gate`：新增竖屏检查（H.264 上传版 ≤ 9 MB、成片 1080×2340、`制作/vertical/qa.json`、3:4 封面、四个平台标题限长）；`published --also 抖音 --also 小红书`。
- `make_episode.py`：台本可选字段 `vhook` / `vbigs` / `titles` 的校验（只给提示）。

### 4. routine 和文档
- `ai-daily-news-produce` 的提示词和说明已更新（竖屏、四个平台、上传限制、视频号跳过、推送写各平台结果）；技能 `SKILL.md` 第 6 步（出片）、第 7 步（复核提示词加竖屏静帧）、第 8 步（四个平台，8a B 站 / 8b 抖音 / 8c 小红书 / 8d 视频号）、第 9 步改了；AGENTS.md「三个合集和发布平台」表和《AI每日日报》一节改了。

## 没解决 / 要用户知道

1. **视频号**：上传框在 wujie 的 shadowRoot 里，插件看不到、`file_upload` 传不了；成片 32 MB 也超过 10 MB。routine 里**不发视频号**（推送里写明、给成片路径），要发得用户拖。我提的 JS 分块上传被权限分类器拦了、用户说“别这样”，所以不再试。
2. **画质**：routine 传给 B 站 / 抖音 / 小红书的是 ≤ 9 MB 的上传版（720×1560、约 140 kbps），比今天手工发的原片糊（静帧文字还清楚，转场帧会差一些）。要原画质只能用户拖成片。
3. **没在真实 routine 里整条跑过**：`daily.py render` 的串联（build_timeline → mix_audio → … → make_vertical）只靠分段测试；明早 04:32 第一次真跑，竖屏出不来会用 `--horizontal` 退路只发 B 站。
4. 抖音 / 小红书的发布流程（8b / 8c）是照 `short-video/references/publish.md` 写的，用户拖好成片、我把 10/5 这条发完后用实测补；routine 里 `file_upload` 能不能找到这两个页的视频上传框还没验证。
