# 银魂像素游戏宣传片 v2：成片检查与重剪依据

## 检查对象

- 成片：`游戏素材/银魂/录屏素材/2026-10-04_精彩展示/银魂像素游戏_高能展示_30秒_横版.mp4`
- 当前合成脚本：同目录 `build_showcase.py`
- v2 方案：同目录 `优化方案_v2.md`

## 成片本身的证据

1. 视频流标称 1920×1080、60 fps，但画面时长约 29.683 秒；音频时长 30 秒。导出时画面和音频时间轴没有完全一致。
2. 0–4 秒主要是标题菜单的连续静态画面，音乐开头的轻前奏没有画面动作承接，形成“无声静态标题图”的观感。
3. 成片抽帧显示多个镜头保留了顶部血条、底部对白框、操作提示和游戏菜单；这些 UI 信息与宣传片叠加标签互相争夺视觉层级。
4. 当前脚本仍使用 17 段旧镜头表：每段统一缩放到整屏并叠加左上角标签、白闪，四格 / 分屏 / 画中画通过多路 ffmpeg 输入实现。`source_args()` 把 `-ss/-t` 放在 `-i` 后，存在多路输入起点错位风险；分屏使用 `scale=960:1080`，会把 16:9 画面横向压扁。
5. 中间文件 `13_return.mp4` 为 0 字节级别的无效片段，和旧镜头表中的“终章 两年后归来”不一致；因此旧成片无法作为 v2 的时间轴依据。
6. BGM 与音效文件均为 30 秒、48 kHz、双声道 PCM；频谱图可见现有 BGM 是截取后的独立音轨。v2 方案指定改用源曲 135.205 秒起的 25.5 秒段，再用结尾两记重音补至 30 秒。

## v2 执行约束

- 原成片、旧镜头表和旧中间文件保留，不覆盖。
- v2 使用统一 60 fps 时间轴，所有素材先按源片段时间精确读取，再在 Python/PIL 中做最近邻放大、裁切、黑边、闪白、震屏、分屏与文字层。
- 每个 v2 镜头必须标出宣传片时间、源文件、源起止、手法；先验证源时长和首尾帧，再渲染。
- 输出视频、BGM、音效三条文件的起点统一为 0 秒；完成后逐秒抽帧并检查音乐重音点、UI 清理、画面比例和结尾 Logo 层级。

## 本轮结果

- 已生成 `银魂像素游戏_高能展示_30秒_横版_v2.mp4`、`_v2_BGM.wav`、`_v2_音效.wav`，三者均为 30.000 秒；视频为 1920×1080、60 fps。
- 已抽查冷开场、6.375 秒标题爆点、14.05 秒急停黑屏、25.5 秒收尾梗和 27.05 秒 Logo。
- 方案中的部分源时间属于原始 WebM 录像，而当前精彩片段重新从 0 秒计时；脚本目前按精彩片段实际时长夹取，避免黑屏，但少数镜头仍需下一轮用原始 WebM 重新映射，才能恢复精确动作帧。
