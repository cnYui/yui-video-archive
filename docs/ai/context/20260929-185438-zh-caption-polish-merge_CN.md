## 顺带改的代码：为什么、怎么验证

- **验证**：把新旧函数原样抠出来跑（node / python）。

  - 第 02 期 131 条字幕里没有任何括号，所以对已发布的期数没有影响。

# 中文字幕精修与括号注释（含中英双语）

## 适用场景

- 口播、访谈、科技/AI 解说类视频，字幕已由转写生成，需要“只改字幕文字，不动画面和声音”的精修。
- 用户说：删口癖/去语气词、修字幕错字或专有名词、给引用或术语加括号注释、加英文字幕/双语字幕、导出前检查字幕。
- 不适用：剪掉音频里的口癖或停顿（走口播剪辑流程）、字幕样式设计。

## 开始前先确认

- 先通读全部字幕，弄清现状：哪些是用户手动改过的（包括用户自己加的括号），哪些是识别错误，哪些是拆分留下的碎片。
- 当前字幕样式是否隐藏标点、一行大约能放多少字（决定注释能写多长）。
- 专有名词的正确写法：以用户已经改过的写法为准（例如用户写成 “Opus5.5”，全片就统一成这个写法）。
- 用户的范围要求：说“其他不变”时，除目标内容外一个字都不动。
- 使用双语：中文全部定稿后再做英文。

## 流程

1. **删口癖（只改字幕文字）**
   - 删除：呃、嗯、额；句首或句中的“啊，”“哦”；句尾当口癖用的“啊”（“做做自媒体啊”→“做做自媒体”）。
   - 保留：有语气作用的“呀、吧、呢、吗”；口吃重复（“一一部”“攻攻击”）默认保留，除非用户要求清理。
   - 整条只有口癖的字幕：把这条**隐藏**（透明度设为 0），不要把文字清空。清空后这条字幕会失去对应的词，之后无法再改回来，做双语时自动翻译也可能因此失败。
   - 告诉用户：声音里的口癖还在，只改了字幕。
2. **修正识别错误**
   - 同一个名词全片统一修正，不要只改第一处。
   - AI 类视频常见误识别：Opus → “OPS”/“OPPO”，Claude → “Cloud”，OpenClaw → “OpenCloud”，3A → “三 D3A”。
   - 拿不准本意的，标出时间点问用户，不要猜。
   - 疑似引用张冠李戴（把 A 说的话安在 B 身上）时，提醒用户，由用户决定怎么改。
3. **清理拆分残留**：用户手动拆分字幕后，检查极短（约 0.3 秒以内）、只剩残字的字幕（例如单独一个“式，”）。这种会在画面上闪一下：把它**合并进前一条字幕**（画面上看不出变化），不要清空文字。
4. **加括号注释**：规则见下文。
5. **双语字幕**：规则见下文。
6. **终检后再导出**：见“完成前检查”。

## 括号注释规则

- 目的：帮观众听懂引用、典故、术语和冷门信息。用户给的示范：说到“给猴子一部打字机”，括号里加“这是无限猴子定理”。
- 格式：全角括号“（）”，紧跟在被解释的词或引用后面；一般控制在 12 个字以内；点名典故/定理用“这是……”，术语给最短的定义。
- 该加的类型：

  | 类型 | 例子 |
  |---|---|
  | 引用、典故 | 那给猴子一部打字机（这是无限猴子定理） |
  | 术语缩写 | 没想到是这样实现 AGI（通用人工智能）的 |
  | 技术概念 | 在使用了 Loop Transformer（循环复用网络层的架构）之后 |
  | 行业黑话 | 做一个 3A（高成本 高体量 高质量）大作 |
  | 冷门产品/项目 | 半年前 OpenClaw（开源 AI 智能体）刚出来的时候 |
  | 支撑观点的背景事实 | 黑神话悟空一些场景（多扫描自山西古建筑） |

- 不加：大众熟知的名字（GPT、豆包、马斯克等）；自己不能核实的内容；用户已经自己加过括号的地方（不改、不叠加）；不在注释里反驳或纠正说话人，除非用户要求。
- 位置：放在第一次出现的地方；那条字幕太短（1.5 秒左右以内）读不完时，放到相邻、提到同一概念、时间更长的那条。
- 密度：大约每分钟一条，宁少勿滥。
- 可读性：加注释后中文字幕不超过两行，超了就缩短注释。如果字幕样式会隐藏顿号等标点，别写靠“、”分隔的并列（会连成一串），改成不需要分隔的说法，或用空格分开。
- 准确性：注释是给观众看的事实陈述，只写有把握的；拿不准就不加，并在回复里说明。

## 双语字幕规则（中文 + 英文小字）

- 版式：中文在上，英文在下；英文用小一号的字（约为中文字号的 60%～65%），同样白色、居中，西文字体（如 Inter）。中英合计不超过三行，英文尽量一行。
- 顺序：中文先定稿（删口癖、修错字、加注释都做完）再生成英文；之后中文再改，要检查对应的英文有没有跟着更新。
- 翻译要求：
  - 口语、简洁，按意思翻，不逐字直译。
  - 专有名词保留英文原名：Opus 5.5、Claude、OpenClaw、Gemini、GPT、AGI、Loop Transformer；中文特有名称用通行英文名：豆包 → Doubao，黑神话悟空 → Black Myth: Wukong，UP主 → creator。
  - 中文括号注释也翻成简短的英文括号注释，例如（这是无限猴子定理）→ (the infinite monkey theorem)。
  - 用户自己写的玩笑或更正要保留原意，例如“马斯克（不是马斯克）”→ “Musk (actually, not Musk)”。
- 单独做的中文文字层（没有语音的段落）也要在下面配同样样式的英文小字。
- 自动翻译失败时：先检查有没有被清空文字的字幕，这种字幕会卡住翻译。确实走不通时，可以由 agent 自己翻译，做成与字幕对齐的英文文字层，但要告诉用户这层不会跟着中文字幕自动更新。

## 不要做

- 不要为了改字幕去改源转写：改转写会重新切分同一段里的字幕（实际遇到过把两句话拆开），还可能覆盖手动修改。遇到只能这样解决的显示问题（例如英文词在画面上被拆成 “Ultra code”），告诉用户原因，不要硬改。
- 不要把整条字幕的文字清空来“删除”它：隐藏或合并进相邻字幕。
- 不要改用户手动写的内容和注释。
- 不要顺手改范围外的内容；看到其他问题，列出来让用户决定。

## 完成前检查

- 全片扫一遍：残留的识别错误、同一名词写法是否统一、会闪一下的碎片字幕、注释长度、文字被清空的字幕。
- 双语时：抽几处画面看中英上下位置、字号对比、是否超过三行、有没有挡住人物，英文专有名词和注释是否正确。
- 抽改动处的画面确认：文字正确、中文不超过两行、注释读得完。
- 回复用户时用表格列出改动：时间（分:秒）+ 改后的字幕；说明哪些只改了字幕、声音没变，以及没改的问题和原因。
