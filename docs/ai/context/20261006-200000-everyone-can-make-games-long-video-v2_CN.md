## 引擎（新写的，可以复用）

- `v2\comp.py`：numpy 逐帧合成。Item（画板 Panel / 精灵 SpriteItem / 自定义）+ 入场出场动画 + 关键帧矩形补间；素材 VideoSrc（ffmpeg 管道，按显示尺寸直接缩好）/ ImageSrc（含慢推近）/ GenSrc（PIL 画的活素材）/ FaceSrc（按要的宽高比在 16:9 里裁脸）。画板的粗边和硬阴影预先算成“稀疏像素表”，每帧只改边上几万个像素，整条 307 秒 5 进程约 4–5 分钟。
- `v2\ui.py`（框、贴纸、卡片、键帽、目录卡、数字卡）、`gens.py`（动作墙、视差街景、终端卡、代码窗口、文件夹窗口“双击就能玩”）、`plan.py`（整条时间线）、`render.py`（`still` 抽帧检查 / `video` 并行渲）、`scan.py`（实况录像抽联系表找镜头）。

## 踩的坑

- `playtest.py --help` 会被当成 `all` 真去跑整部游戏（它只认 `--lose / --record / --until`），用 `TaskStop` 停掉，Playwright 的 headless 浏览器随后自己退了。
- 补录“输一次再来”（`E_序章输一次重来\`）时，别的会话（fork）正在给游戏加触屏按键（`20261006-192400-gintama-game-touch-controls_CN.md`）；触屏按键只在触屏下显示，电脑上画面没变，补录的画面和 A 段对得上。
- Whisper 逐词时间在停顿处不可靠（一个字被拉长到整段静音）：剪口播和对字幕都要用音量（−48 dB 静音、−42 dB 有声）修正；EDL 里“一个字被切掉”要看能量不要看 ASR 的词。
- 把 Python 写进 bash 的 heredoc 时，`\\` 会被吃成一个反斜杠：正则和 Windows 路径出过三次错（`\2026` 变成 0x82、`\v2` 变成 0x0b、字符集 `[^'\]` 少一个反斜杠）；路径用 `chr(92)` 或 Edit 工具，写完扫一遍 0x80–0x9f。

## 收尾时又修的几处

- **开场快切没声音**：`plan.build()` 里 `AUDIO.clear()` 放在 `cold_open()` 之后，把开场快切登记的游戏声清掉了；靠分段响度（0.3–4.0 s = −70 LUFS）才发现。已把 clear 挪到最前面，开场快切 BGM −26 / 音效 −23 dBFS RMS。
- **字幕改成照他说的字写**：之前我顺手改了几处词序（“我是做的一个” → “我做的是一个”）、换了词（“用户” → “玩家”、“将近” → “近”）、加了他没说的字（“知道”、“去找”）；全部改回，列在 `字幕核对表.md` 里的 14 处拿不准的词才是我按上下文写的。
- **三处切点**：“飞 | 就是”从能量谷 31.39 s 切（原来切在“飞”的尾音上）、“的 | 因为”切在 35.86 s、“通过这 | 种 AI 工具”中间他停了半秒，压到 0.12 秒。逐个接缝查了能量（开头 / 结尾 30 ms 的平均 > −40 dB 的当可疑），剩下 0 处。
- **A/V 同步**：嘴部动作能量和人声音量互相关，剪后的 face_tl + 人声滞后 7 帧，没剪过的原片 0193 是 7 帧、0194 是 6 帧，一样，说明剪辑没引入偏差（正数是“下巴动得最快总在声音最响之前”的正常现象；原片 / 代理的视频、音频 start_time 都是 0）。
