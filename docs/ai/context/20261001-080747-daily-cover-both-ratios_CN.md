# 日报 10/1：封面只换了 4:3，16:9 还是默认首帧（2026-10-01）

用户：“你看一下 routine，b 站每日新闻的，刚刚发的视频封面忘记设计了，你设计一下，然后去 b 站视频那边修改一下封面”“用浏览器插件来修改封面”。附了一张手机上 B 站空间“视频”列表的截图：10 月 1 日那条的封面是米白底加一小块橙色，9/30、9/29 的是设计好的封面。

## 结论

- **封面其实设计了、也传了，只传进了一个位**。本地 `AI日报/2026-10-01/封面/` 里有 routine 按技能规则做好的封面（“Codex 新插件 / 能做掌机游戏？”，白底两行大字 + 鲸鱼娘 + 左边其余 5 条小字），routine 的运行记录里也有“封面已上传，点完成 / Cover is set”。所以没有重新设计，直接用了这一套。
- 原因：B 站的“封面制作”弹窗现在分成两个位——「首页推荐封面（4:3）」和「个人空间封面（16:9）」，中间有个「双比例同步改动」复选框，**默认没勾**。不勾的话上传只进当前选中的 4:3 位，16:9 位保持 B 站自动截的视频首帧。个人空间、稿件列表用的是 16:9，所以看到默认首帧；编辑页“封面”栏显示的是 4:3，看着正常，很容易被误判为已换好。
- 已用 Chrome 插件补换，线上已生效（见下）。

## 修复（用户要求用 Chrome 插件）

1. 插件新开标签页 → `https://member.bilibili.com/platform/upload/video/frame?type=edit&bvid=BV16qYF6XEYZ`（标签组里原有的 Fish Audio 标签页不是我的，没动）。
2. `.cover-module-main .edit-text`（“封面设置”）用 JS `click()` 打开弹窗（按坐标点没出来）。
3. 勾上「双比例同步改动」（两个复选框都变成 true）→ `file_upload` 传 `封面_16x9_1920x1080.png`（147 KB）到弹窗里 `image/png, image/jpeg` 的输入框。
4. 用弹窗里 4 个 `canvas` 采样：4:3 位和 16:9 位的图层蓝色像素都是 9.9%、浅色 78.4%（旧首帧是 0% 蓝）；右侧手机预览里首页推荐流也是新封面。
5. 点“完成”（`div.button.submit`，文字“完成”，在视口外，`find` 找不到，用 JS 点）。
6. 提交前核对：标题没变；标签 9 个没变；简介 `getText()` 长度 1571、SHA-256 和本地 `投稿信息.json` 一致；合集「AI每日日报」没变。

## 坑和备忘

- 编辑页“封面”栏只显示 4:3，不能拿它判断封面换没换；判断看接口的 `archive.cover`（16:9）和 `cover43`。
- 封面弹窗比窗口高，“完成”在视口外，无障碍树里没有；`Page.captureScreenshot` 在弹窗打开时反复超时，截图内容会错位。视口（`innerWidth` 2143）比截图坐标系（1568）大约 1.37 倍。用 `javascript_tool` 读 DOM / 画布、`element.click()`。
- `javascript_tool` 的 async 函数要在顶层 `await`，否则返回 `{}`。返回值里不要带网址（文件名取前 6 位即可）。
- 封面图文件没动：`封面\` 里的 16:9 / 4:3 / 预览都还是 routine 生成的那一套。
