# 短视频交付包：封面 3×3、标题 3×4 的脚本（2026-10-04 晚）

## 用户原话

- “复盘一下，把这个 我给你素材 -- 调用短视频skill -- 生成视频 封面x3 标题x3 -- 我同意后发布四个平台 这个流程复盘一下”（Tavus 发完之后；image-blaster 那条的会话也收到了同一句）。
- “标题的话，你要给我3x4（4表示四个不同的平台需要的标题，比如微信视频号还有小标题这样的要求等等），你可以具体看一下要求”。
- “封面的话，是3x3，3种每种都要有竖屏、16：9、4：3的封面”。

## 结论

标准流程 = ① 用户给素材 → ② 技能做成片 → ③ **交付包**（成片 + **封面 3×3** + **标题 3×4** + 默认项）一次发给用户 → ④ 用户一句“封面 X 标题 Y 同意”= 授权，四个平台一次填完整、读回核对、点发布、逐个核对线上（用户只拖原片）。Tavus 那条用户插话 14 次，都能落进这四段（9 次是默认值 / 规矩没写、5 次是交付包没有），差距分析和时间对照在 `D:\大疆\短视频\流程复盘.md` 第 1 部分“对照标准流程的差距”。

分工：流程复盘开头的“四段 + 交付包消息模板”、SKILL.md 的标准流程段、publish.md 的授权语义由“视频素材文件夹结构”会话写（image-blaster 那条）；本会话（Tavus）写第 1 部分的差距分析和**把封面 3×3 / 标题 3×4 做成脚本**。

## 做了什么（`D:\大疆\短视频\skill\short-video\`）

- `scripts/make_cover.py`：加 `style: "full"`（满框 C 风格，Tavus 那条用户定的样式）——OpenCV 自动检脸（不写 `target` 时）、按比例自动裁窗（3:4 脸居中偏下、横版脸在左 / 右三分之一）、大字放在脸的另一边（左右两边试一下，选和脸 / 小窗重叠最少的）、箭头从字那边指脸并保证尾巴不出画面；`avoid`（裁窗躲开的区域，先平移再放大）和 `keep_clear`（保留但字不能盖的区域）处理视频通话小窗；`theme` 换颜色；`tags` 可选的来源小标签。原来的 shot / split 不变——用 image-blaster 的候选 A 复现，三个比例**像素级一致**。新增 `build()` 供别的脚本调用。
- `scripts/make_candidates.py`（新）：读 `制作/04_封面/candidates.json`（`defaults` + 3 个 `candidates`，样式可混用），一条命令出 3 候选 × 3:4 / 16:9 / 4:3 = 9 张 + `候选总览.png`；`--select X` 复制成 `封面_选定_*`。总览排版沿用 image-blaster 会话的 `make_candidates.py`。
- `scripts/check_titles.py`（新）：读 `投稿信息.json` 的 `titles`（3 候选 × bilibili / douyin / xiaohongshu / weixin_channels）和各平台定稿字段，按 B 站 ≤ 80（标签 ≤ 10）/ 抖音 ≤ 30（话题 ≤ 5）/ 小红书 ≤ 20 / 视频号短标题 6–16 量字数，也查标题不含封面大字、三个候选不重复；有超限退出码 1。
- 模板：`assets/cover-template/candidates.json`、`assets/publish-template/投稿信息.json`；`new_short.py` 建条目时拷进本条并打印交付包的下一步；`assets/cover-template/cover.json` 里素材相对路径的层级改对（`../../../../素材/…`）。
- 文档：`SKILL.md`（开头标准流程里“封面 3×3 / 标题 3×4”、步骤 6 脚本入口、文件清单）、`references/publish.md`（新增“交付包的两张表：封面 3×3、标题 3×4”，含四个平台标题要求表和 Tavus 的 3×4 例子；封面一节改成指向新脚本；并入另一个会话发现的 5 条新坑，改正我之前写错的“抖音 8–10 个话题”和“带小窗必被判截屏”）、`D:\大疆\短视频\流程复盘.md`（开头、第 1 部分差距分析、下一条清单）、`D:\大疆\AGENTS.md` 的标准流程条、记忆 `short-video-four-stage-flow` / `short-video-cover-fullframe` / `short-video-publish-prefs` 和索引。

## 后续：视频号封面 = 成片第 0 帧（用户 2026-10-04 晚）

我问“要不要在成片第 0 帧放封面帧”，用户答：“视频号封面放到成片第 0 帧，做成选定的封面”。做了 `scripts/cover_frame0.py`：

- 第 0 帧 = 选定的 3:4 封面放在 1080×2340 画面正中（y 450–1890），上下两条用封面自己铺满再重度模糊填满；视频长度、帧数、每帧 pts、原声都不变，只是把第 0 帧（33 ms）换掉。
- 画质：只重编码第一个 GOP（到第二个关键帧，Tavus 是前 250 帧 ≈ 8.3 s，参数读原片 x264 SEI：crf 16 / keyint 250 / yuvj420p），第 0 帧用 x264 `zones` 单独 crf 6；其余 1115 帧**直接拷贝**，原声直接拷贝；concat 拼接后原片留 `<slug>_成片_无封面帧.mp4`，再跑一次从备份重做（幂等）。
- 校验（不过就不替换）：帧数和每一帧 pts 与原片一致、第 0 帧 vs 封面 ≥ 40 dB（只做 4:2:0 的参考，Tavus 实测 48 dB；封面本身的彩色抖动底纹做 4:2:0 就掉到 29 dB，这是任何视频帧都有的限制）、拷贝段 3 个样本帧逐像素一致、重编码段第 1 帧 vs 原片 47 dB、原声 md5 一致、解码无报错；拼接校验不过自动改整条重编码（crf 14）。
- 用 Tavus 成片的副本测过（19 秒；`--check`、`--full`、原地替换 + 备份、重复运行都试过）；**没有改 Tavus 已发布的那份成片**，视频号那条上线时用的是默认首帧，要换封面得删了重传（没问用户）。
- 流程里的位置：用户说同意、`make_candidates.py --select X` 之后、开 Chrome 之前。视频号“编辑封面”选第 0 帧、3:4 裁剪框对到 y 450–1890（居中）；**第一次实际发布时要在真页面上核对裁剪框默认位置、第 0 帧能不能选中**。
- 文档：`SKILL.md` 步骤 7 和文件清单、`references/publish.md` 规矩 2 和视频号一节、`投稿信息.json` 模板、`流程复盘.md`、AGENTS.md 标准流程条、记忆 `weixin-channels-wujie-shadowroot` / `short-video-four-stage-flow`。
