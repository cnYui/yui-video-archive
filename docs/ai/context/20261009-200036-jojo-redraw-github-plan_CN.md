# 承太郎重画与项目分批同步

用户要求按附图重画承太郎，解决全身精灵头部过大的问题，并把当前项目分批提交到 GitHub。

## 公开范围

用户已明确确认：纳入 JoJo 游戏代码和运行资源，原始素材库继续排除。目标仓库为公开仓库 `cnYui/yui-video-archive`，提交到 `codex/` 分支，分别创建以 `main` 为目标的 PR，不合并。

`游戏素材/JoJo/游戏/` 的正式代码、文档和运行资源可以公开；原始源码、角色图集、剧情分镜、烘焙脚本、原音频库、会话备份及其他游戏仍排除。私人素材、求职、星轨、评论私信运行记录、认证信息及临时构建目录不提交。

## 美术方案

- 采用现有像素绘图工具，在游戏层新增统一的成年承太郎骨架；缩小帽脸、加宽肩部、提高腰线、拉长裤腿，参考黑帽黑大衣、酒红内衫、帽徽、金链和彩色腰带。
- 统一站立、行走、奔跑、指人、压帽、坐下、受伤、惊讶、防御、闪避、倒地、水面漂浮和踢腿动作；儿童形态保持独立。
- 不修改只读原始库，不用运行时缩放掩盖比例问题。保留动作名、帧数、播放速度、播放方式和脚底锚点。
- 在原名冲突审计之后增加明确、局部的成年形象替换，再用同一 registry 烘焙和验证；保持新增精灵不覆盖原名的检查。
- 重新生成游戏实际使用的图集和内嵌数据，输出新旧对比和实际运行截图。

## 验证与同步

1. 保存受保护原始库哈希及相关运行资源基线。
2. 重画并检查动作预览，运行定向美术契约、像素回读和引擎比对；用浏览器验证 `file://` 启动与实际显示。
3. 新增游戏 README，如实列出本地原库重建依赖及既有未完成项，不把旧任务未验证的章节声称为通过。
4. 审查全仓待同步文件、大小、敏感数据和历史删除；按内容分组，使用独立索引生成提交，保留当前工作树。
5. 各批次显式暂存、验证、推送并创建 PR。既有未推提交纳入对应批次；既有 PR #1 先对照差异，避免重复。

当前 `main` 比远端领先 3 个本地提交，工作树有大量此前积累的制作工程与记录。本轮新增实现与历史同步在 PR 描述中分别说明。
