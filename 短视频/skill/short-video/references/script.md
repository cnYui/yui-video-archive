# 短视频台本

**先读 `D:\大疆\docs\台本风格_AI大圆镜.md`**（用户 2026-10-04：“语言风格就和上面的那个up主的风格相似即可”）。这里只写短视频多出来的规矩。

## 长度和字数

| 时长 | 拍子 | 汉字数（曼波 S2 Pro 约 0.22 s / 汉字，已含英文词和标点停顿） |
|---|---|---|
| 20–30 s（长视频二次剪辑的默认） | 钩子 → 背书 → 拆机制 → 收尾金句（四拍） | 90–125 个汉字，6–10 句（第 1 条：9 句 121 汉字 + 7 个英文词 → 有声 27.2 s、成片 28.3 s） |
| 45–60 s | 六拍（加“加码 / 对照”和“泼冷水”） | 200–265 个汉字 |
| 60–90 s | 六拍，拆机制里可以有一个自问自答 | 265–400 个汉字 |

- 用户说了时长就照做（“20 秒到 30 秒”）；没说就按素材：一个点 → 30 s，一条新闻 → 60 s。
- 估时：`build_timeline.py --est` 按每个汉字 0.225 s（只数汉字，英文词的时间已经摊进去了）；配音出来后以 `tts_edit.json` 为准，超了就删次要句重新生成，**别靠加速凑时长**（第 1 条先用 1.15× 凑，读到这条后作废、改成删句；要加速最多 1.1×，而且要用户同意）。

## 英文讲解的素材 = 曼波中文同传（原声压低留着）

用户 2026-10-04（对 image-blaster 那条）：“如果是英文讲解的话，你要用曼波ai配音做双语同传，还有双语字幕”。那条第一版我们自己写解说、把原声丢了，被纠正。做法（`独立视频\短视频\2026-10_image-blaster推荐\`，记录 `docs/ai/context/20261004-111500-image-blaster-short-video_CN.md`）：
1. 原声逐词转写（faster-whisper `word_timestamps=True`，`initial_prompt` 里写专名：“克劳德”“Claude Code”“中旬”……，不然 Claude 会被听成“骷髅 / Cloud”）。
2. 按句切，切点放在静音处；每句做一条同传：**中文字幕 = 同传那句话，英文字幕 = 讲解内容（第三人称，可以略压缩，见下一节）**。
3. 同传比英文晚约 **0.4 s** 开口；`common.py` 里这个素材 `HAS_AUDIO` 写 True，`mix_audio.py` 会把原声压到 −21 LUFS、曼波说话时再压 −9 dB。
4. 同传句子之间可以插自己的短句（背书、页面录屏、定格），这些段的 range 写 `"mute": true`。
5. 台本风格照样是 AI大圆镜 的：同传也要短、口语、先说结论；但意思以讲解者原话为准，不加原话没有的东西。

**压缩成 20–30 秒的二次剪辑不做同传**（用户 2026-10-04 答“不要”）：第 1 条（ClaudeDesign）那样“把观点更快更密地讲出来”的压缩改写，原声不留、曼波重新讲中文。同传只用在成片和原片差不多长、按讲解者原话一句句跟着讲的时候（image-blaster 那条）。

## 第三人称（不要用“我”开头）

用户 2026-10-04：“短视频skill中……要使用第三人称来描述，而不是用 我 开头，比如当前视频就是作者第一人称的描述，需要你修改为第三人称，比如直接叫他推特的名字”。
- 同传、解说都用第三人称：讲解者说的 “Today I'm releasing…” 不念“今天我发布…”，直接叫他的 X 账号名：“@neilsonks 五月发布了一套 Claude 技能……”（字幕写 @账号；账号名语音念不顺就用中文音译，`say` 写“尼尔森五月发布了……”）；**英文字幕也改第三人称**（“@neilsonks released …”）。
- 讲解者说“你”（“once you have that list”）的地方改成无主语（“列好清单、选定要生成的物件之后”）；自己写的句子也别以“我”开头。
- **先核实讲解者是谁**：image-blaster 的视频是作者 @neilsonks 的原帖（2026-05-14，作者主页 neilsonks.com 列着这条 X 链接），@liambraus 只是转发——称呼用原帖作者的，转发者写进简介。他说的 “today / 今天” 指原帖那天，现在讲要换成日期（“五月”）。
- 第 2 条（ClaudeDesign + Slides）补的：同传和英文字幕都直接叫名字（Nate），**不用“他 / 她 / his / her”**；讲解者对观众说的“你”改成无主语；**官方金句照原样**（Claude makes it. You steer it.）。曼波把“掌舵”三次都念得像“讲读 / 讲诺”（zh 发成 j），这类词换成好念的说法（“定方向”）。
- 只改人称和时间，意思不变。改过的句子单独重配：Fish 新建只有这几句的空白项目，导出后放进 `tts/seg_pick_v3/<句号>.wav`，`build_voice.py` 会盖过整稿里的原句，不用整稿重来。

## 两种稿子

- **长视频二次剪辑（dual）**：用户原话“把视频里的观点更快更密集的讲出来”。原视频是英文的，配音是中文讲解（不是逐句翻译）：挑 2–3 个最硬的点，按四拍重排；原话只引最关键的一句（“她只说了一句：鸟再大一点”）。英文字幕写我们这句中文的英文，不抄原视频字幕。
- **新闻短条（single）**：多个来源拼一条新闻，六拍走完；每个数字都要有出处（`references/facts.md`）。

## 录制稿.json

- `hook`：两行标题，整条视频一直挂在顶上（照 AI大圆镜）。第一行 ≤ 12 字，最反常识的事实；第二行 ≤ 15 字，数字或反转。和第一句台词可以接近，但别一字不差。
- `kicker`：标题上面的小字（`悠一 · <b>Claude</b> 新功能` 这种），≤ 18 字。
- `lines`：每句 `zh`（字幕，≤ 约 34 字，引擎按 17 字一条自动拆）、`say`（念的字：数字写汉字、`@` 写艾特，英文专名读不准就写中文音译，字幕仍写原文）、`en`（英文字幕，口语、≤ 约 120 字符，拆成 ≤ 60 一条）。**每句都要有 en**（项目中英双语标准）。可选 `who`：说话人标签（同传那句写讲解者的名字，例 `"who": "Nate"`），字幕前面出一个橙色小标签，拆条时自动把标签宽度算进去；我们自己的解说句不写。
- 第一句就是钩子，不寒暄、不自我介绍；最后一句是金句，不喊关注、不预告（短视频不加悠一片头片尾，结尾停在金句上，留 0.8 s）。
