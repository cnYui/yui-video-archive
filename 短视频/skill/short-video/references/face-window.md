## 一句话

**所有悠一出镜的短视频：脸 = 镜像（hflip）的圆角小窗，边框和成片同一套“边框 6”（7 px 黑描边 + 橙色硬阴影 + 右上角黄贴纸“悠一 出镜”）；单框版居中放在字幕下面（360×360），双框版缩到 240 放下框的左下角；场景换版式时顺势移动 + 缩放。** 不再做满屏出镜、不再做左上角出镜框（记忆 `voiceover-no-cam-box`：只有画外音、没有出镜的段不放脸）。

## 按场景换位置（“顺势移动到角落”）

- `plan.json` 的场景写 `"face": "center" | "bl" | "tl" | "tr" | "hide"`；不写 = 按版式默认（单框居中、双框 bl）。
- `compose_face.py` 在场景交界处用缓入缓出（smoothstep）移动，整段 0.35 s，大小也跟着缩放（360 ↔ 240），所以版式从单框切到双框（或反过来）时脸会“顺势”滑进 / 滑出角落；有字幕停顿就放进停顿里（离交界最近的那个），没有就取交界前后各 0.175 s。
- **停着的位置绝不能盖字幕**（用户 2026-10-06 看到测试帧里窗口压住字幕后强调：“你找一个不挡住字幕的地方”）：脚本每次合成前按 0.05 s 采样窗口（含阴影 / 描边 / 贴纸）和字幕条（single y 1490–1620、dual y 1756–1884）比对，盖了就报 `⚠ 字幕检查`。真实的双框画面实测：窗口 (40, 1460, 240) 在下框左下角，字幕（1764 起）不被盖；单框居中 (360, 1664, 360) 在字幕下面，不被盖。
- **移动途中扫过字幕条是躲不掉的**：单框版里“框内角落（y 1123 / 746）”和“字幕下面居中（y 1664）”之间隔着字幕条，滑动一定会扫过它约 0.15 s（字幕几乎一直挂在屏幕上：显示区间比说话多拖 0.1–0.45 s，两条之间的缝只有 ~0.1 s，停顿里放不下 0.35 s 的移动）。要么接受这 0.15 s，要么 `face.json` 写 `"move": "cut"`（0.04 s 直接跳过去），要么这条里让位置保持不动（单框一直居中、双框一直 bl，就没有移动）。**别拿“相邻位置”当解法**——居中和框内角落本来就不相邻。
- 版式切换点（单框 ↔ 双框）本来就是画面整块变化的一刻，窗口在这一刻滑一下（单框居中 ↔ 双框 bl）观感最自然，也是用户说的“顺势移动到角落”的主要场景。
- 临时试位置：`--moves "A2:bl,A5:tl"` 覆盖，不改 plan.json。

## 流程（用户自己录口播 = 原声版）

1. 用户给 DJI 原片（`H:\DCIM\DJI_001\…MP4`，4K 60p HEVC，直接用，不转码）。先抽 3 个时刻的帧看脸在哪、有没有别的东西入镜。
2. **ASR**：`python scripts/own_voice.py asr <原片> --out <素材\出镜>`（faster-whisper large-v3-turbo + medium 两遍，输出分句和时间）。专名 / 同音要两遍对照（“Clouder / Claude”“钓鱼之法 / 钓鱼执法”“拆GPT = ChatGPT”）；末尾的“好好好”是 ASR 幻觉。
3. **字幕 = 他实际说的话，一字不改**（用户：“不要修改任何内容”）：只改 ASR 听错的专名 / 同音字；英文字幕忠实直译（他说“我”就写 I）；观点句、没出处的比较、绝对化的说法，**在交付说明里写出来**让他知道，不改稿、不替他润色。要用耳朵确认的词（ASR 两遍不一致的）列给用户。
4. 写 `lines.json`（id / s / e（原片时间）/ zh / en）→ `python scripts/own_voice.py build <本条> lines.json --video <原片> --start 0.20`：写 `tts_narration.wav`（原片音轨）、`tts_edit.json`、录制稿 lines、`plan.json` 每句的 `a`（= 他实际的停顿）、`common.py` 的 `NATURAL_TIMING = True`、`face.json`。
5. **自然停顿**（`NATURAL_TIMING`）：引擎默认会按句切块、句间加 0.18 s、场景末加 0.4 s——原声不能这么重排，否则音频 / 画面 / 小窗对不上。开关打开后：`GAP_LINE = PAD_END = 0`、配音只放一整块、场景切在上一句结束处、下一句的 `a` = 他实际的停顿。画面场景照常写（页面截图 / 官方页面录屏 / 高亮），`P()` / `S()` 的时间就是原片时间 − start。
6. `build_timeline → check_subs → prep_frames → mix_audio（BGM 床 −10 dB）→ render_all`，**渲完把 `整片_v1.mp4` 改名 / 拷成 `整片_v1_cards无小窗.mp4`**，再 `python scripts/compose_face.py <本条>`（读 `制作/00_整片/face.json`，模板 `assets/face-template/face.json`；输出覆盖 `整片_v1.mp4`，音轨直接拷贝 base 里已混好的），然后 `qa_mix → finish`。
7. 验证：抽几帧看窗口位置；镜像用相关系数核对（Claude 中文界面：镜像 0.92 / 不镜像 0.29）；`qa_mix` 逐句识别分（低分多半是同音 / 繁体假低分，列给用户听）。
8. 封面：用**安静的帧**（停顿处抽帧，闭嘴 / 正对镜头），**同样镜像**，走框版封面（`make_cover_framed.py`，`video` 写镜像后的 png 路径）；候选里放一个出镜的（“不敢点的 / 中文选项”这种）。
9. 声明（本人原声 + 脸，没有 AI 生成的声音 / 画面）：**不选“含AI生成内容”**。B 站选“个人观点，仅供参考”（选项：内容无需标注 / 含AI生成内容 / 含虚构演绎内容 / 内容含营销信息 / 个人观点，仅供参考 / 内容为转载，**发布后不能改**）、抖音“内容为个人观点或见解”、小红书“内容来源声明 → 自主拍摄”（会弹拍摄地点 / 日期，不选位置就点取消，类型声明仍记为自主拍摄）；小红书“原创声明”照旧要开，《原创声明须知》的同意用户已长期授权我来勾（2026-10-06 晚）。

## compose_face.py 的实现要点（改它之前先读）

- 三层 440×440 透明小画布（`shadow.png` 橙色硬阴影、脸层、`ring.png` 黑描边 + 黄贴纸），窗口本体在画布 (30, 40)；脸层 = 原片 `fps=30 → crop 正方形 → scale 360 → hflip → alphamerge(圆角蒙版) → pad`。
- 三层都用 `scale=w='…':h='…':eval=frame`（表达式里用 `t`）按帧缩放，再用 `overlay=x='…':y='…':eval=frame` 按帧移动；位置 / 大小 = 起始值 + Σ（变化量 × smoothstep），每个场景交界一项，表达式只有几项，不用嵌套 if。ffmpeg 8.0 实测可行。
- 脸的裁切写在 `face.json` 的 `crop`：`cx / cy` = 中心（占原片宽 / 高），`side` = 边长占原片高度；Claude 中文界面用 `{cx 0.515, cy 0.449, side 0.787}`（4K 里 1700×1700，头顶留一点空、到胸口）。
- 原片 `-ss start -t duration` 和配音同起点，口型和声音天然对齐（和音频用同一个 start）。
- 64 s 的 4K 60p 原片合成约 2–3 分钟。
