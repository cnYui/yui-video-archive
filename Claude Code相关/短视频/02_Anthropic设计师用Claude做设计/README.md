## 做法

1. **选段**：Design 全片按 Nate 的话切成 14 段，**顺序按“怎么用”重排**（先说他是谁、为什么要做新手引导，再按 连仓库 → 提需求 → 咖啡 → 评论 / 手改 → 原型 → 开工 → 小结）；Slides 8 段（过渡 + 5 步 + 小结）。每段的入 / 出点放在句子前后的停顿里（`check_cuts.py` 量原声、`snap_cuts.py` 对着逐词时间找安静点），对齐到 1/24 s；**画面和原声同步**，不变速。
2. **同传（第三人称）**：每句英文一块曼波同传，**比英文晚 0.4 s 开口**（技能 short-video 的规矩）；**第三人称**（技能 2026-10-04 下午新加的规矩：不用“我”开头，直接叫讲解者的名字；讲解者说“你”的地方改无主语；不用他 / 她，英文字幕也不用 his / her）：“Nate 打开 Claude Code，连上仓库……”，英文字幕 “Nate opens Claude Code, connects the repo, …”。同传比原片段长时画面定格最后一帧等它说完（最长 1.1 s），**配音不加速**。我们自己加的句子只有两句：Slides 开头的过渡“同一位设计师，做演示文稿，以前总对着空白窗口发愁。”（S00）和结尾金句“Claude 做出来，你来掌舵。”（S07，官方原句 “Claude makes it. You steer it.” 的译文，里面的“你”是官方原话的泛指，照原样）。
3. **画面**：上框 = 同步的人脸 / 全屏，下框 = 对应的操作特写（Design 从 4K 原片里裁切放大，字看得清）；人脸不在的时候上框放全屏概览、下框放特写，“同一时刻不放同一个镜头”的地方用定格 + 缓推（Design 的画布五块新手引导方案：开头推到 “Every day, one dumb thing.” 那张、讲“现有的引导”时推到 Current 那张、讲“bird mode”时推到小鸟那张）。每个镜头的裁切框都在 `台本/plan.py` 里（`O` = 原片同步、`B` = 别处素材、`F` = 定格 + 推镜）。
4. **混音**：原声（说话 + 界面音效 + Slides 的 BGM，混在同一条轨里分不开，整条一起用）按段放在时间轴上，同一个来源拼起来量一次响度拉到 −21 LUFS；同传拉到 −16 LUFS；同传说话时原声压 −8 dB（前 0.12 s、后 0.4 s 保持），没人说话时原声照常（BGM、界面音效都听得见）；**再垫系列 BGM**（用户：“按照skill中的要求，还需要给视频加上bgm”）：`AI科普/素材/音频/bgm.wav`（lo-fi 轻爵士，F 大调 80 BPM）从头铺到尾，−16 dB（约 −36 LUFS，比配音低约 20 dB），同传空档（≥ 0.3 s）回升 +5 dB（0.5 s 以上的平滑斜坡，不泵），Slides 一章原声里自带 BGM（分不开）所以系列 BGM 在那几段再降 6 dB、让自带音乐领头，头 1 s 淡入、尾 2.5 s 淡出（技能引擎的规则是“有原声的素材段 BGM ×0.05”，这条每段都有原声，照搬等于听不见，所以改成整条垫底 + 说话时压低）；整条再拉到 −16 LUFS，软限幅。
5. **字幕**：项目双语标准（中文 52 px 墨黑 + 英文 30 px 灰，各一行，居中，描边用米白），竖屏每条中文 ≤ 约 17 字宽、英文 ≤ 约 60 字符；位置 y 1764 起（dual 版式，两框下 80 px；用户：“字幕放在屏幕底部偏上的位置”），下面 1930 以下留给平台的账号 / 文案。**字号**（用户：“你看一下当前 /short-video 里面规定的字幕的字号，你同步修改一下当前视频的字幕”）：技能规定的 52 / 30 px 是 CSS 的 em，而 ASS 的 `Fontsize` 是行高（Noto Sans SC 的 winAscent + winDescent = 1.448 em）——libass 里写 52 只画出约 36 px 的字（同一串字 CSS 52 px 宽 1077 px、ASS 52 画出来 739 px，比值 0.686）。第一版成片写的就是 52 / 30，实际只有标准的 68.6 %；现在 ASS 写 76 / 44（`make_subs.py` 里 `LIBASS_EM = 0.686`），`check_subs_render.py` 量成片里真烧进去的字：中文墨迹高中位数 51 px，最宽一行 878 px、离左右边缘最近 85 px（≥ 70）。上一条（第 1 条）和之前几条走 ASS 的成片有同样的问题，没动。
6. **版式 = 技能 short-video 的 dual（版式 B + 边框 6，用户 2026-10-04 选定）**：1080×2340；标题 280–570 + 随步骤变化的小标签；上框 680–1170、下框 1194–1684（860×490，x 110–970，框里画面 846×476）；边框 6 = 7 px 黑描边 + 橙色硬阴影（右下 14 px）+ 右上角黄色贴纸“Claude 官方 YouTube”；背景 = 米白 + 技能背景库随机挑的印花（这条挑到 `pattern_orange.png`，AI 工具图标橙色低透明度，约 12%）。

## 踩到的坑

- **技能当天被连着改**：开工读的是 11:00 的版本，第一轮成片（旧版式、第一人称、点阵底）渲完才看到下午加的三条规矩（第三人称、版式 B + 边框 6、随机背景印花）——整轮配音重做（Fish 又一整稿）、重渲一遍。**开工前和第一次渲整片之前都要重读技能 + `docs/ai/context` 最新记录**（记忆 `short-video-skill-rules-change-midday`）。
- **原片的灰白播放键帧**：Design 里 Nate 的人脸视频在切换时会出现 0.3–0.6 s 的灰白“播放键”帧（17.7 s 前、24.65–25.3 s），切点要避开（D01 入点 17.958、出点 24.583；D04 先定格 25.40 再接着播）；切点还要看原声（`check_cuts.py`）、画面（4 fps 联系表）、逐词时间三样。
- **定格 + 推镜**：`freeze` 子镜头用 OpenCV 逐帧裁切缩放（smoothstep 缓动）再管道喂给 x264，4K 原片放大后字仍清楚；视频子镜头不支持变宽缩放（只有平移）。
- **x264 要偶数尺寸**（框里画面 846×476）；**faster-whisper 喂 numpy 数组按 16 kHz 解释**（`qa_mix.py` 已处理）；PowerShell 里 `Start-Sleep` 后面接别的命令会被拦，等后台任务用 `run_in_background` / Monitor。
- **Fish**：新建空白项目 + 曼波 + S2 Pro，一次键入 34 行、`div.content` 核对 34 块、点一次“生成”、导出“按段落拆分”，没碰“重新生成”；**故事工作室列表页的布局会变**（第二次打开侧栏多了“创意 / 开发者 / Agents”，“新建项目”按钮从卡片右上移到页面右上，第一次点常被吞）→ 用 `find` 取 ref、点完截图确认。
- **机器识别的假低分**：这个声线的 sh/x（“连上”→“联想”、“是画”→“续花”）和 Nate / Claude 的同音误听（“内地 / 内体 / 骷髅 / 库洛”）会把分数拉到 0.5–0.7；`qa_tts2.py` 带提示词、用两个模型再听一遍，**两个都低的才算问题**（本轮只有 D03a“任务是画一幅画”两个模型都对不上），仍要用户耳朵听。
