核对时间：2026-10-10。读的都是官方原页（`curl` 下载 HTML、直接解析页面里的基准表数据，不信搜索摘要）：

## 一、价格（每百万 token，美元）

| 模型 | 输入 | 输出 | 缓存读取 | 出处 |
|---|---|---|---|---|
| Fable 5.1 | 10 | 50 | 0.25 | 价格页 / 总览页 |
| Opus 5.5 | 4 | 20 | 0.20 | 同上 |
| Sonnet 5.5 | 2 | 10 | **0.10**（10-07 起；发布页正文还写着 0.20，没改） | 价格页；Haiku 发布页「Further updates」 |
| Haiku 5.5，提示 ≤ 10 万 token | 0.10 | 0.50 | 0.01 | 价格页 / Haiku 发布页 |
| Haiku 5.5，提示 > 10 万 token | 0.50 | 2.50 | 0.05 | 同上 |
| Haiku 4.5 | 1 | 5 | 0.10 | 同上 |
| Sonnet 5 | 2 | 10 | 0.20 | 价格页脚注 3：$2/$10 原是“到 8 月 31 日的发布期价格”，现在转正；**原定 9 月 1 日涨到 $3/$15，取消** |

- 批量接口 50% 折扣（价格页）。Haiku 5.5 的“提示长度”算全部输入 token（含缓存读写），每个请求单独计价，超过 10 万的请求整条按高档价（价格页「Long context pricing」）。
- 四款模型上下文都是 100 万 token、输出上限 12.8 万（总览页）；但 Sonnet / Opus / Fable 100 万按标准价，**Haiku 5.5 超 10 万就按高档价**。
- 台本里的“账”是我按官方标价算的：输入 100 万 + 输出 20 万 token（Haiku 的每次提示都在 10 万以内）：Haiku 5.5 = 0.10 + 0.10 = **0.20**；Sonnet 5.5 = 2 + 2 = **4**；Opus 5.5 = 4 + 4 = **8**；Fable 5.1 = 10 + 10 = **20**；没算缓存和批量折扣。
- Haiku 5.5 / Sonnet 5.5 = 0.10/2 = 0.50/10 = 1/20，“整整 20 倍”成立。

## 二、官方给的“便宜 / 快”说法（Anthropic 自己测的）

- Sonnet 5.5：单价与 Sonnet 5 相同，“同样的活最多便宜 30%”（用的 token 少）；输出“30%+ 更快”，是“最快的 Sonnet”（发布页）。缓存读取减半后，“多数智能体任务再便宜约 20%”（Haiku 页）。
- Haiku 5.5：“平均约便宜 75%”；脚注：提示 ≤ 10 万便宜 90%、> 10 万便宜 50%，Haiku 4.5 九成请求在 10 万以内；这个数“也算进了 Haiku 5.5 新分词器多用的 token”。**官方没写完整算式**。
- 订阅额度（Haiku 页「Further updates」）：“本周”起给 Max 和 Team 订阅者每月 API 额度——Max 5x $100、Max 20x $200、Team 最多 $500（全团队共用），可用于任何模型。“本周”指发布那一周，到账时间官方没写。

## 三、能力（官方基准表；台本里每个数都在这里）

**Sonnet 5.5 页（Sonnet 5.5 / Sonnet 5 / Opus 5.5 / GPT-6 Sol）**
- Terminal-Bench 4.0：70.6% / 10.3% / 66.4%（脚注 1：Opus 取 Xhigh，“它的最高分”）/ —
- FrontierCode 1.1：46.2%（Max）、52.1%（Xhigh）/ 42.4% / 54.4% / 49.3%（脚注 2：Sonnet 5.5 的 Max 档比 Xhigh 档低，因 Max 档更常调用拆给很多子智能体的代码审查，在 Cognition 查的两例里超时或改了范围外的东西）
- CursorBench 4.0：55.5% / 34.1% / 57.8% / —
- GDPval-AA v2.1：1844 / 1449 / 1846 / 1487；AA-Briefcase v1.1：1811 / 1359 / 1822 / 1483（脚注 3：第三方 Artificial Analysis 在预发布部署上测，有结构化输出 bug，官方说影响预计很小、已修）
- Humanity’s Last Exam（带工具）：64.5% / 54.9% / 67.7% / —；OSWorld 2.1（partial）：80.1% / 57.0% / 81.8% / —；Chartography（无工具）：61.6% / 15.6% / 64.4% / 53.6%
- 八行里 Opus 5.5 领先七行（只有 Terminal-Bench 是 Sonnet 高）；差距：FrontierCode 2.3、CursorBench 2.3、GDPval 2、AA-Briefcase 11（Elo）、HLE 3.2、OSWorld 1.7、Chartography 2.8。
- 官方原话：“Opus 5.5 remains clearly stronger at complex, open-ended work requiring sustained judgment.”；“第一个只看截图就通关 Pokémon Red 的 Sonnet”。
- 官方效率说法：中档思考力度下，Terminal-Bench 上超过 Sonnet 5 最好成绩，每任务成本不到十分之一（发布页图表说明）。

**Haiku 5.5 页（Haiku 5.5 / Haiku 4.5 / GPT-6 Luna / Sonnet 5.5 供参考）**
- GDPval-AA：1620 / 735 / 1437 / 1840；AA-Briefcase：1578 / 614 / 1336 / 1824
- OSWorld 2.1（离线子集）：72.4% / 15.7% / 48.9% / 83.9%
- HLE 无工具：45.9% / 10.2% / — / 56.9%；带工具：57.4% / 18.7% / — / 64.5%
- Terminal-Bench 4.0：39.2% / 0.0% / 16.4% / 70.6%；FrontierCode 1.1：46.4% / — / 42.4% / 52.1%（Xhigh）；Chartography：46.4% / 6.4% / 29.1% / 61.6%
- GPT-6 Luna 有成绩的行共 6 行（GDPval、AA-Briefcase、OSWorld、Terminal-Bench、FrontierCode、Chartography），Haiku 5.5 六行全部更高。
- 首个带可调“思考力度”的 Haiku；三张“成绩对成本”图（OSWorld、GDPval、HLE），三张里最高分的点都是 Sonnet 5.5。
- 官方定位：大批量、成本敏感的活——摘要、压缩（compaction）、查数据库、分类；给 Opus / Sonnet 当编码子智能体；够快、能做实时客服和浏览器操作。官方原话：“Sonnet 5.5 and Opus 5.5 remain better choices for complex agentic coding tasks”。
- 推文（@ClaudeDevs）：Haiku 5.5 已在 Claude Platform 和 Claude Code 可用。
- 护蛋演示（@ClaudeDevs 视频，官方 Claude Managed Agents 测试）：Opus 5.5 单干 3:37 / 25 个设计 / $0.47，Opus 5.5 + 10 个 Haiku 5.5 子智能体 0:58 / 86 个设计 / $0.14，两边最后都到 32 m；片中说明“回放 3.5×，标 20× 处 20×”。**3:37 ÷ 0:58 = 3.74 倍；0.47 → 0.14 便宜 70%（我按片里计时器算的）**；这是官方挑的一道题。
