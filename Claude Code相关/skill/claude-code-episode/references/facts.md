# 事实核对：先查再写台本（15 分钟时间盒）

第 1 期靠“台本写完逐条对官方教程页”（37 条 36 条逐字对上）；第 3 期改成**先查再写**，查出来的东西直接改了台本的走向：推文只说 “Enable it with …”，文档和更新日志才写着“默认关闭、第一方会话 + 遥测开着、组织可用”，源码没公开，推文 / 博文 / 文档三处口径还不一样。**这一步在写台本之前做，台本照“能写 / 不能写”清单写。**

## 做法

1. 素材下载完（推文文字、链接已打印出来）**立刻**起后台调研子代理（`Agent`，general-purpose，默认后台）；它读官方原页、不信搜索摘要；你同时去看素材、搭引擎、录页面。
2. **时间盒 15 分钟**：第 3 期的子代理跑了 32 分钟（把 1290 个仓库文件逐个搜了一遍，最后结论是“源码里没有”）。提示词里写明“最要紧的先写：①官方文档 / 更新日志里有没有、哪个版本 ②默认开还是关、怎么开关 ③前提条件 ④官方没说的”，15 分钟时 `SendMessage` 让它先把已核实的写进文件。你自己也可以同时 `curl` 官方文档 / 更新日志页搜关键词，几分钟就能核到最要紧的几条（第 3 期这样提前拿到了“默认关闭”和“2.1.287 加入”）。
3. 子代理产出 `台本/事实核对.md`：①名称对照（官方名 ↔ 推文里的写法 ↔ /plugin 里显示的名字）②已核实（结论｜来源网址｜读到时间）③没法核实 / 官方没说 / 与推文不符 ④“能写”和“不能写”清单 ⑤小字注释用的一句话说明 ⑥可做页面录屏的小节（URL｜起点文字｜要高亮的英文原句）⑦上期已讲过、这期不要重复的点。
4. 写台本时每句有出处；写完用清单逐条对。简介里把“官方说的”“官方没写的”“用户反馈（不是官方结论）”分开写。
5. **读不到的页面要写明**（403、渲染不出来），只能靠 RSS 摘要 / 搜索摘要的标“搜索摘要”，投稿前让用户看一眼。

## 子代理提示词模板（填空）

> 你是事实核对员。今天是 <日期>。工作环境：Windows，项目目录 D:\大疆。请用中文汇报。
> **背景**：我在做一条中文 B 站短视频（约 2–3 分钟，全程画外音 + 官方演示视频 + 官方页面录屏），介绍 Claude Code 新出的 <功能 / 插件名>。旁白里每一句关于“它是什么、怎么开、怎么工作、哪个版本、在哪能用”的话都必须有官方出处；官方没写的不能说成“官方说”。
> **官方推文**：<账号、发帖时间 UTC、原文逐条贴>（带一个 <N> 秒演示视频）。**官方博文**：<链接>（我读过：<提没提这个功能>）。上一期台本在 <路径>，请先读，输出里列出“上期已讲过、这期不要重复”的点。
> **要核实**：A. 官方文档里有没有它（<页面，例如 https://code.claude.com/docs/en/plugins/mods/overview 的 “Mods built into Claude Code” 表>）：一句话说明、默认开还是关、怎么开 / 关、在哪能用（命令行 / 桌面版）；B. 更新日志（https://code.claude.com/docs/en/changelog 或 GitHub anthropics/claude-code 的 CHANGELOG.md / Releases）：哪个版本加的、原话大意、括号里的前提；当前最新版本；C. 官方仓库有没有它的源码（mods/ 目录等；读不到写“源码里没写”）；D. 推文里的术语（<如 sideagent>）在官方文档里的叫法和定义；E. 官方还有没有别的说明页（claude.dev 博客、docs、X 其他帖子）；F. 适合做页面录屏的小节（URL + 起点文字 + 要高亮的英文原句）；G. 安全 / 权限方面官方有没有专门说法。
> **怎么查**：官方页面用 `curl.exe -sL -A "<Chrome UA>" <url>` 抓原文再读，页面是前端渲染的话读 HTML 里的内联数据；抓不到（403）再换 WebFetch / WebSearch 并标“搜索摘要”。**不要使用 Chrome 浏览器插件和内置浏览器**（别的会话在用），不要碰 Fish Audio，只读不改项目里已有的文件。**时间盒 15 分钟**：最要紧的先写进文件（A、B、默认状态、前提、官方没说的），其余写“未查完”。
> **输出**：写成 <本期>\台本\事实核对.md，150 行内，结构见上；不要抄大段原文（版权），只写事实、转述和很短的关键词引用（≤ 15 个词并标明是引用）；最后给 10 行内要点摘要和矛盾 / 存疑点。

## 本合集常见陷阱

- **默认状态**：mods 功能默认开，不等于每个内置 mod 都默认开（You should know 默认关）。
- **前提**：版本号、第一方会话 / 遥测、组织是否开放、桌面版 / VS Code 是否支持——官方没写的范围别说。
- **名称**：官方名（You should know）、`/plugin` 里的名字（`cc-plugin-you-should-know`）、完整 id（`…@builtin`）、推文口径（plugin / mod / sideagent）要对照；`@builtin` 不是能下载东西的市场，是内置插件的来源名。
- **能写 / 不能写**：能写“官方文档的表里写着 …”“更新日志写着 …”；不能写“开源”“能拦截”“实验功能”“多花多少 token”“只看最终回答”“内置的所以绝对安全”（除非官方原文这么写）。
- **演示视频里的标注**：视频后期加的标签（Glossed over）官方没解释，旁白 / 译文只说“演示视频在这一行上标了 …”，别当成产品功能。
- **用户反馈（GitHub issue）**：只能写“有用户在官方仓库反馈 …，这是用户反馈，不是官方结论”，放简介，不放旁白，不带用户名。
